# RAD-085 — تقرير حزم بوابة Assess W1–W8، 2026-11-03

دفعة تحضير فقط: لا SQL حي ولا إجراء سحابي ولا Variables ولا أسرار. البوابة مغلقة، والدوران NOLOGIN، وكل إصدارات السر DISABLED في كل ما شُغّل. الحزم التفصيلية وخطوات المالك في [حزم W](ASSESS_GATE_W_PACKAGES.md)، وحالة كل بند في [دليل البوابة](ASSESS_GATE_OPEN_RUNBOOK.md).

## 1. الانحرافات والميزانية

- **الميزانية المعلنة قبل التحرير:** ≤18 ملفًا من سقف 22. **المستعمل:** 15 ملفًا، منها 12 في commit الحزم، وثلاثة في commit الحالة الأخير (هذا التقرير وHANDOFF وproject-status). الوحدة المشتركة الوحيدة هي `ci.yml`، وأُضيفت إليها ثلاث خطوات اختبار.
- **انحراف 1 — LOGIN منفصل عن النقل.** نص المهمة يضع `LOGIN` داخل أمر النقل. الحزمة تجعل النقل يضبط verifier وصلاحية ≤90 يومًا مع إبقاء الدور NOLOGIN، وتؤجل LOGIN إلى ملف الخطوة 4.3. السبب: يبقى الدوران مغلقًا حتى يُمكَّن السر بالترتيب الثابت. نتيجة الربط واحدة. **قرار المراجع مطلوب.**
- **انحراف 2 — اسم الدوران.** الدوران `assess_job_b` وليس اسمًا جديدًا. حزمة الإيقاف v2 (ثابتة البايتات) والإيقاف داخل التطبيق لا يغطيان إلا `assess_job_a` و`assess_job_b`، فاسم جديد يفلت من الإيقاف.
- لم تتغير marker أو manifest أو أي ترحيل أو حزمتا الهاتف. القيمة بعد الدفعة: `pilot-v1:3d8b505c…18b7`، كما هي (Verified).

## 2. ما أُنجز وما أُسقط

- **أُنجز:**
  - W1: SQL التجهيز والفحص والـLOGIN، ومقترح D-W1.
  - W2+W3: أداة النقل واختباراتها.
  - W5: مسبار TLS بلا اعتماد، واختباراته وإجراؤه.
  - W4: نص إجراء الصورة لاحقًا.
  - W6: مقترح القرار.
  - W7: الوصفة مع موانعها.
  - W8: النتيجة.
  - تحديث جدول W و§4 و§6 في دليل البوابة.
- **أُسقط بصدق:**
  - صورة إنتاج W4: غير ممكنة دون كود جديد وقرار.
  - smoke كتابي W7: غير قابل للتنفيذ في المنتج المنشور.
  - أي تعديل للربط أو للحراس.

## 3. لكل بند

| البند | الحالة | الخلاصة |
|---|---|---|
| W1 | Decision-needed | الدور `assess_grading_worker` بمنح الربط الخمس فقط، ودوران واحد بعضوية وحيدة (SET true، INHERIT false، ADMIN false)، ومعاملة واحدة بحراس رفض وبمهل. الربط يرفض أي دور له TEMP، وPUBLIC تملك TEMP في الإنتاج، فاقتُرح D-W1 |
| W2+W3 | Ready-for-owner بعد W1/W4/W5 | كلمة المرور في الذاكرة، وverifier SCRAM محلي عبر stdin الخاص بـ`owner_sql`، والنص الصريح إلى إصدار رقمي جديد يُعطَّل فورًا. لا Enable ولا latest ولا إعادة محاولة. تشمل مراجعة IAM |
| W4 | STOP | `worker-main.mjs` اصطناعي حصرًا: علم `RAD085_SYNTHETIC_WORKER`، وواجهة `rad085-postgres`، و`localOnly`، وتصريح مصالحة اصطناعي، و«No operational verifier exists» |
| W5 | Decision-needed | المضيف المباشر على FREE يعمل عبر IPv6 فقط. Cloud Run يحتاج Direct VPC egress على subnet مزدوج بـIPv6 خارجي، وهذا غير مثبت. المسبار يحسمه. الخيارات A/B/C بمخاطرها |
| W6 | Decision-needed | التشغيل الواحد يصحح محاولة واحدة على الأكثر، ويجب التصحيح خلال 24 ساعة من التسليم، وإلا لا يبقى إلا recover قبل اليوم السابع. المقترح: Scheduler غائب، وN تشغيلات يدوية متتالية |
| W7 | STOP | `assign_v1` لا يقبل إلا schema 1، و`start_v1` يرفض غيرها، والواجهة تستدعي v1 فقط، فلا بند كتابي. لا مسار تثبيت محتوى مراجع للإنتاج. وصفة auto-only جاهزة لاحقًا |
| W8 | مرفوض (مقترح) | الإرسال يضع `grading` (v2 السطر 214، وv1 السطر 246)، و`finish` وحده ينقل إلى `awaiting-manual`/`graded` (v2 السطر 312، وv1 السطر 322) |

## 4. التغييرات المشتركة والتوسع (S-STD-3)

- `ci.yml` (مسار db): تمرين W1–W3 في الأنماط الثلاثة، واختبار النقل، واختبار المسبار. لا skip ولا تغيير لخطوات قائمة.
- **سقوف معلنة:**
  - **تشغيل واحد = محاولة واحدة.** رافعه: قرار Scheduler عند نحو 10 محاولات أو أكثر في الدفعة.
  - **TEMP بعد D-W1:** الأدوار التي يضيفها Supabase لاحقًا لا تحصل على TEMP. رافعه: ظهور دور مزود جديد يحتاجها.
  - **قائمة الإصدارات ≤100 في النقل.** رافعه: بلوغ الحد.
  - **صلاحية الاعتماد بين ساعة و90 يومًا.**
