## 3. Concrete query/export contract

For each stream preserve a deterministic mixed ordering: newest time first, id ascending. Cursor predicate is `t < cursor_t OR (t = cursor_t AND id > cursor_id)`; match index direction and type (UUID vs bigint). Reject malformed cursor, excessive/negative limit, forbidden user/filter combinations; check owner before processing anything. Page fields/counts disclose only necessary data, no auth email/user_id in export; join code in SQL. Use row id dedupe and explicit page errors. Notes' attempt number comes from SQL join, not the current browser attempt page.

Export captures upper boundary, chosen filters, format version, UTC time, row counts and completeness/error status. Stream bounded pages to a file or split into clearly numbered bounded parts with counts; do not concatenate all 250k full rows in browser memory. Choose a supported browser download mechanism after reviewing target phone support; no new package/backend just for file streaming. Never reuse visible page as “full export”. Retain BOM/CRLF/quoting/formula guard in each part. Export wording must say **rows read within boundary during export**, not a guaranteed point-in-time snapshot: supplied timestamps and concurrent backdated writes defeat time-boundary-only snapshots. If exact snapshot export is needed, stop and get a concrete contract before adding an ingestion sequence or stored export job. Note text inclusion follows S-PILOT-14; automatic flags/masking need a separately scoped decision/validation, not “scrubbed = anonymous”.
