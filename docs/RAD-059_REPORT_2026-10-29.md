# RAD-059 — تقرير التصميم والإيقاف والمراقبة المحلية

## 1. الانحرافات والميزانية

الهدف حزمة تصميم وأداة محلية للهاتف؛13ملفًا وصفر وحدات مشتركة. checkout نفسه حُدث من main قبل العمل؛ الأساس إتمام P1 B وإزالة العزل وفق B8 وبوابة مغلقة. لا بيانات مشاركين حقيقية. أضاف المالك مهلات قصيرة وصف PARTIAL/FAILED، وتنبيه420ثانية مقابل timeout300ثانية، وبقاء gate مغلقة عند غياب مستجيب بديل.

## 2. المنجز والمستبعد

المرحلة1: [التصميم](RAD-059_OPERATIONS_DESIGN.md) وخيارات القنوات/الصحة/التكلفة وقرارات التجميد وحدود الإلغاء. المرحلة2: [SQL الإيقاف](../supabase/manual/assess-emergency-stop.sql) و[التحقق](../supabase/checks/assess-emergency-stopped.sql) و[المراقبة](../supabase/checks/assess-operations-monitor.sql)، و[حزمة الهاتف](RAD-059_PHONE_PACKET.md) المولدة واختبار PostgreSQL إلزامي في CI. المرحلة3: [دليل الهاتف](RAD-059_PHONE_RUNBOOK.md) بخطوات GCP وشاشاتها، والاستعادة المنفصلة، وقائمة تجربة المالك قبل المستخدمين. أضيفت فحوص manifest التسعة وLOGIN إلى الحزمة كي ينقلها المالك مباشرة من GitHub دون مولّد/CLI. لا قناة أو جدولة أو موارد أو أسرار أو Variables تغيرت.

## 3. بحسب المهمة

RAD-059 فقط أصبحت in_progress؛ review بعد دمج التصميم والأداة والاختبارات بواسطة المالك، ثم تبقى إجراءات التنبيه والتجربة الحية مفتوحة. RAD-085 وRAD-082 والحقوق/الخصوصية لا تتغير. مصدر الحالة الوحيد [project-status](project-status.md).

## 4. المشترك وScale

لا وحدة مشتركة أو منتج تغير. المراقبة الهاتفية يدوية كل5دقائق في النافذة؛ SQL مقترحة بسقف1000 وسنتينل1001، والتنبيهات افتتاح/إغلاق دون إعادة دورية. مهلة lock2s/statement5s لكل مرحلة إيقاف بدل رفض الأعداد؛ تجاوز المهلة فشل معلن. رافع السقف RAD-082، والخطة المدفوعة قرار مالك مستقل.

## 5. الطب والدرجات

لا تعديل طبي أو مصحح أو درجات أو نتائج مسجلة. قرار المالك: آخر إجابات محفوظة تُجمد في grading-failed، والاستعادة للتصحيح فقط بعقد recover_v1 خلال7أيام دون تمديد. أثبتت اختبارات المرحلة2 تطابق results/details/receipts/reservations/profiles والكتالوج والدرجات المسجلة؛ finish مشروع ملتزم قبل حاجز الجلسات يبقى graded.

## 6. QA

المرحلة1: نجحت docs:check مقابل origin/main بلا أخطاء أو تنبيهات مراجعة، وstatus:check مع require-previous، وgit diff --check؛ المرحلة2: نجحت7اختبارات node:test على PostgreSQL18.4 (الخادم المعزول المثبت من manifest القائم)، منها إعادة بناء LF وCRLF،111جلسة و10اتصالات عامل بعد SET ROLE بما فيها اتصال بقاعدة ثانية، وتكرار الإيقاف والدور الغائب وصف gate المفقود. ثبت رفض اتصال جديد بعد COMMIT ورفض finish القديمة وcommand المجمدة، واستعادة الحالات الثلاث عبر recover_v1 ورفض ما تجاوز7أيام. المرحلة3 وسعت الشاهد إلى فحوص manifest التسعة دون تغيير مصادرها: كل حقول الجاهزية ناجحة قبل الإيقاف وبعد الاستعادة على LF/CRLF، ومنها P1 B الحالية13/13؛ أعلام restore/runtime المصممة false باقية false، وجاهزية LOGIN active_catalogue_valid=true. كما ثبت أن timezone جلسة SQL Editor المختلفة لا تغير تمثيل التجميد؛ SQL يثبت UTC محليًا للمعاملة. الشاهد يستخدم هياكل Auth اصطناعية للـcreated_at/banned_until/sessions/refresh_tokens التي يقرأها C2؛ لا يزعم اكتمال تمثيل Supabase.

شواهد الفشل: قفل الجلسات يعيد freeze:55P03؛ trigger محلي بطيء يعيد freeze:57014 مع بقاء gate/NOLOGIN ملتزمتين؛ قفل gate يعيد أخطاء gate/verification؛ مشغل محدود الصلاحية يعيد PARTIAL، وغير مخول يعيد FAILED. لا skip. أثبتت المراقبة READ ONLY والنتائج UNKNOWN_CEILING/null عند تجاوز1000جلسة أو تسجيل. نجح lint للملفين الجديدين وdocs:test75؛ فحوص docs/status/diff ناجحة بلا تحذيرات مراجعة.

ملاحظتان أثناء التطوير صُححتا محليًا: fixture الإجابة احتاج specs المطابقة للعقد القائم؛ مهلة إقرار إنهاء الاتصال100ms كانت تعطي PARTIAL صريحًا رغم وصول العدد0، فصارت1000ms لكل اتصال مع بقاء الحلقة كلها محكومة5s. لم تتغير توقعات/بصمات قديمة. نجح تطابق حزمة النقل؛ أكبر جزء SQL8812حرفًا، وكل الأجزاء أقل من15000 بعد الغلاف، بما فيها الجاهزية التسعة وفحص LOGIN للدورين. لا qa:golden/qa:characterise.

قراءة GitHub واحدة لرأس المرحلة2 أثبتت deploy=success وcheck=pending؛ هذه ليست نتيجة الرأس النهائي. CI وPages المعتادان يعملان دون skip ci؛ أضيف اختبار RAD-059 الإلزامي بعد تجهيز PostgreSQL. نتيجة دفعة التسليم تُقرأ مباشرة مرة واحدة ولا تُفترض ناجحة. لا polling أو فتح معاينة مستضافة.

غير المنفذ محليًا: app build/check الكاملان وتدقيق متصفح/axe لأن المنتج لم يتغير؛ ينفذ CI المعتاد الفحوص والبناء. لا SQL حي/اختبار هاتف من الوكيل أو تشغيل Job/قناة/سر أو قراءة فوترة حية. PostgreSQL المحلي18.4؛ Supabase17.11 وردت في إفادة المالك السابقة، ولا يثبت هذا تطابق مزود أو اختبار cache.
