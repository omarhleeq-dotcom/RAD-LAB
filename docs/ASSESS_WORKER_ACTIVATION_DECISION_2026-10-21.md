# قرار TEMP وقناة السر لعامل Assess — مقترح للمراجعة

## الحالة والنطاق

طلب المالك «تمام ابدا» بعد نجاح [التجهيز المغلق](ASSESS_WORKER_LOGIN_STAGE_REPORT_2026-10-21.md#worker-login-stage-owner-result). هذه متابعة إعداد قرار التفعيل وقناة السر؛ ليست إذن LOGIN أو تعديل PUBLIC أو إنشاء موارد Google. assess_job_a يبقى NOLOGIN، وlaunch_gate مغلقة. [حزمة login](ASSESS_WORKER_LOGIN.md) مرجع الحواجز والإلغاء، و[حزمة الربط](ASSESS_EXTERNAL_BINDING_READINESS_2026-10-21.md) مرجع IAM/الموارد/الإنفاق؛ لا تتغير سياسة النسخة المؤجلة.

المعلوم من المالك: PostgreSQL17.11، وPUBLIC TEMP=true، وPUBLIC schema CREATE count0. صف الدور يثبت staged=true وactive=false وdirect_assess_table_access=false وbackend_sessions=0. credential/pooler/runtime=false مقصودة. CREATE0 تخص منح PUBLIC للمخططات، وليست جردًا لكل دوال/بيانات/منح المزود التي يمكن الوصول إليها.

## 1. توصية PUBLIC TEMP وحدودها

**التوصية للمراجعة:** إبقاء منح PUBLIC المشتركة كما هي، وقبول TEMP فقط كاستثناء تجربة يدوية محددة بعد استكمال جرد السطح الفعلي، لمدة أقصاها سبعة أيام من وقت تفعيل مستقل مسجل بـUTC. لا قبول ضمني من هذا المقترح أو من «staged=true». لا جدولة أو تشغيل مستمر، ولا ادعاء tick-only أو عزل كامل للقاعدة.

| الخيار | الأثر | التوصية |
|---|---|---|
| سحب TEMP من assess_job_a وحده | لا يلغي ما يصل إليه عبر PUBLIC؛ لا توجد صلاحية DENY تغلب المنحة المشتركة | يُرفض كحل صوري |
| سحب TEMP من PUBLIC ثم إعادة منحها لقائمة أدوار | يغير صلاحيات الجميع وقد يؤثر في Practice والمزود؛ يلزم جرد المستفيدين والاعتماد واختبار وتراجع منفصل | لا ينفذ في هذه المتابعة |
| استثناء TEMP محدود للتجربة | يتجنب تغييرًا جماعيًا، مع بقاء قدرة إنشاء جداول مؤقتة واستهلاك الموارد وخطر حجب الأسماء | المرشح المشروط أدناه؛ ليس مسار إنتاج |
| الإبقاء على NOLOGIN | يمنع اختبار مصادقة العامل حتى تُحل الشروط | المسار الحالي، ويبقى إن تعذر قبول الاستثناء |

TEMP تتيح إنشاء جداول مؤقتة وليست بحد ذاتها SELECT على جداول Assess أو تصريحًا لإنشاء كائن دائم. لكنها تسمح باستهلاك مساحة/موارد، وقد تستغل دوالًا ذات صلاحيات مرتفعة تستعمل أسماء relations/types غير مؤهلة. وجود search_path='' في دوال المستودع وحده لا يثبت السلامة: pg_temp قد تدخل ضمن البحث عن العلاقات/الأنواع، ويلزم مراجعة الأسماء الفعلية المؤهلة ومسارات SQL الديناميكي والدوال القابلة للاستدعاء خارج assess أيضًا. لا يكفي ضبط search_path عند login أو SET ROLE كبديل للمراجعة.

شروط الموافقة على الاستثناء، كل منها دليل مستقل:

- جرد catalogue فقط بهوية الإدارة للأدوار assess_job_a وassess_worker وPUBLIC، يشمل المخططات والجداول/الأعمدة/sequences والدوال EXECUTE وSECURITY DEFINER وأصحابها وproconfig والعضويات والـdefault privileges واللغات/foreign access القابلة للاستعمال، بلا بيانات مستخدمين أو كلمات مرور/verifiers أو نصوص جلسات. أي أسماء/دوال حساسة تُراجع محليًا؛ يرسل ملخص منقح فقط. لا فحص دوال باستدعائها: health/consent أو worker RPC قد تكتب.
- جرد قواعد المزود القابلة للاتصال عبر CONNECT أو PUBLIC؛ عدم جردها يمنع وصف الحساب بأنه مقيد بقاعدة postgres وحدها. الاستثناء يشمل TEMP على postgres فقط، ولا يجيز تجاوز أي وصول آخر مجهول.
- مراجعة اعتماد الدوال التي يستطيع العامل الوصول إليها: مراجع relations/types مؤهلة، وعدم مسار يسمح بقراءة/كتابة غير مقصودة أو تصعيد عبر كائن مؤقت. أي فجوة تُوقف التفعيل وتحتاج معالجة منفصلة، دون تعميم سلامة مصدر المستودع على حالة المزود.
- تحديد نافذة واحدة وهوية المنفذ ومسؤول DB قادر على الإلغاء والقتل. المرشح التشغيلي المالك Rad-lab، ويجب تأكيد قدرته وبديل مسمى قبل التشغيل المستمر؛ لا تعيين شخص أو إرسال رسائل من هذه الوثيقة. عند غياب قدرة إلغاء محددة للمزود يبقى الحساب معطلًا.
- صلاحية password المقترحة تنتهي في موعد UTC لا يتجاوز وقت التفعيل+7أيام، مع موعد إلغاء يدوي قبل الانتهاء. هذا يضيّق الحد السابق ≤90يومًا لهذه التجربة فقط؛ لا تغيير لفاحص catalogue أو سياسة الدوران العامة. VALID UNTIL لا يقتل جلسة قائمة ولا يلغي طرق مصادقة أخرى.

الضوابط الحالية pool1 وtask count1/parallelism1 وretries0 وtimeout300s تقلل العمل العادي؛ ليست حصص أمان لـTEMP أو عدد جلسات Supavisor. connection limit2 لا يثبت قيد frontends/cache. إعدادات جلسة يستطيع المستخدم تغييرها ليست بديلًا لحدود موارد يفرضها المزود. لا اقتراح حصة قرص أو مراقبة TEMP غير متاحة كأنها مطبقة. أي تكلفة غير متوقعة أو جلسة تعود بعد الإلغاء توقف التجربة وتستدعي الحجر.

## 2. قناة السر — أداة أول إصدار مجهّزة، والتفعيل غير مثبت

المسار المرشح: جهاز المالك الموثوق → عميل psql (المتاح لدى المالك18.6) → مطالبة كلمة مرور مخفية، ثم إدخال JSON إلى Secret Manager من [أداة أول إصدار المراجعة](../scripts/assess/upload-worker-secret.py) في Cloud Shell بذاكرة/stdin. أُعدت واختُبرت اصطناعيًا، ولم يصل شاهد رفعها الحي بعد. لا SQL Editor لتعيين password، ولا URI/وسيط CLI/ENV/ملف على Downloads أو داخل Git يحتوي السر. لا إرسال كلمة postgres أو كلمة العامل أو SCRAM verifier للمحادثة. شهادة CA عامة وليست كلمة مرور.

| الخطوة اللاحقة | المسؤول/الإجراء المحدد | شرط القبول أو التوقف |
|---|---|---|
| جاهزية جهاز المالك | التحقق من psql ونسخته ومسار CA؛ أداة تشخيصه الحالية Get-Command psql وpsql --version فقط | لا تثبيت تلقائي أو وصول عن بعد مفترض؛ بيئة الوكيل Linux مستقلة عن Windows |
| اتصال إدارة مستقل | psql -X، TLS verify-full مع hostname الصحيح وCA المراجعة وconnect timeout10s؛ password الإدارة عبر prompt فقط | لا sslmode=require أو تجاوز السلسلة/الاسم. اسم postgres.projectRef يخص الإدارة وحدها؛ لا يدخل config العامل |
| حماية السجلات | منع echo/debug/transcript وتسجيل الإدخال/الجلسة محليًا، ومراجعة server/audit/proxy/pooler logs لمنع plaintext وverifier | لا يكفي psql prompt وحده لإثبات إخفاء SCRAM verifier من logs المزوّد. عدم القدرة على التحقق يبقى عائق قبول التفعيل؛ تجهيز سر لحساب معطل لا يثبت سلامة logs ولا يغير audit، ولا يُطلب سجل خام |
| توليد سر العامل | مولد عشوائي تشفيري أو مدير كلمات مرور موثوق على جهاز المالك؛ 32byte عشوائية على الأقل، مثال ترميز base64url ينتج43محرفًا؛ فريد لهذا login | لا كلمة نموذجية أو إعادة كلمة postgres؛ لا توليد داخل المحادثة. إن استُعمل clipboard فتعطل مشاركته/history وتُمسح بعد الإدخال؛ لا يُعد المسح محوًا مضمونًا |
| ضبط كلمة الدور المعطل | داخل psql يستخدم المنفذ meta-command المستهدفة \password assess_job_a بعد مراجعة password_encryption=scram-sha-256 | \password عملية ALTER ROLE كتابة فعلية، تحتاج نطاق التفعيل اللاحق؛ ليست فحصًا أو أمرًا مطلوبًا الآن. لا نطبع verifier. يبقى NOLOGIN حتى نجاح تخزين السر والتحقق من الخطة |
| إدخال نسخة السر | بعد إذن Google منفصل، أداة محلية مراجعة تقرأ password مخفية وCA العامة، وتستخدم JSON serializer ثم stdin لـgcloud secrets versions add assess-worker-config --data-file=- مع project صريح | [الأداة](../scripts/assess/upload-worker-secret.py) مبنية ومختبرة اصطناعيًا للإصدار1 فقط، وتوقف وجود نسخة/فشل/غموض دون replay؛ لا أمر PowerShell pipeline يدوي أو تشغيل حي للوكيل. ترفض args/env/files للسر وتطبع metadata منقحة فقط؛ أي فشل يبقي NOLOGIN |
| تثبيت الإصدار | مسؤول السر يسجل رقم N وlogin وexpiry UTC وCA fingerprint دون payload؛ الناشر يثبت N في mount /run/secrets/assess-worker.json | IAM على السر الواحد فقط وفق الحزمة؛ لا latest أو تنزيل مفاتيح SA. نجاح upload/metadata لا يثبت محتوى أو اتصال runtime |
| تفعيل محدود | بعد موافقة محددة وتحقق جديد للحواجز، تعيين VALID UNTIL ثم LOGIN؛ readiness وcredential/pooler/identity/ACL تختبر منفصلة | لا activate-on-upload أو تشغيل تلقائي، ولا فتح gate. فشل أي مرحلة يبقي/يعيد الحجر وفق خطة الإلغاء |

دليل psql17 الرسمي يوضح أن \password يطلب الإدخال ثم يشفره من جانب العميل ويرسله كـALTER ROLE، فيحمي plaintext من history/server log. هذا لا يضمن أن verifier لم يسجل أو أن proxy/audit لدى Supabase يحذفه، ولا يثبت أن psql الموجودة على Windows محدثة أو متاحة. psql -X يتجاوز startup file الخاصة بالعميل فقط؛ لا يثبت قبول startup options أو هوية backend من session pooler.

قالب البيانات غير السري المثبت في الأداة: host=aws-1-eu-central-1.pooler.supabase.com، port=5432، database=postgres، user=assess_job_a، sessionPoolerProjectRef=vlacestfruxooznrcjqc، ca=PEM العامة المراجعة، password=إدخال مخفي فقط. الأداة تركب JSON بالـserializer؛ النقل القائم يركب الاسم المركب. لا نكرر PEM أو نص JSON بكلمة بديلة قابلة للتنفيذ. يجب إثبات الحجم≤64KiB وnon-root read من الإصدار المثبت لاحقًا؛ لا ملف سر منشأ الآن.

## 3. نافذة التفعيل والإلغاء المقترحة

قبل بدء النافذة تُسجل موافقة TEMP المحددة ونتيجة جرد السطح وهوية المشروع ومشغّل DB ووسيلة إلغاء pooler وموعد expiry ونافذة المراقبة وقناة التنبيه. لا يبدأ إجراء كتابة بالاعتماد على المستند وحده، ولا يعاد إنشاء الدور بعد صف نجاحه.

تسلسل الاعتماد: إثبات القناة وأداة الإدخال ببيانات اصطناعية أولًا؛ ثم إذن ضيق لتعيين سر الدور المعطل وتخزين نسخة محددة فقط؛ ثم تحقق مستقل قبل LOGIN؛ ثم اختبار مزود محدود مأذون. لا worker tick أو publish/recover RPC كفحص اتصال. اختبار DB read-only مستقل عن تشغيل runtime الذي قد يكتب. إنشاء SA/secret/Job/registry أو IAM يظل تجهيزًا خارجيًا له نطاق ومراجعة مستقلة.

عند خطأ بعد تعيين password أو upload وقبل LOGIN، يبقى الدور معطلًا ولا تُجرّب credentials في loop. توثق metadata فقط، وتعطّل النسخة الجديدة عند وجودها؛ PASSWORD NULL/expiry والإلغاء تُنفذ من قناة الإدارة المأذونة عند الحاجة. لا إعادة تنشيط سر قديم مشتبه به أو جعل LOGIN حلًا لخطأ رفع.

عند فشل بعد LOGIN: امنع runs وألغ executions؛ نفذ حزمة الإلغاء التي تثبت NOLOGIN/password null/expiry/revoke قبل قتل backends المحددة، ثم أوقف frontends/cache بإجراء المزود المراجع. تحقق رفض اتصال جديد وفشل اتصال كان قائمًا وعدم عودة جلسة عبر فحص محدود60s، وبقاء حساب غير معني سليمًا؛ هذا لم يُنفذ على Supavisor. لا توسيع قتل/إعادة تشغيل عامة أو افتراض أن budget/إصدار السر/VALID UNTIL يقتل جلسة. صاحب النافذة مسؤول الإغلاق وتسجيل النتيجة؛ غياب البديل يمنع العمل دون حضوره.

## 4. القرار المطلوب بعد اكتمال الشروط

الموافقة اللاحقة يجب أن تسمي الاستثناء TEMP على postgres وassess_job_a فقط، ومدته القصوى7أيام، والمشغّل وموعد الانتهاء، وأن تعتمد نتيجة السطح وقناة السر. قبول هذا الاستثناء لا يقبل بقية صلاحيات PUBLIC أو يرفع أعلام credential/pooler/runtime، ولا يأذن تشغيلًا أو نشرًا أو فتح gate. ما لم تكتمل الشروط يبقى NOLOGIN هو النتيجة الصحيحة.

وصل شاهد المالك: psql18.6 تعمل من D:\Tools\PostgreSQL\17\bin\psql.exe والشهادة المطابقة محفوظة على D؛ لا إعادة تثبيت أو نقل الملفات إلى C. فحص psql لم ينجح بالمصادقة، والكلمة الإدارية غير متذكرة؛ [تقرير أثر reset](ASSESS_POSTGRES_PASSWORD_IMPACT_REPORT_2026-10-21.md) يحفظ الأدلة وتصحيح PEM/DER وحدود TCP. التالي مراجعة استخدامات postgres خارج المستودع واتخاذ قرار استعادة/إعادة تعيين مستقل قبل اتصال جديد، ثم أداة الإدخال الاصطناعية والجرد. لا حاجة لإعادة مرحلة NOLOGIN أو TLS الناجحين، ولا طلب نسخة احتياطية مؤجلة مجددًا.
