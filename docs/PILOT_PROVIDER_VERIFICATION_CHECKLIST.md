# قائمة التحقق من مزوّد الهوية وقاعدة البيانات (RAD-040) — 2026-10-15

**الحالة:** **لم يُنفَّذ التحقق.** سياسة شبكة جلسة Claude Code منعت الوصول إلى مواقع المزوّدين (`supabase.com` وغيره؛ أخطأ الاتصال بـ 403 على نفق CONNECT)، فلا توجد هنا أي معلومة عن مزوّد بعينه. هذه الوثيقة **قائمة أسئلة ومعايير قبول فقط**، تُملأ من الوثائق الرسمية عند توفر الوصول. لا تُعدّ ترشيحًا لأي مزوّد.

## 1. المطلوب لرفع الحجب (من المالك)

إما:
- **توسيع الشبكة:** من قائمة البيئة السحابية (شريط عنوان الجلسة ← تعديل) ← Network access: مستوى أوسع، أو إضافة المضيفين المطلوبين في Allowed domains مع إبقاء مربع Allow package managers مفعّلًا (الخطوات: https://code.claude.com/docs/en/cloud-environments#network-access)؛ أو
- **لصق الصفحات** الرسمية (النص أو لقطات) في المحادثة، فأقرؤها منها.

**المضيفون المقترحون للقراءة:** `supabase.com` (وثائق وأسعار)، `firebase.google.com` و`cloud.google.com` (بديل غير علائقي للمقارنة)، `neon.com` (Postgres مُدار دون هوية)، ووثائق أي مزوّد آخر يقترحه المالك. القراءة فقط؛ لا حساب ولا مفتاح ولا تسجيل.

## 2. المزوّدون المرشّحون للمقارنة

| المرشّح | النوع | سبب إدراجه |
|---|---|---|
| خدمة مُدارة تجمع هوية + Postgres + RLS (مثل Supabase) | مرشّح رئيسي | تطابق تصور المالك (علائقي، RLS، دعوات) |
| Postgres مُدار + هوية منفصلة (مثل Neon + خدمة هوية) | بديل | فصل المسؤوليات؛ تعقيد أكبر |
| هوية وبيانات غير علائقية (مثل Firebase) | مقارنة | مألوف؛ لكنه ليس علائقيًا ولا يدعم RLS بنفس المعنى |
| Cloudflare Access + D1 | أساس المقارنة | يلائم الاستضافة الحالية؛ لا RLS (سبق استبعاده كخيار أول، S-PILOT) |

## 3. الأسئلة التي تُجاب من الوثائق الرسمية (لكل مرشّح)

كل جواب يُسجَّل مع **رابط الصفحة وتاريخ قراءتها واقتباس قصير**، وما لم يُقرأ يُكتب «لم يُقرأ».

| # | السؤال | معيار القبول |
|---|---|---|
| A1 | **تعطيل التسجيل العام** وإبقاء الدعوة فقط | يمكن منع التسجيل الذاتي تمامًا من الإعدادات |
| A2 | **دعوة بالبريد من المالك** (من لوحة أو واجهة إدارية) | رابط لمرة واحدة بانتهاء؛ المدعو يضع كلمة المرور بنفسه؛ المالك لا يرى كلمة المرور |
| A3 | **تأكيد البريد** | إلزامي قبل الدخول |
| A4 | **سياسة كلمة المرور** | حد أدنى قابل للضبط، فئات أحرف، فحص كلمات مسرّبة (وعلى أي باقة) |
| A5 | **حماية من التخمين** | تحديد معدل أو قفل بعد محاولات فاشلة |
| A6 | **التحقق بخطوتين** لحسابات المالك | متاح (وعلى أي باقة) |
| A7 | **سجل الدخول** | أحداث الدخول والخروج والفشل، مكان العرض، مدة الاحتفاظ، قيود الباقة |
| A8 | **استعادة كلمة المرور** | بالبريد دون تدخل المالك |
| B1 | **سياسات الصفوف (RLS)** | مدعومة صراحة، وطريقة اختبارها، وحدودها (الأدوار التي تتجاوزها) |
| B2 | **أدوار الاتصال** | الواجهة الأمامية تستعمل مفتاحًا عامًا لا يتجاوز RLS؛ المفتاح الإداري لا يظهر في المتصفح |
| B3 | **معاملات وقيود علائقية** | لازمة لتوسع المقاعد والمؤسسات لاحقًا |
| C1 | **مناطق التخزين** المتاحة وموقعها | أقربها لمنطقتنا؛ وهل تُغيَّر لاحقًا (Q1) |
| C2 | **الخصوصية والمعالجة** | شروط معالجة البيانات، مكان الاستضافة، من يملك البيانات، التصدير والحذف |
| C3 | **النسخ الاحتياطي والاستعادة** | وجوده على الباقة المقترحة، تكرارها، تجربة الاستعادة (متطلب قبل أول مشارك) |
| D1 | **الباقة المجانية** | حدود المستخدمين والتخزين والطلبات، وهل تتوقف المشاريع عند الخمول |
| D2 | **أقل باقة تناسب 100 مشارك** | سعر شهري تقريبي، وما الذي يضيفه (نسخ احتياطي، سجلات، تحقق مسرَّب) |
| D3 | **الخروج من المزوّد** | تصدير كامل للبيانات بصيغة قياسية (تجنب الارتهان) |
| E1 | **الطلبات من الواجهة الثابتة** | النطاقات التي ستتصل بها الواجهة، وإمكان تمريرها عبر نطاقنا (Q4) |
| E2 | **خدمة المراقبة** | سجلات الأخطاء والتنبيهات المتاحة |

## 4. شكل المخرَج (جلسة التنفيذ)

جدول مقارنة قصير (مرشّح × سؤال) بالأجوبة المرفقة بالروابط، ثم توصية واحدة، وتحديث الخطة (`PILOT_PLATFORM_PLAN.md` §4 و§9: Q1–Q4)، وتسجيل القرار في DECISIONS. بلا كود ولا حساب لدى المزوّد.

## 5. ما لا نفعله في هذه الجلسة

لا إنشاء حسابات عند المزوّدين ولا مفاتيح ولا أسماء نطاقات ولا تسجيل بيانات حقيقية؛ لا قبول أسعار أو شروط نيابة عن المالك.
