## 3. RAD-056 والأدوات المحلية

RAD-056 تبقى review/waiting_on owner؛ ليست done ولا قبولًا حيًا. أُنجز تجهيز الأدوات ووصل جرد الأصلية الخالي من البيانات التشغيلية والمستحقات. المتبقي حماية نطاق التنفيذ والتزامن وتطابق الواجهة/SQL وتجهيز الهوية ونافذة تشغيل مستقلة؛ لا انتظار إعادة الجرد نفسه.

`installOneMixed` تقبل UUID واحدًا فقط، تفسر الإعداد عبر parseJobConfig القائمة بـconnections1 وتستعمل createWorkerBinding القائمة؛ ثم installMixedContent الحالية: content_read_v1 → validateMixedContent → content_install_v1. لا قائمة مرشحين أو install ضمن tick، ولا claim/maintain/health أو تغيير gate. كل مسار بعد إنشاء النقل ينتظر close حتى عند فشل التحقق/التثبيت؛ فشل cleanup مستقل. نجاح الأداة لا يثبت المراجعة الطبية أو إذن نشر الوثيقة. المرشح pending مطلوب؛ installed أو missing يتوقف دون إعادة تثبيت. فقد إقرار COMMIT يعني STOP غير محسوم، لا retry أو افتراض rollback.

`closeOneAssignment` تقبل UUID إسناد واحدًا وإعداد owner منفصلًا (URL المشروع الحالي، مفتاح عام، accessToken authenticated). ترفض service_role/المفاتيح السرية والإضافات والوجهات الأخرى. تحليل صيغة JWT تصنيف أولي فقط؛ `auth.getUser(accessToken)` لدى المشروع يتحقق من الهوية قبل أي RPC. بعدها تستعمل retentionService.close القائمة وclose_assignment_v1، وSQL يتحقق من is_owner وowner_id=auth.uid. طالب أو مالك آخر مرفوضان. لا auth.uid أو claims أو userId يمررها المشغّل، ولا service/admin key أو worker capability لهذا المسار. requests بمهلة15ثانية ورفض redirect؛ لا جلسة دائمة أو refresh تلقائي أو logout يلغي جلسة المالك الأصلية. فشل RPC/الإقرار يتوقف دون replay أو تسجيل JWT/هوية/خطأ خام.

الاستيراد خامل. main تقبل فقط أحد علمي التنفيذ الصريحين `--authorized-install-mixed` أو `--authorized-close-assignment` ثم UUID، دون flags إضافية أو URL/سر في argv/ENV. loader يقرأ حتى64KiB من `/run/secrets/assess-worker.json` القائم للتثبيت، أو `/run/secrets/assess-owner.json` للإغلاق، ويرفض symlink؛ ملف المالك يشترط صلاحيات0600 أو أشد. ملف المالك واجهة إدخال مستقبلية مؤقتة، لم يُنشأ/يرفع ولم يُجهز secret جديد أو تدفق استخراج JWT هنا. لا تطلب tokens بالمحادثة أو تلصقها بأوامر/history؛ تجهيز جلسة مالك آمنة وتنظيفها لاحقًا خطوة مستقلة قبل استخدام CLI.

الأداة محلية من المصدر عبر Node24 وnode-loader القائم، ولم تضاف إلى job-main أو صورة العامل. لا تُنفذ أعلامها من هذه الجلسة. أي تعبئة لصورة تشغيل مستقلة أو mount أو window أو أمر تشغيل حي يحتاج تحضيرًا ومراجعة لاحقة؛ لا إعادة استخدام Job التشخيص لتشغيلها ضمنيًا. مخرجاتها contract/outcome/code/runtimeOrLaunchVerified=false فقط؛ لا IDs أو وثيقة أو درجة أو رد RPC.

## 4. المراجعة المشتركة وScale والعزل

المصدر الحاكم: [maintain_v1 الأحدث](../supabase/migrations/20261020001100_assess_retention.sql) و[claim_v1](../supabase/migrations/20261020000700_assess_lifecycle.sql) و[runAssessJobs](../src/features/assess/server-service.ts). maintain تعمل على كل Assess: انتهاء ثم void ثم failed ثم purge ثم reservations ثم consents، ولكل مرحلة حدها الخاص. claim لا تقبل assignment وتختار الأقدم المؤهل عالميًا. gate لا تحرس أيًا منهما، وإغلاق الإسناد يمنع البدء الجديد ولا يوقف تسوية المحاولات القائمة. health عالمية أيضًا. limit1/taskCount1/اسم التجربة ليست عزلًا.

| نتيجة الجرد | المعالجة المطلوبة قبل التشغيل |
|---|---|
| تجاوز100/مهلة/نقص صلاحية/اختلاف schema | توقف؛ لا counts جزئية أو رفع سقف تلقائي. يلزم تصميم جرد بصفحات خادمية محدودة ولقطة متسقة/تجميع موثوق مراجع إن كان الحجم الحقيقي يحتاجه |
| محاولات أو طابور أو leases/retries/مستحقات أو metadata مستحقة خارج التجربة | تمنع tick العالمية على الأصلية. الخيار الأدنى أثرًا بيئة اختبار منفصلة خالية ببيانات مصطنعة؛ إن استمر شرط الأصلية، يلزم عقد عزل SQL مراجع يغطي **كل** مراحل maintain وclaim وhealth وتزامن إدارة/بدء، مع اختبارات رفض النطاق، لا تعديل limit أو claim وحدها |
| إسنادات مفتوحة/targets أو محتوى pending/available أخرى | لا تنسبها تلقائيًا للتجربة أو تغلقها/تعطل أصحابها. البوابة العامة قد تتيح بدءها. يلزم حصر server-side موثوق للبدء والإدارة/التقديم والتثبيت أو بيئة منفصلة؛ غلق واجهة/اتفاق شفهي لا يحجر backend |
| لقطة خالية | ليست قفل تزامن أو إذن تشغيل. بعد تجهيز بيانات التجربة يلزم شاهد محدود يطابق UUIDs المعروفة داخليًا دون كشفها في الدليل، وحجر/قفل قابل للإثبات يغطي الكتابات المتزامنة ونافذة كل tick؛ أي فشل يعيد المسار إلى بيئة منفصلة أو عقد العزل |

وصلت نتيجة الجرد الخالية من البيانات التشغيلية؛ لا يلزم تنظيف أو ترحيل أو إنشاء بيئة أخرى تلقائيًا بسبب بيانات سابقة. تبقى حماية التزامن شرطًا مستقلًا. لا نغيّر claim/maintain أو صلاحيات الأصلية من هذا الشاهد وحده، ولا نعد حارس تطبيق قبل RPC حلًا لفجوة TOCTOU. العد الإجمالي المتساوي قد يخفي تبديل صفوف؛ لن يُستعمل كإثبات أن الصفوف تخص التجربة. لا تنفيذ تلقائي لمعالجة عزل من هذه الحزمة. البيئة المنفصلة المقترحة بيانات هندسية جديدة، لا نسخ بيانات مستخدمين أو طلب نسخة شاملة الآن. لا إعادة طرح قرار النسخ المؤجل.

المعالجة المطلوبة تحديدًا بعد هذا الصف هي **عزل نافذة التنفيذ والبدء**، لا تنظيف الأصلية. قبل أي تشغيل لاحق على الأصلية يجب أن يثبت عقد خادمي مراجع أن:

1. UUIDs المحتوى والإسنادين والطالب المسند ثابتة ومتحقق منها داخليًا، ورفض البدء/الإدارة خارج نطاق التجربة مفروض في الخادم أثناء النافذة؛ اسم التجربة أو تطابق الأعداد أو حارس واجهة لا يفي بذلك.
2. فحص النطاق والتنفيذ لا تفصل بينهما نافذة كتابة غير محكومة: إما فحص وتنفيذ تحت حماية معاملات/أقفال مراجعة تغطي مصادر الشروط، أو عمليات SQL مقيدة بالنطاق نفسه. قفل advisory لا يكفي ما لم تلتزم به كل طرق الكتابة. لا تُمنح جداول للعامل لتجاوز RPC القائمة.
3. تشمل الحماية جميع مراحل maintain: انتهاء وvoid وfailed وpurge وreservations وconsents، وclaim وhealth، دون مس سجلّي الموافقة السابقين أو تغيير أعمار الاحتفاظ. نتيجة غير متوقعة أو فشل حماية يمنع العملية قبل أي أثر؛ لا فحص بعد global tick لإعلان أنها كانت معزولة.
4. اختبارات محلية تضيف إسنادًا أو محاولة أو استحقاق metadata خارج النطاق، وتنافس كتابة بين الفحص والتنفيذ، وتثبت الرفض/حفظ البيانات خارج التجربة. تكون اختبارات SQL متعددة الاتصالات مرجع التزامن؛ PGlite المتسلسلة وحدها لا تثبته.

هذا وصف قبول للمعالجة التالية، وليس حارسًا مثبتًا أو migration مطبقة. إن تعذر تحقيقه على الأصلية يكون البديل بيئة هندسية منفصلة بلا نسخ بيانات مستخدمين. لا يفرض الصف الخالي أحد الخيارين تلقائيًا، ولا يجيز فتح gate/LOGIN أو تشغيل العامل. أدوات تثبيت mixed والإغلاق الموجودة كافية لنوعي العملية المحددين، لكنها لا تحصر runAssessJobs الحالية.

Scale: سقف100 لكل جدول و15 جدولًا عقد جرد محدود لا سعة منتج؛ رفعه يحتاج سببًا ومراجعة واختبارًا. UUID واحد للعملية، اتصال واحد، لا polling أو scheduler أو retry أو تعميم وجهات. خريطة الجداول وشروط المستحقات مرتبطة بترحيلات B–F/retention الحالية؛ أي تغيير schema/SQL ذي صلة يستدعي مراجعة الحزمة قبل قبول نتيجة جديدة. لا API عامة أو تغيير وحدات مشتركة.
