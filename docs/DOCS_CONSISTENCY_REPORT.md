# تقرير اتساق التسليم والحالة

## 1. الانحرافات والميزانية

الهدف المعتمد: تصحيح التناقضات وتقليل تقادم HANDOFF وتوليد حقائق الجلسة وتقوية الفحص المشترك. البداية main بعد #85 عند `003b3b97c82ddbeb832fe8aa7ab2d6e20874b62b`، وفرع العمل `docs/handoff-consistency`؛ هذه لقطة دليل، لا تعليمات بدء مستقبلية.

الميزانية النهائية12 ملفًا. أُلغي توسيع مؤقت إلى14 لتصحيح وقت الحالة بعد أن أصبح UTC الفعلي عند الاستئناف لاحقًا للوقت السابق، فعاد فاحص الحالة إلى أصله وحُذف الاختبار المضاف لهذا الاستثناء؛ لا منتج أو اعتماد جديد أو تغيير اختبار منتج أو CI. الملفات: AGENTS.md، docs/HANDOFF.md، docs/project-status.md، docs/status-format.md، docs/README.md، docs/DOCS_CHECKS.md، هذا التقرير، package.json، scripts/docs/check-docs.mjs واختباره، scripts/docs/context.mjs واختباره.

## 2. المنجز والمُسقَط

- HANDOFF مختصر للبدء والمتبقي والعوائق والمتابعة، ويربط الأدلة بدل تكرار الفرع وSHA وإصدار الحالة وQA وطلب الدمج الذي يتقادم.
- أمر `docs:context` يقرأ حقائق Git بلا كتابة أو شبكة افتراضيًا؛ `--pr NUMBER` يتحقق صراحةً عبر gh أو يصرّح بالفشل. لا استنتاج من ref محلي ولا تثبيت أو login تلقائي أو polling.
- `docs:check` نفسه ينبه إلى أوصاف انتظار داخل مهام done ويرفض أنماط النسخ المتغيرة في HANDOFF؛ CI الحالي يشغله دون تعديل workflow.
- مُسقَط: الادعاء بأتمتة فهم كل تناقض أو إثبات الطب/النشر/الهاتف أو ضمان الوصول الشبكي في كل بيئة. لا سجل حالة آخر ولا أداة جديدة لتحديث الملفات تلقائيًا بعد الدمج.

## 3. لكل مهمة وحفظ الدليل

RAD-052/053/054: صُححت الأوصاف لتطابق done وإفادة المالك المدموجة في #85؛ بقيت completion_evidence وsource_ref والحالات كما هي. التحسين البصري في RAD-057 بقي deferred.

كشف الفحص أيضًا وصف RAD-040 يقول إن دمج #49 متبقٍ، بينما دليله الموروث يسجل الدمج؛ صُحح الوصف وحده وأُحيل النطاق الخارجي إلى O103/RAD-041 دون إغلاقه. كل المهام الأخرى والمعرّفات وnext_id محفوظة، ولا إعادة فتح RAD-025 أو إغلاق طبي/خارجي.

تحديث وقت الحالة تم بساعة UTC الفعلية بعد الاستئناف؛ لم يبقَ استثناء لتصحيح الساعة أو تغيير في فاحص انتقال الحالة أو حقول JSON أو توقع اختبار قائم.

## 4. المشترك وScale

تعليمات البدء والتسليم في AGENTS، وتفاصيل العقد في status-format، والأوامر وحدودها في DOCS_CHECKS، والفهرس يحيل إليها. راجع حقول المهمة معًا وHANDOFF كاملًا قبل التسليم؛ تنبيه الفاحص يُصحح أو يشرح في التقرير. لا حاجة إلى PR لتحديث رقم «آخر PR» فقط بعد كل دمج.

Scale: الفحص يمر على المهام دون قائمة RAD ثابتة؛ عدد اختبارات ملفات الأدوات يُكتشف بنمط الملفات. context يقرأ PR واحدًا مطلوبًا واستجابتين محدودتين بمهلة وحجم، لا مسحًا متزايدًا للتاريخ. يدعم origin GitHub بصيغة HTTPS أو SSH وgh القائم؛ غير المدعوم يبقى غير متحقق ويمكن استخدام الموصل. مرجع origin/main خاص بسير هذا المستودع، والمقارنة المحلية مع فرع أساسي آخر تعرض null. لا شبكة في CI ولا تبعية جديدة.

## 5. الطبي والدرجات ومراجعة المعنى

لم تتغير قيمة طبية أو درجات أو رسم أو hash أو رخصة. بقيت المراجعات والتجميد وتأجيل البرمجة. هل تغيّر الحكم؟ تغيرت آلية تدوين Git والتسليم فقط؛ أحكام المنتج والمهام لم تتغير. هل بقي الدليل؟ نعم، إحالات المهام وأدلة إغلاقها والأرشيف والقرارات محفوظة دون تعديل.
