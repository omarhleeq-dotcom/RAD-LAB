# RAD-086 — إجراء النسخ الاحتياطي على اللابتوب وأدواته، تقرير2026-10-31

الهدف: إجراء مراجع وأدوات دنيا لنسخ يومي آلي واستعادة مجربة على لابتوب المالك، بمسار session pooler. الوكيل لم ينفذ SQL حيًا ولم يضبط Variables ولم يفتح gate ولم يفعّل LOGIN أو سرًا ولم يكشف سرًا. السلطة: [قرار المالك D-A/D-B](DECISIONS.md#rad086-laptop-owner-2026-10-31) و[D2](DECISIONS.md#rad085-owner-tidy-2026-10-27). الدليل: [RAD-086 runbook](RAD-086_LAPTOP_BACKUP_RUNBOOK.md).

## 1. الانحرافات والميزانية

الميزانية المعلنة قبل التحرير: 13 ملفًا ووحدة مشتركة واحدة (`rad062-db-day.mjs`)؛ النتيجة 12 ملفًا (لم يلزم تعديل `docs/README.md`):

انحرافان تفسيريان يلزم مراجعتهما: (أ) **الـpooler لا يخدم `apply` و`restore`** في `rad062-db-day.mjs`؛ أمر المالك لم يوسع يوم القاعدة الكتابي إلى pooler، فأبقيته على المسار المباشر وسجلته بندًا مفتوحًا. (ب) pg_dump يجري بعميل المضيف17.11 وDocker لإثبات الاستعادة فقط، فلا يتوقف النسخ اليومي على تشغيل Docker Desktop. لم تُضعف أي حماية أو تأكيد أو مهلة؛ المسار المباشر بالبايت نفسه منطقيًا (اختبار يثبته)، وحزم الطوارئ وsupabase/manual وملفات المخطط المفحوصة بايتاتها ثابتة (اختبار `byte identical` القائم ينجح).

## 2. المنجز والمستبعد

منجز (كود وتوثيق، دون تشغيل على اللابتوب): محدد `--session-pooler` مع `RAD062_POOLER_HOST`؛ مساعد نسخ يومي للقراءة فقط؛ سجل مصالحة age؛ أداة استعادة Docker؛ دليل المالك؛ مقترح الاحتفاظ؛ تصميم اختبار Supavisor؛ تحديث شروط P9. مستبعد: أي تنفيذ على الإنتاج أو اللابتوب، الحذف الآلي للنسخ القديمة (مقترح يدوي فقط)، تنبيه سحابي، توسيع pooler إلى `apply`، دور نسخ مخصص بصلاحيات أقل.

**بند4 (Supavisor): STOP للجزء الإنتاجي.** الاختبار الفعلي لاعتماد العامل القديم مستحيل دون كشف أو تفعيل إصدار السر DISABLED، والدور NOLOGIN فيُرفض أي اتصال لسبب غير cache. صُمم بدلًا منه اختبار على مشروع scratch (دور probe، ثم NOLOGIN وتدوير كلمة المرور، ومحاولات بالاعتماد القديم عند0/30/90/180/300 ثانية مع تحكم إيجابي)، وهو لا يثبت شيئًا عن مستأجر الإنتاج أو السر الحقيقي. خيارات المالك الخمسة في الدليل (قبول scratch، دور مؤقت في الإنتاج بحزمة SQL مراجعة، اختبار عند أول تدوير حقيقي، سؤال Supabase، أو تدوير باسم دور جديد). لا شيء ضبط `pooler_cache_verified`.

## 3. بحسب المهمة

RAD-086 انتقلت من blocked إلى **review** مع waiting_on=owner، لا done: العائق (اللابتوب غير متاح) انتفى بإفادة المالك، والمتبقي تنفيذ المالك وقبوله. [مصدر الحالة](project-status.md) وحده يحمل ذلك. لم تتغير مهمة أخرى. RAD-062 وRAD-059 دون تعديل؛ فقط شروط P9 تشير الآن إلى مسار pooler.

## 4. المشترك وScale

المشترك الوحيد `options()` في `rad062-db-day.mjs`: محدد صريح، مضيف مطابق للنمط `aws-N-<region>-N.pooler.supabase.com` ومساوٍ لـ`RAD062_POOLER_HOST`، مستخدم `postgres.<ref>` بالضبط، منفذ5432 بالضبط (6543 مرفوض)، `verify-full` وملف CA، المرجع المتوقع نفسه؛ بلا اكتشاف تلقائي ولا fallback؛ يرفض `apply/restore/verify`. أداة النسخ تعيد استعمال `options()` نفسها فلا قاعدة ثانية. S-STD-3: سقوف مسماة في الدليل (القسم I): توفر اللابتوب (يعمل والمالك مسجل الدخول، ولا تنبيه، والضابط فحص `status` الأسبوعي)؛ كلمة مرور `postgres` في ملف0600 (رافعه دور نسخ مخصص بعد مراجعة المخططات المُدارة)؛ إصدار17 و`postgres:17.11` ثابتان (عدم تطابق يوقف بـ`version`)؛ موقع واحد مع USB أسبوعي؛ قراءات الاحتفاظ يدوية (رافعه حجم>25GB). الإعداد والبيانات: ملف config مُصدر الشكل ويرفض مفاتيح غريبة؛ سجل المصالحة ملف لكل إدخال قابل للإضافة بلا حد.

## 5. الطب والدرجات

لا تغيير طبي أو درجات أو بيانات منتج أو ترحيل. النسخة تحوي بيانات مشاركين فتبقى على قرص مشفر وUSB مشفر BitLocker To Go؛ سياسة الاحتفاظ بها تتبع بوابة الخصوصية.

## 6. QA

نُفذت في بيئة الوكيل (دون الإنتاج): `node --test scripts/docs/laptop-backup.test.mjs` 7/7، تتضمن **بروفة حقيقية** على PostgreSQL16 محلي ببيانات اصطناعية: لقطة مصدرة متسقة مع pg_dump، عدّ الجداول، sha256، الصلاحيات0700/0600، رفض الكتابة فوق مجلد قائم، إعادة تسمية `.failed` عند الفشل، سجل age مع سلسلة تكشف الحذف، وعدم ظهور أي سر في المخرجات. اختبار الاستعادة يعمل بـdocker وهمي يتحقق من الوسائط (`--network none` وبلا `-p`/`-P` وبلا كلمة مرور و`--pull never` وlocale الحي) ومن مسارات counts وextensions والأرشيف المعبوث؛ **لم يُشغَّل Docker حقيقي** (لا daemon هنا). `rad062-db-day.test.mjs`: اختباران جديدان للـpooler (قبول ورفض شامل: 6543، مستخدم، منفذ، مضيف مزيف، غياب CA، apply، وتحقق أن المباشر لم يتغير) والبقية تنجح. الاختبار `actual local logical restore` يفشل هنا لأنه يحتاج daemon Docker (STOP المعروف من P9b) ويفشل بالطريقة نفسها على main دون تغييراتي. نتائج `npm run check` وdocs:check وstatus:check وdiff --check في آخر القسم. **غير مُنفذ**: أي اتصال بـSupabase/pooler الحقيقي، TLS verify-full أمام شهادته، Docker Desktop، Task Scheduler؛ تثبتها تشغيلات المالك B وC وD3.

## 7. البنود المفتوحة

1) قرار: هل يُسمح لـ`apply` بالمرور عبر pooler؟ حتى ذلك يحتاج يوم القاعدة اتصالًا مباشرًا (IPv6 غير متاح على هذا اللابتوب) فيبقى محجوبًا. 2) قبول اختبار scratch أو اختيار آخر لبند Supavisor. 3) صيغة مضيف pooler الفعلية قد لا تطابق النمط (يلزم إبلاغ الشكل وتغيير مراجع). 4) الاستعادة قد تقف عند extensions غير المتوفرة في الصورة العامة (إعلان مصدر الصورة بديل بقرار منك). 5) سياسة الاحتفاظ مقترحة فقط. 6) اللابتوب قد لا يتوفر عند الجدولة: الإنذار يدوي. 7) معرفة هل يقبل Supavisor الـsnapshot المصدّر وقيود idle-transaction؛ الفشل يظهر برمز `snapshot` بلا fallback مضعف.
