# مراجعة دورة Assess وخطة تجربة مضبوطة — 2026-10-22 عمّان

## 1. النطاق والميزانية والقرار

طلب المالك مراجعة الدورة من البداية للنهاية وتحديد اختبار تجريبي مضبوط بعد نجاح ربط Google. هذا إذن مراجعة وتخطيط وفحوص محلية؛ ليس إذن فتح launch_gate أو تفعيل العامل/LOGIN أو نشر محتوى/إسناد/حسابات على الأصلية. الميزانية أربعة ملفات توثيق: هذا التقرير وREADME وHANDOFF وproject-status؛ لا كود أو SQL أو صلاحيات أو صورة أو موارد أو Variable تتغير. معيار القبول خريطة مسارات مع مصادرها، تمييز الشاهد الحي من المحلي، عوائق محددة، وسيناريو بمدخلات ونتيجة معروفة وتوقف وإغلاق واضحين.

**القرار:** الاتصال الخاص جاهز ضمن [شاهد الربط والإغلاق](ASSESS_GOOGLE_PROVISIONING_REPORT_2026-10-21.md#cloud-run-probe-closed-final)، لكن التجربة الحية الكاملة ليست جاهزة للتنفيذ الآن. المسار الأول المرشح اختبار هندسي مؤقت من نوع mixed يحوي MCQ غير طبية فقط. لا نحتاج اختيار مزود أو إعادة TLS/login/probe؛ نحتاج أداة تشغيل لتثبيت المحتوى وحدودًا مثبتة لأثر tick وبوابة البدء قبل الكتابة الحية. هذا لا يغيّر [قرارات المنتج](DECISIONS.md#assess-owner-2026-10-19) أو [S-ASSESS-15](DECISIONS.md#assess-retention-owner-2026-10-20) أو [توجيه النسخة المؤجلة](DECISIONS.md#assess-retention-original-no-backup-2026-10-20).

### عوائق مثبتة قبل التجربة

1. **تثبيت المحتوى ليس آليًا:** job-main يشغل runAssessJobs فقط. مرشح owner JSON يظل pending دون مسار تشغيل trusted لـinstallMixedContent. لا يُحل بتفعيل ASSESS_JOB_ENABLED أو إدخال مفتاح إجابة إلى المتصفح. المسار المطلوب عملية مستقلة لمعرّف مرشح واحد، بلا gate toggle أو tick ضمني، بإصدار وصلاحية وتنقيح مخرجات مراجعَين.
2. **التشغيل أوسع من تصحيح محاولة واحدة:** maintain_v1 قد ينهي محاولات أو يحذف نتائج/metadata مستحقة، وclaim_v1 يختار من طابور Assess كله. لا يوجد assignment/session allowlist في entrypoint أو claim الحالية. launch_gate تحرس البدء العام ولا تقيد الصيانة أو claim بإسناد أو توقف جلسة قائمة. لا نفتحها على الأصلية بناءً على اسم اختبار تجريبي أو taskCount1 وحدهما.
3. **مسار العملي الكامل مؤجل للتجربة الأولى:** [installPracticalContent](../src/features/assess/server-practical.ts) موجود، لكن [server-runtime](../src/features/assess/server-runtime.ts) لا يصدره ولا يسمح content_install_practical_v1 في operations. هذا عائق توصيل تشغيلي، لا ادعاء أن مصحح العملي ناقص. لا نعد اختبار MCQ دليل قبول simulator-part أو full-practical.
4. **التطابق المنشور والإدارة والإيقاف:** المسودة غير مدموجة، ونجاح Pages لا يثبت أي نسخة UI يفتحها المشارك أو وجود موافقة v2 عليها. يلزم تثبيت نسخة الواجهة/SQL والهوية، ومسار close/disable مفوض، ومشغّل قادر على وقف execution وDB login/جلساته ومتابعة cache. لا schedules أو retry تلقائي خلال التجربة.

### شرط النطاق على الأصلية

أول خطوة حية مقترحة **جرد قراءة فقط بأعداد محدودة ومنقحة**: المحاولات بحسب حالتها، المستحق منها للصيانة/الاسترداد/الحذف، الإسنادات المفتوحة ومستهدفوها بالعد، مرشحو المحتوى/الإصدارات، metadata قابلة للتنظيف، وحالة البوابة/الدور. لا أجوبة أو علامات أو نص جلسات أو raw claims، ولا محتوى PRIVATE في الدليل. لا يكفي sessions0 تحت اسم مستخدم DB؛ ذلك عدد اتصالات قاعدة لا عدد محاولات Assess.

تكون صفحة الجرد محدودة بالخادم، مثل سقف100 وسنتينل101 يعني «أكثر من السقف» ويتوقف القرار بدل عدّ جزئي على أنه إجمالي. SQL الجرد لم تُنشأ أو تُنفّذ في هذه المراجعة، ولا نستنتج أن الطابور خالٍ. قبل أول tick يجب إثبات عدم وجود مستحقات/محاولات/مستهدفين غير التجربة ضمن النطاق العالمي، ومنع تغييرات إدارة متزامنة خلال النافذة؛ إن تعذر الإثبات، يتوقف التشغيل على الأصلية إلى معالجة عزل محددة ومراجَعة. مجرد لقطة فارغة ليست قفل تزامن. لا إضافة سياسات allowlist أو تغيير claim/maintain ضمن مراجعة توثيقية.

## 3. RAD-056 وخطة التجربة ذات النتائج المعروفة

تبقى RAD-056 review/waiting_on owner؛ لا completion_evidence أو done. الخطة التالية مرشحة بعد حل العوائق، وليست عمليات أُجريت أو موافقات قبول نيابة عن صاحبها.

### حدود التجربة المقترحة

- ثلاثة حسابات مخصصة: مالك معتمد، طالب A معتمد ومسند، وطالب B معتمد غير مسند. لا حسابات طلاب حقيقيين أو تغيير اعتماد غير المعنيين. تستخدم واجهة Auth الفعلية؛ لا worker capability للمستخدم.
- نسختان immutable مختلفتان للمحتوى لا تعديل سياسة النسخة المستعملة: visible بسياسة after-submission لمدة300ثانية ومحاولة واحدة، وhidden لمدة120ثانية ومحاولة واحدة. إسناد فردي لـA فقط؛ لا مجموعات/توسعة مستهدفين في الجولة الأولى.
- سؤالان single-choice بالإنجليزية، حروف/أشكال هندسية غير طبية، لكل منهما5نقاط والمجموع10. مفتاح خاص يحدد خيارًا واحدًا لكل سؤال. يسجل المنفذ إجابة صحيحة للأول وخاطئة للثاني؛ المتوقع5/10. نطاق المراجعة «اختبار برمجي غير سريري» ومصدر fixture الأصلي فقط، لا أسماء مراجعين أو مصادر طبية مختلقة.
- لا simulator أو تعريض أو صور أو فحص جديد؛ تلك جولة لاحقة بمحتوى ومصدر ومراجعة O108. لا توصف النتيجة5/10 بأنها صحة تقييم سريري.
- تشغيل يدوي محدود بعد اتفاق نافذة محددة ومسؤولها وموعد الإغلاق، دون scheduler. عملتان مقصودتان كحد أقصى، واحدة لكل محاولة بعد تسليمها/انقضائها. لا نرفع batch أو نكرر tick لملاحقة queued أو غموض finish؛ أي أعمال غير متوقعة توقف التجربة.

## 4. التغييرات المشتركة وScale

لا تعديل وحدات مشتركة. الحد المقترح نسختان ومحاولتان واتصال عامل واحد وتشغيل يدوي بلا جدول. حدود الصفحات وقيم الوقت هنا لتجربة هندسية محددة، لا سياسة منتج جديدة أو سعة مثبتة. claim/maintenance العالميان وhealth التي تجمع حالات sessions كلها لا يصيران tenant-isolated من limit1؛ رفع الحجم/المشاركين أو تشغيل متكرر يحتاج قياسًا وعزلًا ومراقبة وموافقة مستقلة.

التطوير التالي المقترح بعد المراجعة: أداة تثبيت mixed محدودة بمعرف مرشح واحد تستعمل validateMixedContent/createWorkerBinding الحالية وتغلق النقل، وقناة إغلاق مفوضة للمالك، وجرد محدود يثبت نطاق تأثير العامل أو معالجة عزل محددة إن فشل. لا إضافة API عامة أو worker RPC للمتصفح أو دمج تثبيت المحتوى داخل grading tick. هذه مهام لم تنفذها مراجعة الجاهزية.

## 5. الطب والدرجات والاحتفاظ

O108 والمصادر/الرخص/المراجعة والخلفيات والمعايير وMarker تبقى بوابات المحتوى الطبي. تجربة حروف مصطنعة تثبت ميكانيكا5/10 فقط. لا فحوص أو صور أو قواعد Practice أو expectations/hashes تغيرت. خطة النسخ المعتمدة باقية، وتوجيه المالك بتأجيل النسخة الشاملة محفوظ دون إعادة سؤال أو إعداد تلقائي؛ لم يثبت backup/restore/export أو نسخة مزود أو تنبيه من هذه المراجعة. الحذف والأعمار لا تُعدّل لتنظيف تجربة بسرعة؛ metadata/نتائج التجربة تتبع S-ASSESS-15 وإغلاق الإسناد، ولا DELETE يدوي لإخفاء أثرها.

## 7. المفتوح ومعنى التوقف

الربط ثبت وانتهى، والمجهول الآن نطاق البيانات المنشورة والواجهة الحالية، ومسار تثبيت المرشح وإغلاق الإسناد، وأثر الصيانة/claim العالميين، وقبول المستخدم وJWT/العزل حيًا، ومراقبة وإلغاء/cache وتكلفة ونسخ/restore. لا نجمع كلها تحت «مشكلة اتصال». لا نعيد كلمة postgres أو worker أو upload من عدم جاهزية المحتوى. الجزء المكشوف سابقًا من كلمة العامل ورفض تدويره محفوظان في تقرير الربط، ولا يعاد كشفه.
