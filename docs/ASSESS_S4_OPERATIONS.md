## Backup preparation and RLS boundary

Reuse RAD-086 public-key age encryption, snapshot/count/digest checks and isolated restore approach. `scripts/ops/cloud-backup.mjs` defaults to zero connections/uploads; `--run` alone selects a fixed Secret Manager mount, exact assess_backup identity, direct host and verified TLS. It rejects membership/admin/BYPASSRLS/write/DDL privileges, unknown inventory, missing full-row SELECT policies and applicable restrictive policies. No private age identity is accepted. Runtime scratch must be a memory volume; credentials are ephemeral there and removed in finally. The bucket receives only a complete age-encrypted tar containing custom archive, password-free role definitions, metadata and checksums, with generation-match0 and a unique daily name.

Verified synthetic hypothesis: SELECT alone hides RLS rows and row_security=off refuses export. A full-row SELECT policy scoped solely to assess_backup, with no applicable restrictive policy, permits complete `pg_dump --enable-row-security`. This flag is deliberate and conditional on policy/inventory checks, not a silent partial export. The isolated PostgreSQL17 proof restores actual encrypted data, binary/large-object bytes, sequence state, schema ACL/RLS and checksums; write/nextval/DDL/SET ROLE, drift and upload-failure cases fail. The private identity is used only by the restore test, never passed to the backup API.

**Pending privilege review:** exact inventory-pinned SELECT grants and SELECT-only assess_backup RLS policies. No production packet is installed or implied by the synthetic proof. Provider-owned Auth/extension tables, sequence and large-object coverage, Vault decryptability and external provider settings need explicit owner coverage evidence; a missing object or inaccessible table is a failed backup, never an accepted exclusion. A SQL database dump is not Storage object content or a Secret Manager export. Keep the reviewed laptop backup for every owner window and routine fallback until automatic coverage, encrypted restore, failure notification and receipt are proved.
