# RAD-085 — عقود SQL المحلية المؤجلة عن الواجهة

هذه عقود مصدر محلي قيد المراجعة، وليست شهادة تطبيق أو قبولًا سريريًا. أُضيف [ربط P1 المحلي](RAD-085_P1_SQL_REPORT_2026-10-26.md) فقط باستخدام RPCs القائمة على PostgreSQL معزول؛ P2 والاتصال الحي وسياسة المشاركة المعتمدة والجسر ما زالت مؤجلة. [تقرير SQL السابق](RAD-085_SQL_REPORT_2026-10-26.md) يحفظ أدلة دفعة SQL وحدودها، دون إعادة كتابة التاريخ.

**ليس additive محضًا:** أُضيفت أعمدة وconstraint إلى groups ومفتاح أجنبي period_id إلى memberships، وثلاثة triggers: حماية تحديث/حذف المجموعة المدارة، صيانة فترات العضوية ومنع تجاوزها بالعمليات القديمة، وإيصال تسجيل Practice بعد INSERT. لم تُستبدل دالة أو constraint أو trigger قديم ولم يُكتب تاريخ migrations من جديد. public.attempts لا تتغير أعمدته أو منح/RLS قراءته وكتابته؛ لا backfill للوقت أو العضويات أو الموافقات. المجموعات القديمة بلا supervisor_id تظل في المسار القديم ولا تتحول تلقائيًا.

## التفويض والأقفال والتوقيت

هوية المستدعي من auth.uid() فقط. لا actorId أو اختيار حساب من fixture في عقد الخدمة. الحساب approved وغير موقوف في Assess، والمشرف يحتاج تعيينًا قائمًا ومجموعة تخصه. الدور public.profiles.role يبقى participant/owner؛ is_owner() لم يتغير. لا إدارة حسابات أو surveys أو directory عام للمشرف. كل الجداول الجديدة RLS/default-deny دون منح مباشرة حتى للمالك أو assess_worker. الدوال الداخلية غير ممنوحة؛ العامة SECURITY DEFINER وsearch_path فارغ مع grants صريحة.

كل RPC جديد يأخذ قفل scope_lock أولًا: SHARE للقراءة وUPDATE للتغيير حتى نهاية المعاملة، ثم قفل profile للمستدعي. القراءة والتغيير على اتصالات منفصلة يتسلسلان عند هذه الحدود؛ الوقت clock_timestamp بعد الانتظار. العقد يقبل READ COMMITTED فقط ويرفض REPEATABLE READ/SERIALIZABLE لمنع لقطة عضوية قديمة بعد انتظار القفل. الربط اللاحق يجب أن يستدعي RPC واحدًا لكل معاملة وألا يحول قراءة ثم كتابة داخل معاملة طويلة إلى ضمان لم يُختبر.

هذا قفل عالمي لنطاق المشرف، يسلسل تغييرات المجموعات المختلفة؛ سقف throughput معلن، لا تصميم سعة إنتاج مثبت. القراءات متوافقة بعضها مع بعض. يلزم قياس انتظار القفل والأداء وحمل الطيار قبل الاستخدام؛ فصل الأقفال لكل مجموعة عند رفع السعة يحتاج تصميم ترتيب أقفال واختبارات جديدة. صلاحيات SQL الإدارية والعمليات القديمة غير المدارة ليست محصورة بهذا القفل؛ لا جسر إداري/ناشر جديد مأذون هنا.

sharing_policy تبدأ بلا نسخة أو بصمة؛ جميع خطوات الانضمام والرؤية التي تحتاج المشاركة تفشل مغلقة. يجب لاحقًا اعتماد نص المشاركة/نسخته وبصمته وتمكين عرض النص الصحيح قبل قبول المستخدم. لا نص أو نسخة قانونية أو موافقة فعلية مخترعة في migrations. السياسة الاصطناعية موجودة داخل اختبارات PostgreSQL وحدها. سحب القبول يحجب البيانات؛ إعادة القبول تبدأ نافذة جديدة بaccepted_at ولا تعيد السابق.

الرمز بطول64محرفًا سداسيًا من UUIDv4 عشوائيين (نحو244بت من العشوائية) ويخزن SHA-256 فقط؛ لا list/read يعيد raw code. التدوير يبطل السابق؛ السحب أو الإنهاء يبطل الرمز. throttle عشر محاولات/ساعة/حساب، والرفض العام نتيجة محفوظة لا exception يعيد العداد بالrollback. يثبت الربط مع المستخدم أن إعادة إرسال RPC بعد خطأ الشبكة قد تستهلك محاولة؛ لا retry غير محدود. لا اتصال/رمز حقيقي في الاختبارات.

العضوية الحالية في memberships، والتاريخ في membership_periods. البيانات منذ max(joined_at,starts_at,appointed_at,sharing accepted_at)، وللعضو الفعال الحالي فقط، والمجموعة والتعيين فعالان. السحب أو المغادرة أو الانتهاء يوقف الرؤية. Practice يعتمد practice_recordings.recorded_at الخادمي؛ started_at/finished_at للعميل لا يحددان النافذة. الصفوف القديمة بلا إيصال محجوبة. score هو total المحفوظ للعرض فقط، بلا إعادة تصحيح أو ادعاء نزاهة Practice؛ result/settings الخام لا يعادان للمشرف.

## ربط P1 المحلي وحدوده

[sql-adapter](../src/features/supervisor-review/sql-adapter.ts) يثبت هوية واحدة لدى النقل ويقارن actorId محليًا فقط؛ لا يرسل هوية مستدعي إلى RPC. كل RPC معاملة قصيرة منفصلة عبر حاضنة Unix socket القائمة. لا Supabase client أو URL أو مفتاح، ولا إدخال adapter في مسارات التطبيق أو تغيير شهادة المتصفح. الاختبارات تجمع adapter وRPC الحقيقيين؛ قبول المتصفح يمر عبر HTTP محلي إلى SQL الحقيقي، لا مخزن بيانات بديل.

- المالك: appointments بقائمة20 وUUID keyset؛ تعيين معرف participant معتمد مدخل صراحة، والسحب من التعيينات القائمة. لا directory جديد أو تفويض للمشرف بإدارة الحسابات.
- المشرف: groups ثم requests/members/practice للمجموعة المختارة، وإعادة قراءة جيل المجموعة قبل عرض المجموعة المركبة. total خادمي للأعضاء والتدريب فقط. لا تحويل score إلى نسبة/درجة قصوى مخترعة أو إعادة تصحيح، ولا نتائج امتحانات في هذه الدفعة.
- الطالب: my-requests فقط. العقد لا يقدم my-groups أو استعلام عضوية الذات؛ لا تختلق الواجهة أسماء/انتهاء مجموعات من fixture. يظهر إجراء المغادرة الآمن المتكرر على الطلب المقبول؛ isMember=null؛ الطلب المقبول سجل قرار وليس دليل استمرار العضوية. لا تعرض بيانات مشرف للطالب.
- لا RPC لحالة تعيين الذات دون مجموعة؛ appointed=null عند غياب مجموعة مقروءة، دون ادعاء أن المشرف معيّن أو مسحوب. إنشاء المجموعة يعاد تفويضه في SQL. المجموعة المختارة غير المقروءة تُرفض وتُمسح بياناتها.
- sharing_consent_v1 يستعمل للقراءة فقط في adapter. لا زر قبول أو نص قانوني معتمد مخترع. المسار غير المهيأ/غير المقبول يغلق نموذج الانضمام. fixture الاختبار تضبط سياسة موسومة اصطناعية ثم تقبل الحسابات الاصطناعية عبر RPC الذات فقط، خارج واجهة المنتج.

كل تغيير محلي يبطل القراءات والرموز قبل/بعد RPC. خادم القبول ينشر إشارة إبطال بلا بيانات عبر SSE داخل loopback فقط؛ فقد القناة يمسح العرض ولا يعيد تحميله تلقائيًا. الواجهة تتحقق من AbortSignal وجيل الطلب وهوية adapter والاستعلام/المراجعة؛ تمسح عند رفض/فشل/مغادرة/سحب/نهاية، وتحسب مهلة العرض من serverNow ووقت رتيب محافظ يخصم زمن النقل. الرد المتأخر لا يرفع الإبطال، ولا إعادة محاولة تلقائية بعد ACK مفقود؛ التحديث ثم إعادة صريحة فقط. الرمز مرة واحدة مرتبط بمعرف مجموعته، ولا يظهر إلا بعد تفويض قراءة مجموعة الإيصال نفسها، حتى لو كانت خارج صفحة المجموعات الحالية.

إشارات الإبطال تخص العمليات المارة بالخادم المحلي؛ التغييرات الإدارية خارج هذه القناة/توصيل إشعارات حي معتمد غير منفذة. لا يثبت هذا PostgREST أو auth أو Realtime على Supabase أو كشفًا فوريًا لتغيير خارجي غير موصول. أي نقل مستقبلي يجب أن يثبت هذه الحدود قبل التشغيل؛ نجاح المحلي لا يفتح المسار الحي. الحجم محدود20صفًا لكل قائمة؛ القراءة المركبة حتى6RPCs دون مسح صفحات كاملة. السقوف العالمية والأداء/انتظار القفل غير مقاسة.

## P2: المسودات والمراجع والنسخة المثبتة

| RPC | العقد |
|---|---|
| draft_save_v1(group,id,revision,document,refs) | كاتب المجموعة الحالي فقط؛ جديد revision=0، والتعديل يحتاج revision الحالي؛ رفض تبديل track أو خلط mixed/full-practical. يعيد revision+1 ومستندًا خاصًا، لا publication |
| draft_page_v1(group,id,after,limit) | id محدد يعيد مستند الكاتب وحده، والقائمة metadata فقط؛ لا قراءة لطالب أو مشرف آخر |

الـdocument شكل مستقل مضبوط عن RPC: schemaVersion/id/revision/track/name/policy/items؛ track صريح في الخدمة. الـfixture القديم بلا track يحتاج mapping إلى mixed عند الربط، ولا يُفسر سكوتًا داخل القاعدة. refs قائمة key/revision من سجل خادمي خاص حالي وفعال؛ partId يطابق مرجع جزء، وcaseRef/evaluatorVersion يطابقان مرجع full-practical. سجل المراجع فارغ افتراضيًا ولا يُملأ من بيانات يرسلها المتصفح. أي تجهيز لاحق له يجب أن يشتق المراجع من السجل القائم ويثبت case/evaluator/rule؛ ليس إضافة فحص أو محتوى أو مراجعة طبية.

المسودات تسمح نقص الحقول التحريرية، وتتحقق من الشكل والفصل والحجم والمراجع، وليست بديلًا لـdraftIssues أو validateMixedContent/validatePracticalContent والتحقق الطبي. الحفظ يثبت نسخة خاصة وبصمتها؛ البصمة تشمل document وrefs بـJSONB في PostgreSQL، ولا تستخدم JSON.stringify من المتصفح لمقارنتها. سقوف الدفعة:5مسودات/كاتب،100revision/مسودة،200بند و128KiB/مستند،50خيارًا. النسخ التاريخية يمكن أن تستهلك نحو64MiB/كاتب عند الحدود القصوى قبل overhead؛ هذا ليس ميزانية قبول FREE. لا تشغيل حقيقي أو رفع تلك الحدود قبل قياس السعة ومراجعة سياسة تنظيف النسخ وحفظ روابط الإسناد؛ لا عامل تنظيف في هذه الدفعة.

لا API لإنشاء publication أو authoring_publication_links، ولا grant للعامل عليها. الجسر المستقبلي يجب أن يقرأ النسخة الخاصة، يتحقق من المصدر والترخيص والمراجعات المطلوبة وO108 والمقياس والمصحح والحالة والإصدارات، ويثبت المحتوى بالقنوات القائمة، ثم يربط version_id بالـdraft/revision/digest نفسه. حقول authoring لا تصنع ContentReview ولا reviewedBy. بدون الجسر والمراجعات والنسخة installed/available الموجودة فعلًا، prepare/confirm مرفوضان. اختبارات النطاق تملأ ربطًا اصطناعيًا عبر مدير PostgreSQL المعزول؛ لا تثبت نجاح ناشر أو مراجعة سريرية.

تغير العضوية بعد التأكيد لا يغير targets أو وصول الطالب تلقائيًا. إعادة الانضمام لا تعيد فترة الاستهداف القديمة للمشرف؛ الطالب يحتفظ بالوصول المثبت ما لم يعدل إسناده صراحة بالمسار المأذون. unique الإسناد المفتوح(owner,version) القائم يبقى؛ محاولة إعداد إسناد ثان مفتوح لنفس النسخة لا تعدل الأول وتفشل عند التثبيت. إيصالات المراجعات المؤكدة محفوظة؛ التنظيف والاحتفاظ بها وعلاقات الحذف تحتاج مراجعة مستقلة قبل التطبيق، بلا عامل جديد.

RAD-060 لها هنا سطح SQL للإغلاق وقراءة closed_at فقط؛ لم يربط زرها أو ينفذ قبول متصفح/هاتف. لا تكتمل بمجرد الاختبار المحلي.

## متطلبات النقل الحي والقبول غير المنفذة

لا adapter حي أو route/menu أو ناقل Supabase جديد. ربط P1 المحلي ينفذ mapping والإبطال الموصوفين أعلاه؛ النقل الحي وربط P2 لاحقًا يحتاجان اعتماد العقود والهوية والإشعارات واختبارها على الخدمة بإذن مستقل. يعالج 42501 رفضًا و40001 تعارضًا و55000 انتهاء/عدم جاهزية و54000 سقفًا و22023 مدخلًا غير صالح؛ لا auto-approve أو قبول نيابة عن المستخدم. أي 23505 من إسناد مفتوح يحتاج عرض تعارض، لا تجاوز unique.

تتبقى سياسة مشاركة معتمدة وقبول الذات، سجل المراجع والجسر المراجع وتطابق العامل/case/evaluator، اختبارات إضافية للعزل والنتائج والمراجع والسباقات/الانتهاء والنسخ/restore والأداء، ومراجعة أمنية مستقلة ثم المالك والمتصفح والهاتف.
