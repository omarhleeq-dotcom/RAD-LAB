# RAD-085 — عقود SQL المحلية المؤجلة عن الواجهة

الحاكم: [قرارات2026-10-27](DECISIONS.md#rad085-owner-tidy-2026-10-27) و[التقرير الموحد](RAD-085_REPORT_2026-10-27.md). سياسة المشاركة الحالية supervisor-sharing-2026-10-27-v2: نتائج الاختبارات المسندة إليّ ضمن هذه المجموعة، ومحاولات التدريب المحفوظة منذ انضمامي لهذه المجموعة؛ AR أساسي وEN مطابق المعنى. النسخة/البصمة القديمة أو المجهولة تمنع القبول. SQL المحلي مطابق بايتًا لمقترح v2 المؤرشف، لا تطبيق حي.

حجب الكاتب/المشرف محدد بالوقت: نقل الإدارة للمالك وإكمال المحو ضمن نافذة Terms ذات30يومًا متطلب قبل البيانات الحقيقية؛ SQL القائم لا ينجز النقل بعد. RAD-082 اليومية الآلية المحلية وRAD-059 الذي يوقف الإنفاق فعليًا شرطان قبل أول امتحان. سجل المصالحة ملف محلي مشفر بجوار نسخ Docker بلا سحابة. الكتابي اللاحق ينبه المالك يوم5 ويجيز تصحيحه قبل7؛ void فقط إن بقي غير مصحح يوم7.

## عامل التصحيح المحلي دون تعديل SQL

[تقرير العامل](archive/RAD-085_WORKER_LOCAL_REPORT_2026-10-26.md) ووصفة build-worker هما دليل هذه الدفعة. worker rad085-grading-worker/1 يستعمل runAssessJobs وgradePublication وclaim/lease/finish القائمة للمسارين، مع tick1/pool1. assess-grader/1 وPractice/8 وكل caseVersion ودرجات/أوزان SQL ثابتة. manifest تربط بايتات الصورة والمصدر والـlock ومصادر SQL وإصدارات الحالات؛ publication/refs مثبتة في snapshot المحاولة، وmismatch يفشل دون تعديل المحتوى أو إعادة تصحيح نتيجة محفوظة.

دور assess_grading_worker خماسي EXECUTE في **fixture فقط**: maintain/claim/finish/fail/health؛ LOGIN صناعي منفصل عن الجسر والمستخدم، بلا نشر أو مراجعات أو حسابات أو recover أو قراءة جداول. لا ترحيل أو منحة مزوّد أو بصمة جديدة. الناقل الجديد يعيد فحص العضوية والمنح الفعلية وCREATE/TEMP وينهي binding عند خطأ دون reconnect صامت. الاستثناء التاريخي للـTEMP لا يعمم؛ صلاحيات المزوّد وSQL تشغيلية جديدة تحتاج فرقًا واستثناءً مستقلًا.

JobControls.stopBeforeFinalize يترك lease عند STOP قبل finalize للعامل الجديد؛ default التاريخي يحفظ drain للـclaim المعلومة. بعد finish مجهولة لا fail/recover/finish آلية أو claim تالية. fail مسموحة تحت lease الحالية بعد تقييم محلي فاشل أو rollback يقره adapter قبل محاولة COMMIT فقط؛ SQLSTATE أو rollback بعد COMMIT مجهولة لا تثبت النتيجة. لا تغيير lease/retry/recovery windows. المصالحة من اتصال مستقل وبالعقد القائم؛ لا recover تلقائية عند startup.

entrypoint محلية فقط، تتحقق من دليل خارج القاعدة قبل البدء وقبل المراحل، وترفض غياب/اختلاف head أو عدم اكتمال الصيانة/الإبطال؛ لا launch_gate كدليل جاهزية. الشاهد الجديد يستعمل reconcileSynthetic لتاريخ صناعي فارغ جديد؛ اختبار التعافي غير الفارغ القائم يبقى مطلوبًا. مخزن وقنوات الدليل التشغيلية والكاتب المحجوب والمزوّد/الإبطال والمراجعة المستقلة باقية عوائق. الصورة وTLS والصلاحيات وSIGTERM والمراقبة والقياس أثبتت محليًا فقط، دون تغيير SQL أو شهادة/بوابة أو نشر أو تشغيل حي.

هذه عقود مصدر محلي قيد المراجعة، وليست شهادة تطبيق أو قبولًا سريريًا. أُضيف [ربط P1 المحلي](archive/RAD-085_P1_SQL_REPORT_2026-10-26.md) باستخدام RPCs القائمة على PostgreSQL معزول؛ P2 والجسر مربوطان محليًا بأدلتهما أدناه؛ الاتصال الحي وتهيئة سياسة المشاركة التشغيلية وهوية نقل الجسر الحية ما زالت مؤجلة؛ معنى نص المشاركة اعتمده المالك كما يبين العقد أدناه. [تقرير SQL السابق](archive/RAD-085_SQL_REPORT_2026-10-26.md) يحفظ التاريخ؛ [التدقيق الداخلي الجديد](archive/RAD-085_SECURITY_AUDIT_2026-10-26.md) و[حزمة التطبيق وبصماته](archive/RAD-085_APPLICATION_PACKET_2026-10-26.md) يحددان المصدر المصحح وشروط التوقف، دون شهادة حي.

## التفويض والأقفال والتوقيت

هوية المستدعي من auth.uid() فقط. لا actorId أو اختيار حساب من fixture في عقد الخدمة. الحساب approved وغير موقوف في Assess، والمشرف يحتاج تعيينًا قائمًا ومجموعة تخصه. الدور public.profiles.role يبقى participant/owner؛ is_owner() لم يتغير. لا إدارة حسابات أو surveys أو directory عام للمشرف. كل الجداول الجديدة RLS/default-deny دون منح مباشرة حتى للمالك أو assess_worker. الدوال الداخلية غير ممنوحة؛ العامة SECURITY DEFINER وsearch_path فارغ مع grants صريحة.

نقاط الدخول العامة الجديدة تأخذ scope_lock أولًا: SHARE للقراءة وUPDATE للتغيير حتى نهاية المعاملة، ثم profile للمستدعي؛ الدوال الداخلية والمشغلات تستعمل ضمن مساراتها. القراءة والتغيير على اتصالات منفصلة يتسلسلان عند هذه الحدود؛ الوقت clock_timestamp بعد الانتظار. العقد يقبل READ COMMITTED فقط ويرفض REPEATABLE READ/SERIALIZABLE لمنع لقطة عضوية قديمة بعد انتظار القفل. الربط العام يستدعي RPC واحدًا لكل معاملة قصيرة؛ الجسر الخادمي وحده يجمع خطواته المقفلة إلى التثبيت والربط في المعاملة الموثقة أدناه.

بموجب الاستثناء الجديد RAD085-SQL-AUDIT-EXPIRY-DELETE-20261026 أُعيد فحص supervised_group عند نهاية read/candidate/install/bind وcontent_submit في فرع الجسر، بعد الأقفال التي قد تتجاوز ends_at. أثبت اختبار PostgreSQL رفض الانتهاء بعد انتظار reference/advisory/version، وrollback للمرشح/الرابط. حارس العضوية في الأول يبقي حذف/كتابة المالك المباشرة مرفوضة مع السماح بـDELETE المتسلسل عندما profile المحذوف لم يعد موجودًا؛ لا منح إدارة حسابات للمشرف. الروابط والمراجعات المرتبطة بقيود FK ما زالت تحتاج إجراء احتفاظ/محو معتمدًا؛ هذا الإصلاح لا يضمن حذف كل حساب مرتبط بمنشور أو إسناد مغلق.

هذا قفل عالمي لنطاق المشرف، يسلسل تغييرات المجموعات المختلفة؛ سقف throughput معلن، لا تصميم سعة إنتاج مثبت. القراءات متوافقة بعضها مع بعض. يلزم قياس انتظار القفل والأداء وحمل الطيار قبل الاستخدام؛ فصل الأقفال لكل مجموعة عند رفع السعة يحتاج تصميم ترتيب أقفال واختبارات جديدة. صلاحيات SQL الإدارية والعمليات القديمة غير المدارة ليست محصورة بهذا القفل؛ لا توسيع إداري عام؛ الجسر الداخلي المحدد أدناه يعمل ضمن قفل النطاق نفسه.

العضوية الحالية في memberships، والتاريخ في membership_periods. البيانات منذ max(joined_at,starts_at,appointed_at,sharing accepted_at)، وللعضو الفعال الحالي فقط، والمجموعة والتعيين فعالان. السحب أو المغادرة أو الانتهاء يوقف الرؤية. ## ربط P1 المحلي وحدوده

[sql-adapter](../src/features/supervisor-review/sql-adapter.ts) يثبت هوية واحدة لدى النقل ويقارن actorId محليًا فقط؛ لا يرسل هوية مستدعي إلى RPC. كل RPC معاملة قصيرة منفصلة عبر حاضنة Unix socket القائمة. لا Supabase client أو URL أو مفتاح، ولا إدخال adapter في مسارات التطبيق أو تغيير شهادة المتصفح. الاختبارات تجمع adapter وRPC الحقيقيين؛ قبول المتصفح يمر عبر HTTP محلي إلى SQL الحقيقي، لا مخزن بيانات بديل.

- المالك: appointments بقائمة20 وUUID keyset؛ تعيين معرف participant معتمد مدخل صراحة، والسحب من التعيينات القائمة. لا directory جديد أو تفويض للمشرف بإدارة الحسابات.
- المشرف: groups ثم requests/members/practice للمجموعة المختارة، وإعادة قراءة جيل المجموعة قبل عرض المجموعة المركبة. total خادمي للأعضاء والتدريب فقط. لا تحويل score إلى نسبة/درجة قصوى مخترعة أو إعادة تصحيح، ولا نتائج امتحانات في هذه الدفعة.
- الطالب: my-requests فقط. العقد لا يقدم my-groups أو استعلام عضوية الذات؛ لا تختلق الواجهة أسماء/انتهاء مجموعات من fixture. يظهر إجراء المغادرة الآمن المتكرر على الطلب المقبول؛ isMember=null؛ الطلب المقبول سجل قرار وليس دليل استمرار العضوية. لا تعرض بيانات مشرف للطالب.
- لا RPC لحالة تعيين الذات دون مجموعة؛ appointed=null عند غياب مجموعة مقروءة، دون ادعاء أن المشرف معيّن أو مسحوب. إنشاء المجموعة يعاد تفويضه في SQL. المجموعة المختارة غير المقروءة تُرفض وتُمسح بياناتها.
- sharing_consent_v1 للقراءة وقبول الذات الصريح والسحب في adapter المحلي. تعرض SharingConsent النصين المثبتين ونسختهما وشرح الحدود وTerms قبل checkbox غير محددة مسبقًا. لا actorId في RPC ولا قبول مالك/مشرف عن الطالب؛ القبول المجهول يرفض قبل النقل، والقاعدة تعيد فحص النسخة/البصمة. السحب متاح حتى عند نسخة مجهولة؛ فشل/ACK مفقودة يمسح العرض دون retry، ثم تحديث وقرار صريح. المسار غير المهيأ/غير المقبول يغلق نموذج الانضمام. حاضنة المتصفح فقط تهيئ النص المعتمد لطلاب صناعيين، ولا تهيئة حية أو ربط بمسارات التطبيق.

كل تغيير محلي يبطل القراءات والرموز قبل/بعد RPC. خادم القبول ينشر إشارة إبطال بلا بيانات عبر SSE داخل loopback فقط؛ فقد القناة يمسح العرض ولا يعيد تحميله تلقائيًا. الواجهة تتحقق من AbortSignal وجيل الطلب وهوية adapter والاستعلام/المراجعة؛ تمسح عند رفض/فشل/مغادرة/سحب/نهاية، وتحسب مهلة العرض من serverNow ووقت رتيب محافظ يخصم زمن النقل. الرد المتأخر لا يرفع الإبطال، ولا إعادة محاولة تلقائية بعد ACK مفقود؛ التحديث ثم إعادة صريحة فقط. الرمز مرة واحدة مرتبط بمعرف مجموعته، ولا يظهر إلا بعد تفويض قراءة مجموعة الإيصال نفسها، حتى لو كانت خارج صفحة المجموعات الحالية.

إشارات الإبطال تخص العمليات المارة بالخادم المحلي؛ التغييرات الإدارية خارج هذه القناة/توصيل إشعارات حي معتمد غير منفذة. لا يثبت هذا PostgREST أو auth أو Realtime على Supabase أو كشفًا فوريًا لتغيير خارجي غير موصول. أي نقل مستقبلي يجب أن يثبت هذه الحدود قبل التشغيل؛ نجاح المحلي لا يفتح المسار الحي. الحجم محدود20صفًا لكل قائمة؛ القراءة المركبة حتى6RPCs دون مسح صفحات كاملة. السقوف العالمية والأداء/انتظار القفل غير مقاسة.

| RPC | العقد |
|---|---|
| draft_save_v1(group,id,revision,document,refs) | كاتب المجموعة الحالي فقط؛ جديد revision=0، والتعديل يحتاج revision الحالي؛ رفض تبديل track أو خلط mixed/full-practical. يعيد revision+1 ومستندًا خاصًا، لا publication |
| draft_page_v1(group,id,after,limit) | id محدد يعيد مستند الكاتب وحده، والقائمة metadata فقط؛ لا قراءة لطالب أو مشرف آخر |

الـdocument شكل مستقل مضبوط عن RPC: schemaVersion/id/revision/track/name/policy/items؛ track صريح في الخدمة. الـfixture القديم بلا track يحتاج mapping إلى mixed عند الربط، ولا يُفسر سكوتًا داخل القاعدة. refs قائمة key/revision من سجل خادمي خاص حالي وفعال؛ partId يطابق مرجع جزء، وcaseRef/evaluatorVersion يطابقان مرجع full-practical. سجل المراجع فارغ افتراضيًا ولا يُملأ من بيانات يرسلها المتصفح. أي تجهيز لاحق له يجب أن يشتق المراجع من السجل القائم ويثبت case/evaluator/rule؛ ليس إضافة فحص أو محتوى أو مراجعة طبية.

المسودات تسمح نقص الحقول التحريرية، وتتحقق من الشكل والفصل والحجم والمراجع، وليست بديلًا لـdraftIssues أو validateMixedContent/validatePracticalContent والتحقق الطبي. الحفظ يثبت نسخة خاصة وبصمتها؛ البصمة تشمل document وrefs بـJSONB في PostgreSQL، ولا تستخدم JSON.stringify من المتصفح لمقارنتها. سقوف الدفعة:5مسودات/كاتب،100revision/مسودة،200بند و128KiB/مستند،50خيارًا. النسخ التاريخية يمكن أن تستهلك نحو64MiB/كاتب عند الحدود القصوى قبل overhead؛ هذا ليس ميزانية قبول FREE. لا تشغيل حقيقي أو رفع تلك الحدود قبل قياس السعة ومراجعة سياسة تنظيف النسخ وحفظ روابط الإسناد؛ لا عامل تنظيف في هذه الدفعة.

لا API متصفح لإنشاء publication للمشرف أو كتابة authoring_publication_links، ولا grant للعامل عليها. الجسر الداخلي المحلي موضح أدناه؛ ويجب أن أن يقرأ النسخة الخاصة، يتحقق من المصدر والترخيص والمراجعات المطلوبة وO108 والمقياس والمصحح والحالة والإصدارات، ويثبت المحتوى بالقنوات القائمة، ثم يربط version_id بالـdraft/revision/digest نفسه. حقول authoring لا تصنع ContentReview ولا reviewedBy. بدون الجسر والمراجعات والنسخة installed/available الموجودة فعلًا، prepare/confirm مرفوضان. اختبارات النطاق تملأ ربطًا اصطناعيًا عبر مدير PostgreSQL المعزول؛ لا تثبت نجاح ناشر أو مراجعة سريرية.

## ربط P2 المحلي وحدوده

[sql-adapter](../src/features/authoring-review/sql-adapter.ts) يعيد استخدام ScopeTransport في P1، بهوية واحدة يثبتها خادم الاختبار؛ actorId فحص محلي فقط ولا يمر إلى RPC. قوائم المجموعات والمسودات UUID keyset بصفحة20. قائمة المسودات metadata فقط، والفتح يعيد مستند الكاتب الخاص من draft_page_v1؛ الحفظ عبر draft_save_v1 دون مخزن آخر. يحتفظ adapter بمؤشر صفحة المجموعات الحالية فقط (≤20)، ويعيد تفويض المجموعة من صفحتها قبل/بعد قراءة المسودة أو حفظها. لا مسح لكل الصفحات، ولا استنتاج صلاحية من fixture. تغير جيل المجموعة/الإبطال يرفض تركيب الرد؛ الساعة الخادمية تخصم زمن النقل والانتظار محافظًا. RPCs منفصلة قصيرة، لا لقطة ذرية مركبة مخترعة.

الـDTO القديم بلا track يتحول إلى mixed صريح فقط. refs تستخرج من مفاتيح البنود مع revision المثبتة التي يزودها المضيف؛ SQL يطابق سجل المراجع الخاص المستقل. تهيئة مراجع حاضنة الاختبار مشتقة من كتالوج الحالات والأجزاء القائم داخل PostgreSQL المعزول فقط، دون مصدر/ترخيص/اعتماد طبي/reviewedBy أو تعبئة سجل تشغيل من المتصفح. --unconfigured يبقي السجل فارغًا؛ المسودة الفارغة/MCQ البنيوية تبقى مسموحة، والبنود ذات المراجع غير المهيأة مرفوضة. لا تغيير SQL أو بصماته بهذه الدفعة.

تعارض revision لا يكتب فوق الأحدث: يحتفظ المحرر بنسخته الخاصة، ويوقف إجراءات التحرير حتى تحقق صريح. فشل النقل أو إلغاء إجراء معلّق لا يعيد mutation؛ قد يكون COMMIT حصل دون ACK. «التحقق من النسخة المخزنة» يقرأ القائمة ثم الهوية نفسها؛ يعرض النسختين للمقارنة فقط بعد إعادة تفويض النطاق. «تحرير المسودة المتحقق منها» يبدأ من آخر نسخة خادمية ويحفظ نسخة المستخدم السابقة للمراجعة اليدوية؛ لا rebase آلي أو تبديل track. الحفظ والعودة إلى القائمة يبقيان معطلين حتى إجراء صريح يحذف النسخة المحلية المحتفظ بها ويغلق المقارنة، بعد نقل ما يلزم يدويًا إلى المحرر. إذا لم توجد الهوية المخزنة، تعود نفس المسودة ذات revision=0 لحفظ صريح لاحق. أي حفظ آخر ما زال يخضع لفحص revision الحالي في SQL. النسخة المحتفظ بها في ذاكرة الجلسة فقط وليست مخزنًا موازيًا؛ إعادة تحميل/إغلاق الجلسة تفقدها، وفقد النطاق/انتهاء المجموعة يمحوها عمدًا مع المستند والمعاينة والقوائم والردود المتأخرة.

إبطال P1 المحلي عبر SSE بلا بيانات مستخدم يعاد استخدامه لتغييرات النطاق فقط؛ حفظ المسودة في تبويب آخر لا يمحو تعديل المستخدم، بل يكشفه فحص revision. فقد القناة يمسح العرض؛ لا subscribe/poll حي أو Supabase. التغييرات الإدارية خارج الخادم المحلي لا تملك قناة إبطال مثبتة؛ يجب إثبات النقل والمصادقة والإشعارات الحية قبل التشغيل. سياسة المشاركة v2 وقبول الذات مجهزان محليًا كما في التقرير الموحد؛ سجل التشغيل والجسر التشغيلي غير مهيأين، ولا قبول مشاركة من واجهة P2. المسار الافتراضي يبقي أزرار تجهيز/تأكيد الإسناد مخفية وRPCs الخاصة بها مرفوضة. خيار --assignments المحلي الصريح يربطها مع الإغلاق على عينة مراجعة مثبتة مسبقًا كما أدناه؛ لا publication channel للمشرف أو worker.

المعاينة تعيد استخدام StudentPreview والإسقاط whitelist القائمين فقط. لا Draft أو refs أو مفاتيح إجابة/ملاحظات مؤلف/بيانات تصحيح خاصة تدخل العرض. [تقرير P2](archive/RAD-085_P2_SQL_REPORT_2026-10-26.md) يميز القبول المحلي الاصطناعي عن المراجعة الطبية والهاتف والتشغيل.

## الجسر الداخلي والإسناد والإغلاق محليًا

[تقرير الجسر السابق](archive/RAD-085_ASSIGNMENT_BRIDGE_REPORT_2026-10-26.md) يفصل إذن دفعته وتغطيتها. [التدقيق الجديد](archive/RAD-085_SECURITY_AUDIT_2026-10-26.md) يضيف الاستثناء المسمى للأول والثالث وبصمتيهما فقط؛ لا توقعات قديمة أو requiredMigrations/checks أو شهادات أو ملفات ترحيل تاريخية تغيرت. استُبدل تعريف content_submit_v1 داخل المصدر المحلي بفرع داخلي مقيد؛ المسار العادي بقي owner-only. لا ناشر موازٍ أو تغيير لدور profile أو grants العامل.

| content_submit_v1(document) | القناة القائمة؛ الفرع الداخلي يشترط role=assess_authoring_bridge والحزمة الخاصة المطابقة للكاتب وrevision الحالية؛ المستخدم العادي يبقى owner-only |

assess_authoring_bridge دور NOLOGIN/NOINHERIT بلا عضوية للمستخدم/العامل، وخمس منح EXECUTE فقط كما في الجدول، ولا جداول. authoring_reviewed_packages جدول RLS خاص فارغ افتراضيًا، لا يكتب فيه المتصفح أو هذا الدور أو العامل؛ تهيئة مستقلة موثوقة لاحقة مطلوبة. الحزمة≤128KiB JSONB/text وواحدة لكل revision؛ مع سقوف المسودات قد تضيف64MiB/كاتب قبل overhead عند الحدود القصوى. الحزمة تتبع حذف revision الخاصة عبر ON DELETE CASCADE في المفتاح الجديد فقط؛ لا تغيير FK قديم أو حذف منشور. لا قياس سعة أو سياسة تنظيف/احتفاظ مثبتة من ذلك.

server-authoring-bridge يقارن snapshot وحزمة مراجعة تغطي digest الخادمي نفسه، ثم metadata والسياسة والبنود والمراجع والإصدارات والنقاط والمفاتيح، ويستعمل validateMixedContent/validatePracticalContent وinstallMixedContent/installPracticalContent القائمتين. حقول المؤلف لا تولد ContentReview. المنفذ PostgreSQL يثبت الهوية والمجموعة لدى المضيف، ولا يقبل actor أو digest في publish، ولا يحمل URL/ENV أو route منتجًا أو credentials. المخزن المفقود أو الحزمة القديمة يرفضان؛ لا موافقة طبية أو مصدر أو ترخيص مخترع.

قراءة snapshot والمرشح والتثبيت والربط معاملة READ COMMITTED واحدة. خطأ أي مرحلة يرجع المرشح والتثبيت والربط معًا. receipt قراءة مفوضة تنتهي rollback بلا mutation؛ بعد ACK مفقود لا إعادة تلقائية. replay صريح بعد التحقق يعيد النسخة المرتبطة نفسها، دون مرشح/نشر آخر. auth/نقل/LOGIN حي وربط الإبطال ومخزن المراجعة التشغيلي غير مهيأة.

createSqlAuthoring بمعامل opt-in رابع=true يربط prepare/targets/confirm وassignments/close بالـRPCs القائمة، دون زر نشر للمتصفح. prepare يحتفظ بمعرف operation عند ACK مفقود لإعادة الطلب الصريحة نفسها؛ أسماء المسودة والمجموعة من SQL. المستهدفون id/name فقط، بلا joinedAt مخترع. الانتهاء من serverNow ناقص زمن النقل وبساعة رتيبة؛ reviews≤20 وعمليات تجهيز غير محسومة≤5 في adapter، يمحوها إبطال النطاق.

assignment_page_v2 محدود20 مع closed_at؛ الإغلاق باختيار وتأكيد صريح وrevision. الخطأ يمحو القائمة ويفرض قراءة صريحة؛ لا إعادة mutation آلية أو إنهاء مجموعة أو سحب targets أو حذف نتائج. فشل التأكيد يتيح قراءة الإسنادات للمصالحة؛ SQL تفرض replay المفوضة وunique الإسناد المفتوح. إبطال SSE وepoch/AbortSignal محلي فقط؛ لا إثبات provider/Realtime.

حاضنة P2 مع --assignments تهيئ سياسة/قبولًا وعضوية ومحتوى حروف وحزمة مراجعة هندسية SYNTHETIC داخل PostgreSQL واحد، ثم الجسر الحقيقي إلى المرشح والتثبيت والربط، فالتجهيز والتأكيد والإغلاق. لا seed للمرشح أو الرابط في هذه الدورة. اختبارات الجسر المتكاملة تغطي mixed مع جزء محاكي قائم وfull-practical والإصدارات والرفض والتكرار والتنافس وrollback وACK. P1 وP2 الافتراضية تبقيان مستقلتين؛ دليل التكامل هو الاختبار الجديد، لا جمع نجاحهما. لا مراجعة طبية أو خدمة حية أو هاتف من ذلك.


## هوية الاتصال والإبطال المحليان

[تقرير هوية الاتصال](archive/RAD-085_CONNECTION_IDENTITY_2026-10-26.md) يضيف bridgeSessionHost خاصًا فوق منفذ PostgreSQL نفسه دون تغيير SQL أو بصماته. هوية الخدمة LOGIN/NOINHERIT في fixture فقط؛ هوية المستخدم والمجموعة من BridgeAuthenticator موثوق محقون، والدور الداخلي assess_authoring_bridge يستعمل SET LOCAL ROLE وخمس القدرات القائمة. publish/receipt لا يقبلان actor/group من الطلب. verifier الصناعي ليس إثبات Supabase Auth/TLS أو pooler حي، وحماية المضيف وcredential الخدمة جزء من حد الثقة.

إعادة تحقق الهوية حول العمليات وبعد الأقفال وعند التسليم؛ إعادة authoring_bridge_read_v1 قبل إنهاء المعاملة تعيد الوقت/النطاق حتى في المصالحة. revoke/close يبطلان capability نهائيًا ويقطعان الاتصال النشط ويشعران المشتركين؛ منع جلسة جديدة يعتمد أيضًا على تحديث مصدر المصادقة الموثوق. disconnect فقد القناة يغلق المضيف وpool الخاص؛ التعافي بمضيف ومصادقة جديدين. NOLOGIN وحدها تمنع الجديد ولا تقطع المفتوح. تغييرات SQL خارج القناة تتسلسل بالأقفال ولا يضمن لها إبطال فوري.

ROLLBACK وDISCARD ALL قبل/بعد إعارة اتصال pg pool، وتدميره عند الإبطال/تعذر التنظيف؛ لا retry كتابة. فقد ACK أو الإبطال بعد COMMIT قد يتركان كتابة ملتزمة مع رد محجوب، والمصالحة receipt قراءة مفوضة فقط دون نشر/إسناد تلقائي. ناقل P2 يمحو cursors ورموز المراجعة وpending، ويرفض نجاحًا أو خطأ متأخرًا؛ الواجهة تمحو العرض ونسختي الاستعادة بالإشعار القائم. اختبارات pool بحجم1 تثبت إعادة الاستخدام المحلي فقط، لا reset/cancel عند المزوّد.

شواهد انتهاء الجسر بعد reference/advisory/version locks وحذف العضوية المتسلسل أصبحت مسار CI مطلوبًا قابلًا للتكرار، مع المصدر السابق المثبت والمصحح، دون dump tools أو skip. اختبار النسخ الكامل التاريخي مستقل وباقٍ؛ CI لا تعني تشغيله. المحو والاحتفاظ بالروابط والمراجعات ونسخ القاعدة يظلان عائقًا؛ لا تنظيف تشغيل أو CASCADE جديد.

المراجعات والأمن والمزوّد والاحتفاظ التشغيلي وحالة الكاتب المحجوبة باقية؛ لا إغلاق عائق التشغيل من نجاح الشاهد المحلي. لا عامل أو ناشر موازٍ أو تغيير درجات/إصدارات/سياسة مشاركة/موافقة فعلية.
