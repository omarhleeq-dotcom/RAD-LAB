## بروتوكول الانقطاع والتزامن v1

هذه مواصفة C وليست تنفيذ lifecycle في A:

1. البدء المعتمد يحجز المحاولة ضمن الحد بإجراء ذري على user/assignment. يعيد الخادم نفس المحاولة النشطة. policy/order/versions ووقت البدء تثبت مرة واحدة. الوقت UTC؛ `deadline = started_at + duration`، وnull تعني غير مؤقت. الساعة المحلية للعرض فقط.
2. كل save/expose/submit يحمل operationId فريدًا وexpectedRevision. يقفل الخادم صف المحاولة، ويفحص الاعتماد والإسناد، ثم يبحث إيصال العملية قبل فحص المهلة أو revision. إعادة نفس العملية ونفس body تعيد الإيصال نفسه حتى بعد انتهاء المهلة؛ نفس المعرف بمحتوى مختلف مرفوض. حفظ digest آمن مؤقت للمقارنة، لا body داخل logs.
3. العملية الجديدة تقبل فقط إذا active و`server_now < deadline`؛ المساواة متأخرة. revision غير مطابق يعيد conflict وحالة آمنة؛ لا last-write-wins بين نافذتين. الواجهة تسلسل العمليات، وتوقف العمليات التابعة عند conflict بدل إعادة كتابة جواب أقدم تلقائيًا. retry لنفس الطلب يحتفظ بالمعرف والنسخة؛ تعديل المحتوى يحتاج عملية جديدة بعد المصالحة.
4. pending محلي ليس نجاح حفظ. ack بعد transaction هو الدليل؛ بعد timeout تُقرأ الحالة ثم يعاد **نفس** الطلب. أثناء offline لا تعريض موثوق ولا وعد بقبول جواب بناء على ساعة الجهاز. العودة تستأنف نفس المحاولة من آخر ack، والوقت يستمر. التنبيه قبل التسليم اليدوي يحسب غير المحلول، دون كشف تصحيح.
5. expose يقفل البند ويحفظ لقطة إجابته في نفس المعاملة. قفل واحد لكل attempt/item؛ عملية ثانية بمعرف جديد ترفض، وإعادة القديمة تعيد الإيصال. لا تغيير letter يحرك markerPosition ثابتًا، ولا إعادة ضبط عبر refresh. save لبند مقفل يرفض؛ التنقل إليه يبقى ممكنًا.
6. submit أو expiry يثبتان submittedAt مرة واحدة ويجمدان المحفوظ ويمرران محاولة إلى grading. expiry يستخدم deadline نفسه وقت تسليم منطقيًا، حتى لو تأخر العامل أو أغلق المتصفح. المحفوظ غير المحلول صفر؛ جواب لم يصل في الوقت لا يدخل التصحيح. idempotency/قفل الصف يمنعان سباق العامل والتسليم اليدوي.
7. عامل التصحيح يقرأ النسخ الخاصة المثبتة ويحسب خارج المتصفح؛ لا يقبل درجة أو definition أو rubric يرسلها الطالب. finalize يتحقق من revision/token المجمد ويثبت FinalResult ويحذف **كل** المؤقت ومفاتيح snapshot/الأجوبة/إيصالات body digests في معاملة واحدة. لا حالة نجاح جزئية. تُستبقى فقط metadata دنيا لازمة لعدم إنشاء نتيجة ثانية، دون answers/checks.
8. فشل التصحيح لا يعطي صفرًا أو نجاحًا، ولا يعيد التعريض أو يسمح بتعديل المجمد. يبقى grading-failed مع نفس snapshot لإعادة التصحيح. الاختيار التشغيلي v1: retries حتى24ساعة وتنبيه المالك، ثم نافذة استرداد حتى7أيام من submittedAt؛ بعد ذلك void دون علامة مع حذف التفاصيل. الحجز لا يُفرج تلقائيًا لمنع تجاوز حد المحاولات؛ معالجة الحد تكون تعديلًا صريحًا للإسناد. هذه مدد تشغيل قابلة للتهيئة قبل الإطلاق مع O106، وليست ادعاء تنفيذ عامل أو تنبيه.

الإلغاء الصريح للمحاولة غير المؤقتة يحذف تفاصيلها؛ لا يُخترع انتهاء بسبب inactivity يعارض الاستكمال. يجب قبل التخزين التجريبي حسم حد الاحتفاظ بالمحاولات غير المؤقتة التي لا يلغيها المستخدم وإفصاحه في الموافقة (O106). لا تشغيل لتلك الحالة قبل الحسم. اختبارات السباقات/المعاملات والشبكة والـack المفقود وفشل finalize وحذف التفاصيل تقع في C، لا تثبتها الدوال النقية الحالية.

## الكسور والدرجات والحفظ

- نقاط القالب/المعيار نص decimal موجب عند النشر؛ الدوال تدعم صفرًا لغير المحلول. حتى6 منازل و9 أرقام صحيحة في v1 كحد سلامة تشغيلي. fractions ذات بسط/مقام صحيحين، بلا floating point؛ نجمع نقاط المعايير المحددة، ونحوّل للسلم النهائي مرة واحدة. لا تقريب لإجمالي Practice ثم قصه للجزء. القيم غير المحدودة/السالبة والمقام0 وcredit خارج0..1 مرفوضة.
- `earnedPoints` يجمع فقط المعايير المرسلة من rubric الخادم؛ عدم الحل له credit0. تعريف اختيار تلك المعايير والتأكد أن مجموع itemMarks يطابق السلم وأن المراجع تنتمي لنفس publication وفك JSON وعدد/أحجام الحقول من مسؤولية خدمة النشر في C. لا يدّعي validator العام تنفيذ ذلك.
- FinalResult يحفظ **العلامة النهائية الدقيقة** بسطًا ومقامًا نصيين ومجموعها decimal، دون تفاصيل البنود. العرض عشري بمنزلتين وhalf-up عند العرض وحده. لا خسارة الكسور المخزنة ولا pass threshold جديد. كامل الفحص يعيد rubric وcritical gates الأصليين؛ لا يختزل gate إلى خصم نقاط أو يعيد توزيع الأوزان.
- ستة **أشهر تقويمية** من submittedAt في UTC، مع تثبيت وقت اليوم وclamp لآخر يوم في الشهر الهدف؛ ليست180يومًا. expiry شامل (`now >= expiresAt`): تمنع القراءة فورًا حتى لو تأخر purge. النشاط وتغيير الاسم/القالب لا يمددانها. الاختبارات تشمل فبراير والسنة الكبيسة ونهاية السنة.
- job الحذف الفعلي والموافقة وسجل حذف أدنى ومراقبة فشل العامل وإعادة تطبيق الحذف بعد restore في C/F وO106. لا حذف أو اتصال إنتاج في A؛ موافقة Practice لا تُعد موافقة Assess.

## خريطة rule → part ومراجعة O108

المرجع التنفيذي [rule-parts.ts](../src/features/assess/rule-parts.ts) يجرد أنواع القواعد الحالية، ولا يمنح عرضًا أو إذن تعديل أو يعتمد سؤالًا طبيًا:

| القاعدة | الجزء ومدخلاته | حد إعادة الاستخدام |
|---|---|---|
| equals / range | setting المعلن نفسه، بما فيه choices.id وSID | credit القاعدة الأصلي بعد فحص انتمائها إلى النسخة؛ optional غير المعلن لا يُستحدث |
| centering | محور x أو y من centralRay | معيار لكل محور، لا بقية الفحص |
| coverage | clipping أو excess؛ centralRay/collimation | الخلفية/التغطية والاعتماد المتبادل تحتاج مراجعة لكل سؤال |
| technique.kvp-band | kvp فقط | لا exposure-adequacy أو gates إضافية |
| بقية technique | adequacy/dose/aec؛ مجموعة اعتماد محافظة من kVp/mAs/SID/projection/mode/chambers/centralRay/collimation | projection يغير التوهين ومجال الضوء يؤثر على AEC؛ applicability بحسب mode/case، ولا افتراض منح صفر لقاعدة محذوفة في manual |
| marker | side مستقل عن placement | **محظور إعادة استخدام combined credit**؛ كلا الجزأين يحتاج adapter مراجع. anatomical/detector-side يعتمد أحيانًا على position/choices، وfixed-side على letter فقط؛ لا إزالة الاعتماد باسم الفصل |

كل بند جزئي يثبت mutablePaths، حالة خلفية كاملة مراجعة، presentation allowlists ومعايير ونقاطًا مستقلة. لا تُنسخ initialSettings على أنها صحيحة. SID لا يظهر باقي أدوات المحاكي، وletter-only لا يغير موضعًا ثابتًا؛ تنفيذ العرض والمصحح في C/D. لا بوابات حرجة خارج الجزء. لا تعديل دالة evalMarker أو حسابات/بيانات التدريب لتحقيق هذه الخريطة.

**مخرج مراجعة النطاق:** لا سؤال Assess طبي جديد صالح للنشر في A. الجرد الحالي يستخدم البيانات القائمة لأغراض هندسية فقط؛ provisional/rubric وحدود الأسر وO5/O108 محفوظة. عينات single-choice في الاختبار أحرف اصطناعية بلا محتوى طبي. قبل أي سؤال منشور: مصدر/ترخيص موثق، reviewer مسمى ونطاق/تاريخ، صلاحية الخلفية والمعيار والدرجة والظهور الانتقائي، وفحص الاعتماد المتبادل للماركر. لا لجنة أو بنك أو عدد أسئلة معتمد تلقائيًا.

## إثبات runtime وحدود Scale

التجربة المختارة **Node24 محليًا**: عملية مستقلة بلا DOM/React/Next، تحمّل المحرك والبيانات القائمة وتصحح عينات محددة؛ تمنع loader استيراد React/Next/Zustand. [runtime.test.ts](../src/features/assess/runtime.test.ts) يقارن JSON كاملًا بين المسار الحالي وعملية Node، ثم يقارن نتائج سيناريوهات PA مع characterisation المحفوظ. لم يُعدّل engine أو توقع أو hash قديم. Loader خاص بالتجربة، ليس اعتمادًا لشحنه للإنتاج. stdin harness يقبل fixtures فقط وليس API مصادقة أو validator لإجابات طالب.

اختيار المزوّد/استضافة Node أو Edge، bundling للمزوّد، schedule للـexpiry/purge والأداء ما زال تحققًا قبل C؛ لا ادعاء توافق Supabase/Deno أو نشره. تكفي التجربة لإثبات قابلية التقييم النقي بالخادم محليًا، لا إثبات مزود حي. لا حاجة لإضافة endpoint إلى الواجهة الساكنة في A.

الحدود الافتراضية المقترحة: صفحة≤100، اختبار≤200بند، MCQ≤50خيارًا، أمر≤64KiB؛ [الثوابت](../src/features/assess/policies.ts) عقد لفحوص B/C وليست enforcement بخدمة موجودة. مستقبلًا تُطبق خادميًا قبل parsing/transaction وتُقاس قبل رفعها؛ harness محدود250عينة/2MB لأغراض الاختبار فقط. snapshots الطلاب هنا عقد منطقي، وسيخزن B صفوف targets بفهرس unique ومؤشرات paging بدل JSON ضخم أو تحميل كل الطلاب. إصدار shape ونوع صريحان؛ النوع غير المدعوم يرفض، والأنواع المقبلة تضيف validator/view/grader دون enum تخزين مغلق. لا دور مشرف أو ControlSpec شامل أو وعد Free/سعة من هذه التجربة.

## تنفيذ C اللاحق وحدود التشغيل

أذن المالك بـC بعد دمج #90. [تقرير C](ASSESS_C_REPORT_2026-10-20.md) و[ترحيل دورة المحاولة](../supabase/migrations/20261020000700_assess_lifecycle.sql) يحلّ محل وصف عدم التنفيذ أعلاه في نطاق الدليل المحلي فقط؛ تبقى فقرات A دليل مرحلتها، لا إذن إنتاج. start صار يحمل operationId مع reservation/tombstone محدودين، وإيصالات الأوامر تستخدم SHA-256 لـJSON القانوني. بعد التصحيح تُحذف الإيصالات: replay لـsave/expose قديم يرفض ويجب قراءة terminal state، وsubmit المعروف يعاد بmetadata دنيا بلا answers/digest. هذا توضيح بروتوكول تقني، لا تغيير لقرار استكمال المحاولة أو التعريض الواحد.

المصحح يثبت حالة/evaluator بإصدار ويتحقق من المسموح، ويعيد بناء الخلفية الخاصة. adapter الماركر يفصل predicates الجانب والموضع هندسيًا، لكن الخلفية والنقاط الثنائية والمراجع لكل سؤال لا تصبح مراجعة طبية. الفحص الكامل يحفظ دلالة بوابة critical بلا تغيير رقمه؛ لا يضيف حقل pass للسجل. result API whitelist وحجب العلامة والحذف الذري وUTC calendar expiry وlease/recovery مثبتة باختبارات محلية، لا خدمة منشورة. مجموع itemMarks هو مقياس خام يتحول مرة واحدة إلى maximum النهائي المحدد بالقالب؛ لا تقريب وسيط.

سقوف C التشغيلية الإضافية: duration مؤقت≤7أيام، maxAttempts≤1000،20ألف إيصال حفظ/تعريض لكل محاولة و20ألف عملية بدء لكل حجز، lease5دقائق، batch≤100. رفعها يحتاج قياسًا، ولا يمثل حد منتج دائمًا. launch_gate مغلقة افتراضيًا؛ لا worker/user RPC يفتحها. غير المؤقت محجوب عند البدء حتى حسم O106. دور assess_worker بلا login ولا منح جداول، وربطه بمزود/جدولة ومراقبة وموافقة ونشر مستقل لم يُنفّذ. لا نسخ بيانات طلاب إلى أداة rehearsal المحلية.
