## 2. المنجز والمستبعد

### حزمة التركيب المغلق

المولد يعمل فقط على قواعد PGlite جديدة من migrations المستودع، ولا يقبل URL أو إعداد مزود. ينتج مجلدًا مؤقتًا فيه preinstall.sql وinstall.sql وpostinstall.sql وreference.json وSHA256SUMS؛ لا يطبق أيًا منها. reference يحفظ البصمات المرجعية وSHA256 لمصدر SQL وعقد catalogue؛ SHA256SUMS يثبت ملفات الحزمة كاملة. لا تعديل لملف trial-isolation.sql السابق أو إعادة بناء حمايته.

catalogue يقارن توقيع كل دالة Assess ودوال public التطبيقية الأصلية، وبصمة prosrc وتعريف الدالة كاملًا، والمالك وSECURITY DEFINER وsearch_path واللغة وACL، وجداول Assess وأعمدتها/column ACL وRLS والسياسات والقيود وACL الفعلية للأدوار الثلاثة وtriggers المرتبة بالاسم مع التعريف وحالة التمكين. وظائف public الإضافية للامتدادات مسموحة، لكن إضافات Assess أو فقد دالة تطبيقية أو trigger إضافي/معطل/معاد التسمية تتوقف. لا يجمع أجوبة أو علامات أو هويات مشاركين. لا اعتماد لبصمة مرصودة من المزود لتجاوز اختلاف.

الأجسام تقبل بديلَي bytes محددين لكل دالة من تطبيق migrations المحلية بنهايات LF أو CRLF كما في آلية الشواهد السابقة؛ تقبل اختلاف نهايات migrations فيما بينها، دون normalization أو قبول whitespace/تغيير منطق أو CR منفرد. هذا عقد مرجعي مراجع محليًا، وليس إثبات مطابقة الأصلية. أسماء المالك/ACL والتنسيق الذي ترجعه نسخة PostgreSQL قد يختلف عند المزود: يتوقف الفحص للمراجعة ولا يُحدّث المرجع تلقائيًا.

preinstall للقراءة فقط ثم ROLLBACK. install يأخذ ACCESS EXCLUSIVE NOWAIT على مصادر حماية Assess الخمسة عشر، ويعيد فحص baseline داخل **معاملة READ COMMITTED نفسها** قبل DDL، ثم يفحص catalogue النهائية وغياب أي صف نطاق والبوابة والحساب قبل COMMIT. بعد COMMIT يبدأ معاملة تحقق مستقلة تحت الأقفال ويخرج PASS بعدها فقط؛ لا SELECT PASS غير مشروط بعد COMMIT قد يخفي ROLLBACK. postinstall يعيد التحقق بأقفال ثم ROLLBACK. المهلات lock2s/statement15s؛ الفشل أو الغموض يمنع إعادة التنفيذ العمياء. لا repair/reinstall/drop/grant أو إعادة فتح ضمن الحزمة.

تشترط الحزمة postgres الفعلي session_user/current_user، وdefault/current READ COMMITTED وsession_replication_role=origin، وبوابة ذات صف واحد مغلق، وassess_job_a مع NOLOGIN وexpiry ماضٍ وصفر backend للدور وNOINHERIT وعضوية assess_worker وحدها بلا admin option/قدرات إدارية. assess_worker نفسه NOLOGIN/NOINHERIT وبلا قدرات إدارية أو عضويات في أدوار أخرى. فحص الإغلاق هنا جزء من postcondition لتركيب جديد مأذون لاحقًا، لا أمر إعادة probe أو جرد الشاهد السابق الآن. لا تغير الحزمة LOGIN/expiry أو البوابة بنفسها.

لا تثبت هذه الجلسة إعداد PostgREST أو جميع العملاء؛ اختبار المزود ضمن نافذة تركيب مستقلة لازم قبل تطبيق فعلي. triggers القائمة ترفض أي كتابة Assess بغير READ COMMITTED حتى dormant؛ يظل ذلك أثر توافق حقيقيًا. حجر الإدارة/DDL خلال النافذة لازم؛ يمكن للإداري تعطيل أي حارس، ولا تحمي مطابقة snapshot من تعديل لاحق خارج الأقفال.

### حزمة العامل المقيد

build-trial ينتج trial.mjs وDockerfile وmanifest.json في مجلد محلي منفصل؛ لا Docker build أو push أو Job update. الصورة المرجعية Node24 المثبتة ببصمة السابقة، مستخدم node، ولا نسخ checkout أو secrets. manifest يسجل hashes للملف التنفيذي وDockerfile ومسار الاستيرادات وأسماء RPC الخمس وحد1. الحارس الافتراضي ASSESS_TRIAL_ENABLED=0؛ ليس ASSESS_JOB_ENABLED العام. لا job-main أو trial-tools في مسار البناء، ولا تثبيت محتوى أو إغلاق إسناد ضمن tick.

بعد إذن مستقل فقط، يحتاج المدخل بلا argv إلى حارس1 وملف نطاق منفصل `/run/config/assess-trial.json` بعقد `assess-trial-scope/1` وUUID تحت `trial`، ثم ملف السر القائم `/run/secrets/assess-worker.json`. قراءة bounded64KiB ورفض symlink/ملف غير عادي؛ UUID والعقد/الحقول تتحقق قبل قراءة السر. لا سر جديد أو ENV/URL fallback. يستخدم executeTrialJob/scopedTrialWorker القائمين: maintain/claim/finish/fail/health المقيدة فقط بـp_trial، وحد معالجة1 واتصال1 وTLS/هوية النقل القائمة. غياب الحماية/النطاق يوقف قبل الرجوع لأي RPC عامة.

SIGTERM/SIGINT يوقفان الأعمال الجديدة وينتظران دورة النقل وإغلاقه، مع إزالة handlers؛ code130 للإيقاف وcleanup_failed مستقل. لا loop أو scheduler أو retry تلقائي. أخطاء/claims/config لا تطبع؛ التقرير whitelist وأعداد مؤكدة فقط. غموض finish/COMMIT يبقى STOP/lease للمصالحة، لا صفر مصطنع أو replay. يظل SQL role ذا قدراته العامة السابقة؛ هذه الحزمة تقيد المسار التنفيذي ولا تحول الحساب إلى tick-only. الصورة العامة القائمة لا تستعمل لهذه التجربة. ضبط Cloud Run لاحقًا taskCount1/parallelism1/maxRetries0، ومنع executions يدوية متداخلة ومراقبتها، شروط تشغيل لم تُطبق هنا.

### الهويات وموافقة v2 والمحتوى

الطريقة المحددة للتحقق لاحقًا هي ثلاث جلسات Auth حقيقية منفصلة في ملفات متصفح مستقلة، على أصل واجهة موثوق مطابق للمراجعة؛ لا private keys في المتصفح. يبدأ كل شخص بـAuth getUser لدى المشروع، ثم قراءة ملفه من public.profiles وفق RLS: مالك approved/owner وطالبان approved/participant وثلاثة UUID مختلفة. لا يكفي decode JWT أو getSession المحلي أو عد الموافقتين. تُطابق المعرفات داخليًا مع controller المقترح وإسنادَي A فقط، ويبقى B خارج targets. لا UUID أو بريد أو tokens في التقرير العام؛ يحتفظ المالك بربط الهويات في سجل خاص محدود.

الأدوار/الاعتماد ليست عمليات تنفذها هذه الدفعة. إذا غاب أي حساب مخصص أو اعتماده، يتوقف التحضير الحي لإذن إنشائه/اعتماده منفصلًا؛ لا افتراض وجوده أو تسوية الأدوار آليًا. لا تُعتمد هويات اعتمادًا على الأسماء أو participant code وحده. المنصة تقرأ ملف المستخدم بالفعل، لكن شاهد Auth getUser ومطابقته للملف خطوة قبول مستقبلية مستقلة، لا ادعاء إضافة تحقق جديد إلى واجهة المنتج هنا.

موافقة Assess هي `assess-pilot-2026-10-20-v2` المستقلة في AssessConsent، لا موافقة الحساب ولا v1. قبل قبولها يختبر A رفض البدء؛ ثم يقرأ النص الحالي بنفسه ويختار القبول بحسابه، وبعده يختبر البدء الفعلي تحت شروطه. يقبل B لنفسه فقط إذا كانت مقارنة رفض غير المسند تتطلب فصل سبب عدم الإسناد عن عدم الموافقة. لا backfill/قبول نيابة عن أحد أو تعديل لسجلّي الموافقة السابقين. لا موافقة أو بداية حية في هذه الدفعة.

trialFixture مصنع خامل يعيد وثيقة mixed/schema1؛ لا اتصال أو نشر أو IDs حية أو stdout. السؤالان: «اختر A» و«اختر B»، خيارا A/B، خمس نقاط لكل سؤال. visible:300ثانية/after-submission؛ hidden:120ثانية/hidden؛ محاولة1 لكل نسخة. المصدر نص هندسي أصلي، وreview.scope وreviewedBy يصرحان بعدم وجود مراجعة طبية، دون اختراع مراجع طبي. المفتاح الخاص محصور بمسار التأليف trusted؛ لا تعطيه للطالب أو ترفعه ضمن الواجهة. A في السؤالين يعطي صحيحًا ثم خاطئًا=5/10؛ A في الأول والثاني غير مجاب=5/10 للمهلة. النشر المؤقت والحذف الذري والأعمار تُفرض بالعقد الحالي، لا حذف يدوي لتسريع تنظيف التجربة.

الإنشاء والإسناد لاحقًا بهوية المالك وعبر content_submit_v1 وassign_v1 القائمتين؛ تثبيت كل UUID مرشح مرة بواسطة [installOneMixed](../scripts/assess/trial-tools.ts)، وإغلاق كل UUID إسناد بواسطة closeOneAssignment القائمة التي تتحقق بـAuth getUser ثم close_assignment_v1 وصلاحيات المالك. لا أدوات بديلة أو auth.uid مصطنع. أداة الإغلاق تقبل ملف owner مؤقت0600 أو تحميلًا من الذاكرة في المكتبة؛ تدفق تهيئة جلسته ونقلها محليًا وتنظيفها يحتاج مراجعة عملية قبل النافذة، ولم ينفذ أو يثبت هنا. لا طلب JWT/OTP/password في المحادثة أو argv/history، ولا نسخ جلسة مالك إلى صورة العامل أو سر العامل أو Git. إذا تعذر المسار الآمن المفوض يبقى التشغيل ممنوعًا؛ لا تعويضه بإدارة SQL.
