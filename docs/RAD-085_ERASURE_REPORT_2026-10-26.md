RAD-085 تبقى review/waiting_on owner، دون completion_evidence أو قبول مالك/هاتف. تحقق مسار المحو والمصالحة الصناعي المحدد، **ولم يغلق العائق التشغيلي**: مصدر دليل دائم كامل القنوات، مسؤول وصلاحياته وخزنته، ومزوّد/Auth/أسرار/exports، وحالة الكاتب المحجوبة والمراجعة المستقلة غير مثبتة. لا إغلاق RAD-060 أو RAD-063 أو O106/O108 من ذلك؛ بقية المهام محفوظة.

## 4. المشترك والذرية وScale

المشترك: finalise C2 يعاد تعريفه محليًا دون تغيير deactivate/restore/list أو نافذته/منعه النفس وآخر مالك؛ scope قبل table/profile ثم versions المرتبة. كل unlink وحذف أصل/CASCADE ضمن معاملة واحدة، وفشل أي خطوة/مهلة/guard يرجع الدفعة كلها. batch≤100 القائمة؛ هدف محجوب قد يمنع batch كلها، ولا نعيد ترتيب requested_at لتجاوزه. النتيجة المجهولة بعد COMMIT تحتاج قراءة تحقق صريحة، لا retry كتابة آليًا.

الإبطال والحجر والدليل الخارجي خارج ذرية PostgreSQL. النية تثبت على قرص صناعي مستقل قبل mutation، وpending يمنع head إلى تحقق الحالة؛ fsync/rename وملفات0600/مجلد0700 ومفتاح منفصل عن snapshot. لا مخزن تشغيلي أو تكامل تلقائي بقنوات الإدارة. بروتوكول المصالحة يتحقق من السلسلة بمرورين وصفحات1–100 ورأس أحدث موثوق، يعيد الآثار المقيدة idempotent، ويشترط maintenance والإبطال والتحقق النهائي. لا API لفتح الخدمة؛ الناتج synthetic-verified فقط.

Scale: معاينة تعيد مجاميع مقيّدة بالهدف لا مستندات، لكن counts وبعض فحوص source_group_ids وprovenance قد تفحص صفوفًا كثيرة؛ لا اختبار حمل أو latency/120مستخدمًا أو FREE. القفل العالمي القديم باقٍ ولا ترفع حدوده. الدليل الصناعي≤10000حدث و100نية؛ البروتوكول سقفه10000قابل للضبط، والتجاوز يرفض مغلقًا دون قطع السجل. لا مخزن JSON ضخم مقروء دفعة واحدة؛ ملفات أحداث وpayload بصفحات، metadata محدودة بالسقف. رفع الحدود أو التخزين التشغيلي يحتاج قياسًا ومراجعة. لا جدولة أو purge ثانٍ.

الشاهد المحلي PostgreSQL18.4 عبر sockets في cluster مؤقتة بلا TCP. CREATE DATABASE TEMPLATE يحفظ قاعدة قبل التعطيل والحذف وسحب القبول والتعيين، ثم يعيدها بعد الأثر إلى قاعدة أخرى؛ الدليل المكتوب على القرص ومفتاحه خارج الاثنين. ثبت أن البيانات/الصلاحيات تعود في النسخة القديمة قبل replay، ثم تغيب بعده، مع بقاء نتيجة طالب آخر وقفل الوصول. فقد ACK بعد حذف ملتزم يترك الأثر، ويكتمل بالاستئناف المقيد؛ missing/truncated/forged evidence أو فشل التطبيق/verification/maintenance/revocation أو رأس متغير يمنع الجاهزية.

هذه ليست تجربة pg_dump/globals القديمة أو إثبات نسخة مزوّد أو Auth/Storage/PITR أو تشفير نسخة تشغيلية أو RPO/RTO. الأدوار مشتركة في cluster، والإبطال/cache داخل شاهد الاستعادة بديل صناعي؛ الدليل الحقيقي للمضيف والمتصفح المحليين في [تقرير الاتصال](RAD-085_CONNECTION_IDENTITY_2026-10-26.md). لا اختبار هاتف/Windows/WSL أو hosted preview/tunnel. حالات group-end/member-leave/account-stop/assignment-close تختبر في بروتوكول التقييد؛ شاهد restore SQL الجديد يطبق الحذف وسحب المشاركة والتعيين تحديدًا، ولا يدعي تغطية مزوّد أو كل قناة إدارية.

واجه التجهيز غياب pg/binaries؛ نجح npm ci المقفل وsetup المعزول دون تغيير lock. أخطاء الإضافة الأولى: fixture دون موافقة Assessv2 وأسماء aliases تصادمت مع p/d في الإجراء القديم؛ صُححت الإضافة وحدها. محاولة متزامنة مع tsc تعرضت لمهلات fixture/initdb؛ نجح تشغيل المستهدف منفردًا دون رفع مهلات أو skip. tsc مباشر قبل next typegen أظهر routes قديمة؛ الفحص الرسمي typecheck هو المعتمد. توسعة عينة survey واجهت خطأ اقتباس JSON في الاختبار الجديد؛ استبدلت قيمة بمعامل SQL قبل إعادة الفحص. بعد ذلك ظهرت مهلة hand-rotation في التشغيل الكامل، ثم نجح الملف مع اختبار المحو على الإعادة كما أعلاه؛ لا إخفاق مخفي أو تعديل توقع قديم.
