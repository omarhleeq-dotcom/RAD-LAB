# فحص الوثائق والحالة

فاحص مشترك محفوظ في المستودع لجميع الوكلاء والمراجعين وCI؛ لا خدمة أو اعتماد جديد، و`docs:check` لا يقرأ الشبكة. تعليمات العمل في [AGENTS](../AGENTS.md)، وتنظيم الحالة في [status-format](status-format.md).

## أوامر الفحص

```sh
npm run docs:check -- --base origin/main
npm run status:check -- --base origin/main --require-previous
git diff --check
```

حدّث مرجع main عبر وسيلة الوصول المعتمدة قبل المقارنة. `docs:check` دون `--base` يفحص الشجرة الحالية فقط ويصرّح بأن مقارنة معرّفات القرارات لم تُجرَ. المرجع المفقود/المقارنة المتعذرة يفشلان، ولا يتحولان بصمت إلى نجاح. الأداة تقرأ Markdown المتتبع والجديد غير المتجاهل من Git، وتستثني الملفات المحذوفة فعليًا؛ لا تفحص node_modules أو مجلدات بناء متجاهلة.

عند تعديل أدوات التوثيق نفسها:

```sh
npm run docs:test
npx eslint scripts/docs/*.mjs scripts/status/summary*.mjs
```

اختبارات Node المضافة تخص هذه الأدوات فقط؛ تختبر روابط وعناوين وجداول وبيانات سليمة ومعطوبة وحفظ المعرّفات ومرشحات العرض وعدم الكتابة. لا تُعدّل expectations أو fixtures/characterisation الخاصة بالمنتج.

عند تحرير DECISIONS أو سجل أدلة الاعتمادات، شغّل أيضًا اختبار الدليل القائم: `npx vitest run src/data/credits.test.ts`. هذا الاختبار يقرأ نص القرار الحالي؛ الفحص البنيوي لا يستبدله، ولا تُغيّر توقعاته لتمرير اختصار وثيقة.

## ما يُفحص

| المجال | الضمان البنيوي |
|---|---|
| Markdown | مسارات الروابط/الصور inline وreference-style وروابط HTML المحلية؛ headings من نوع ATX وexplicit anchors، وslugs مكررة/عربية؛ fences/comments مغلقة |
| الجداول | ترويسة وseparator فعّالان، عدد أعمدة متطابق، ورفض صفوف pipe يتيمة؛ مراعاة escaped pipes |
| source_ref | وجود المسارات النصية وإحالاتها، ومعرّفات D/S/O المذكورة؛ بادئة جلسة مثل S14.1c تُقبل فقط إن لها قرارات مسجلة |
| القرارات | عدم فقد معرّف من سجل المقارنة؛ السجل الحالي والتاريخي يُقرآن معًا، وتكرار لقطات التاريخ مسموح بينما تكرار تعريف حي مفرد يُرفض |
| التوافق | ملفات الإحالة الأربعة القديمة تقود إلى تقاريرها المؤرشفة |
| نقاط الدخول | AGENTS/CLAUDE/الفهرس/التسليم موجودة؛ CLAUDE إحالة قصيرة لا نسخة workflow؛ سقف HANDOFF وفحص JSON الحالي |

[الأداة](../scripts/docs/check-docs.mjs) تفحص البنية، لا تقارن نصوص السجل كلمة بكلمة؛ عند نقل/اختصار قواعد، أثبت حفظ النص/المعرّفات والأحكام في تقرير الدفعة أيضًا. archive يحفظ الأصل وDECISIONS يلخص التطبيق الحالي؛ ليسا سلطتين مستقلتين للحالة.

## حقائق الجلسة دون نسخها

```sh
npm run docs:context
npm run docs:context -- --pr 85
```

[context](../scripts/docs/context.mjs) يعرض JSON من Git الحالي (الفرع، HEAD، الشجرة، origin/main المحلي إن وجد) دون fetch أو تعديل الملفات أو refs أو index. الافتراضي بلا شبكة ولا يعني أن main المحلي حديث. الخيار `--pr NUMBER` يطلب GET للـPR وفرعه الأساسي عبر `gh` المتاح دون تثبيت/تسجيل دخول تلقائي؛ يعرض حالة الدمج ووقته والرؤوس ووقت التحقق، ولا يتبع كل PRs أو يعمل polling.

عند فشل الوصول أو غياب gh أو رد غير صالح، يعرض `verified:false` ويعيد رمز خروج1 إذا طُلب PR. استخدم أداة GitHub المتصلة عند توفرها؛ لا تستنتج الدمج من ref محلي. الأمر لا يثبت النشر أو فحص الهاتف أو الطب، ولا يستخدمه CI للتحقق الشبكي. رقم85 مثال، يُستبدل بالـPR المعني؛ لا تثبته في HANDOFF.

## اتساق التسليم والحالة

`docs:check` يرفض نسخ SHA بصيغة code أو رقم revision أو صيغ «main عند/فرع العمل» وبعض صيغ انتظار دمج Draft إلى HANDOFF؛ هذا حارس لأنماط محددة، وليس كاشفًا شاملًا لكل إعادة صياغة. يبقى HANDOFF مختصرًا للمتبقي والعوائق والمتابعة ويربط تقرير الدفعة. لا يكرر إصدار الحالة أو طلب دمج PR الذي سيتقادم بعد الدمج.

الفاحص ينبه عند بعض عبارات الانتظار في `description` لمهمة `done` (مثل «المتبقي»، «يبقى مفتوحًا»، `still pending`، `awaiting`). التنبيهات لا تفشل الفحص ولا تغيّر حالة أو تغطي كل اللغات والصياغات؛ قد تشير إلى نطاق منفصل مشروع. قبل التسليم صحّح التناقض أو اشرح بقاءه ودليله في التقرير، وراجع حقول المهمة معًا وHANDOFF كاملًا. لا استثناءات صامتة أو تغيير كلمات لإخفاء عمل متبقٍ.

## فحوص المتصفح اليدوية للمحاكي (RAD-074)

سكربتات `scripts/qa/*-audit.mjs` وmatrix وlabel-collisions وغيرها يدوية (Playwright + axe) وليست ضمن CI ولا ضمن `docs:check`؛ شغّلها مقابل `npm run build && npx next start -p 3100` مع `npm i --no-save axe-core playwright@<نسخة Playwright المثبَّتة مع المتصفح>` (نسخة أحدث تطلب متصفحًا غير موجود؛ `chromium.launch()` بلا مسار يستعمل المتصفح المثبَّت) و`BASE=http://localhost:3100`. منذ تخطيط الهاتف (UI-3، أقل من 1024px) تفتح ورقة الحالة نفسها عند التحميل وتتوزع الضوابط على أربعة تبويبات وتُطوى «الضبط الدقيق»، فلا يجد محدد الدور والاسم الضابط إلا بعد فتح مكانه. [workspace.mjs](../scripts/qa/workspace.mjs) هو المساعد المشترك: `startPractice` يغلق ورقة الحالة، و`reveal` / `driver` يفتحان التبويب أو اللوحة بنقرة حقيقية ثم يعيدان المحدد. يعتمد على الدور والاسم (EN/AR من `messages/*.json`) فقط؛ بلا `data-testid` ولا قراءة للمخزن ولا تغيير للمنتج. أي سكربت جديد يصل إلى ضوابط المحاكي يستعمله، ولا يكرر المنطق داخله.

```sh
BASE=http://localhost:3100 npm run qa:exam-audit -- chest-pa-erect pelvis-ap-supine   # قائمة فحوص
BASE=http://localhost:3100 npm run qa:exam-audit -- --all                              # كل سجل الفحوص
npm run qa:exam-audit -- knee-ap --locales=ar --widths=390                            # نطاق أضيق
```

[exam-audit.mjs](../scripts/qa/exam-audit.mjs) يفحص كل فحص × EN/AR × 390/1440 عبر الواجهة الحقيقية: صفحة المركز (h1 واحد، axe WCAG 2 A/AA، لا تمرير أفقي)؛ صفحة التدريب: على الهاتف axe ولا تمرير أفقي لورقة الحالة وللتبويبات الأربعة، وعلى الحاسوب للصفحة كلها ولا tablist؛ زر Expose ظاهر؛ بعد التعريض بالإعدادات الافتراضية: صورة النتيجة جاهزة ولها بديل نصي، وaxe، ولا تمرير أفقي؛ وعدم وجود خطأ صفحة أو console. لا يقيّم محاولة (تقيّمها سكربتات `*-audit.mjs` لكل فحص) ولا يثبت الطب أو المعنى؛ هو حارس تخطيط وإتاحة فقط. `--all` تُستخرج معرّفاته من `src/data/exams/index.ts`، وأي معرّف بلا صفحة مركز يفشل صراحة.

عتبات السكربتات القائمة لم تُخفَّف، وما يفشل بسبب الواجهة نفسها يُسجَّل نتيجةً في تقرير الجلسة ولا يُصلح من أداة QA. [تقرير RAD-074](RAD-074_QA_TOOLING_REPORT_2026-10-24.md) فيه جدول الجرد وما نجح وما فشل.

## مراجعة المعنى

الفحص لا يثبت أن الملخص حافظ على الحكم. عند اختصار أو إعادة صياغة قاعدة أو قرار أجب في تقرير الدفعة على سؤالين: هل تغيّر الحكم؟ وهل بقي رابط دليله الأصلي؟

## CI

CI يشغّل `docs:check` و`docs:test` على الشجرة المختبرة. على PR يضيف مقارنة القرارات بـ`--base origin/<target> --head <PR-head>` وفحص انتقال الحالة مع `--require-previous`. يُستخدم head الحقيقي لتحديد fork point لأن checkout قد يكون merge commit. يشمل `docs:test` اختبارات context، وتظهر تنبيهات الاتساق في ناتج `docs:check` نفسه محليًا وفي CI. فحوص التطبيق القائمة باقية؛ إضافة فحص docs لا تتجاوزها أو تغيّر توقعاتها.

## حدود الفحص والمراجعة

لا يتحقق الفحص من صحة الطب أو الترخيص أو إغلاق المهمة أو النشر، ولا يفتح الروابط الخارجية. دعم Markdown محدد للأنماط المذكورة، وليس محرك CommonMark كاملًا: لا تحليل لروابط مولدة ديناميكيًا أو داخل diagrams/fences، ولا لعناوين Setext أو إضافات Obsidian الخاصة. استخدم ATX وروابط Markdown/HTML المحلية الموثقة في الملفات النشطة؛ لا تضف استثناءًا عامًا لتمرير رابط مكسور. أي syntax جديدة تحتاج مثالًا واختبارًا ودعمًا صريحًا. مراجعة المعنى تقارن الملخص الحالي بقراره ودليله؛ عبارة تاريخية «غير منفذ» ليست حكمًا حاليًا.

## عرض الحالة دون تكرارها

```sh
npm run status:summary
npm run status:summary -- --id RAD-025
npm run status:summary -- --status review --query NIH --details
npm run status:summary -- --all --json
```

[summary](../scripts/status/summary.mjs) يقرأ JSON نفسه ويُحقق بنيته ثم يرشحه، ولا يكتب ملفًا أو يعدّل حالة. الافتراضي يعرض غير المنجز بإيجاز؛ `--id` يسترجع المنجز أيضًا ويعرض الدليل. معرّف غير موجود/خيار خاطئ/حالة غير صالحة يفشل. البحث نصي في حقول المهام فقط، ولا يتتبع محتوى القرارات أو يستنتج علاقة غير مذكورة؛ صفر نتائج لا يعني خلو القرارات من بند متعلق. نتائج البحث ليست إثبات إنجاز؛ الملخص يخضع لدليل الحالة الأصلية.
