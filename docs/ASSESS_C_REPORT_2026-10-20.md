# تقرير Assess C — دورة المحاولة والتصحيح

## 1. النطاق والانحرافات والميزانية

أذن المالك صراحةً ببدء C بعد إبلاغه بدمج #90. تحقق GitHub يؤكد الدمج إلى main عند `8cd416c`؛ بدأ العمل من main المجلوب، في فرع مستقل داخل checkout القائم. سبق الدمج نجاح إعادة Deploy Pages رقم39336701772 بعد تعديل إثبات المخطط، وأكد المالك ظهور قسم B على الهاتف وأنه يعمل. هذه أدلة A/B، لا إثبات نشر C أو نشر main اللاحق.

الميزانية14ملفًا: ترحيل واحد،3وحدات خادمية،3ملفات اختبارات،أداة rehearsal، و6وثائق هي هذا التقرير والعقد والخطة والإعداد والحالة والتسليم. لم تتغير وحدات مشتركة أو package/lock أو توقعات/بصمات قائمة. لا انتقال إلى D–F، ولا exam/image جديد أو محتوى طبي منشور أو اتصال إنتاج أو نشر عامل/مجدول أو تغيير لحالة PR. استعمال الفحوص القائمة في fixtures هندسي محلي فقط.

## 2. المنجز والمؤجل

- [الترحيل](../supabase/migrations/20261020000700_assess_lifecycle.sql) يفصل الكتالوج الخاص وحجز المحاولات والجلسات والتفاصيل والإيصالات والنتائج داخل assess. RLS افتراضي مانع، بلا منح جداول مباشرة حتى للمالك أو العامل، وبلا تغيير public/Practice. بوابة launch مغلقة افتراضيًا؛ لا RPC لفتحها. الاختبارات وحدها تفتحها في قاعدة قابلة للإتلاف.
- start يحمل operationId ويقفل حجز user/assignment، ويربط إعادة البدء بالمحاولة نفسها حتى بعد التصحيح. إعادة طلب استكمال بمعرف جديد أثناء active/grading تُربط بالمحاولة نفسها أيضًا. عداد الحجز وإيصالات بدء دنيا دون أجوبة/علامات يبقيان بعد حذف النتيجة حتى لا يتحول purge إلى محاولات مجانية. إعادة معرف بدء لمحاولة محذوفة ترفض. مفاتيح الجلسة والوقت والإصدار والترتيب والسياسة مثبتة بالخادم.
- save/expose/submit تعيد فحص الاعتماد والإسناد، وقفل الصف وrevision. البحث عن إيصال SHA-256 للجسم القانوني يسبق المهلة/النسخة؛ اختلاف الجسم لنفس العملية مرفوض. التعريض يحفظ الجواب والقفل ذريًا، ولا يفتح refresh تعريضًا آخر. لا درجة أو تعريف أو معيار يقبله العميل. SQL يتحقق حتى من الطلب المباشر الذي يتجاوز TypeScript.
- expiry يثبت deadline وقتًا منطقيًا للتسليم؛ قراءة الجلسة/البدء/أمر متأخر يمكنها تجميدها، والعامل المحدود يجمدها والمتصفح مغلق. الأمر الجديد المتأخر لا يحفظ جوابه؛ يعود ack مع accepted=false وreason=deadline. تنتهي قابلية القراءة عند expiry حتى لو تأخر الحذف.
- [التحقق](../src/features/assess/server-validation.ts) يثبت refs/shape/review وMCQ الخاص ومواصفات القيم المسموحة وخلفية الجزء ومعاييره ونقاطه. تثبيت case SHA-256 يشمل بيانات الحالة وهوية التقييم، وevaluator صريح. إصدار مجهول يفشل مغلقًا بدل إعادة التصحيح بقواعد أحدث. تثبيت publication لا يقبل استبدال مفتاح نفس version؛ إدارة المحتوى بالواجهة في D.
- [المصحح](../src/features/assess/server-grader.ts) يحسب MCQ وsimulator-part والفحص الكامل من snapshots الخاصة. الناقص/المحاكي المحفوظ بلا تعريض صفر. القيم الثابتة يعيد الخادم تركيبها؛ تغيير letter لا يحرك الموضع الثابت. أضيف adapter هندسي يفصل marker-side وmarker-placement باستخدام predicates القائمة، بلا إعادة استعمال combined partial credit؛ درجتهما الثنائية ونطاق الخلفية يحتاجان مراجعة كل سؤال قبل النشر. معيار AEC المتغير التطبيق مرفوض إلى أن يوجد adapter مراجع.
- الفحص الكامل يستخدم checks والـrubric والأوزان والفئات الموجودة مع كسور دقيقة؛ لا قص علامة Practice المقربة. بوابات critical وpassed تُقرأ من المحرك القائم بلا تحويلها إلى عقوبة عددية؛ كالتدريب، البوابة لا تغير الرقم. passed/تفاصيل المعايير لا تُحفظ ضمن السجل المختصر ولا تُعرض كتحليل جديد.
- [الخدمة والعامل](../src/features/assess/server-service.ts) يستخدمان منفذي JWT للمستخدم وصلاحية worker منفصلة. user/owner لا يستطيع claim/finish/maintenance أو قراءة المفاتيح. العامل يأخذ lease/token لخمس دقائق مع SKIP LOCKED، ويحفظ الكسر النهائي ويحذف التفاصيل والإيصالات في معاملة واحدة. فشل الحذف يرجع تثبيت النتيجة أيضًا؛ فشل التصحيح يبقي المجمد، بلا صفر افتراضي أو إعادة تعريض. استرداد finalize بtoken قديم مرفوض؛ إعادة finalize الناجح بنفس token آمنة.
- retries آلية كل دقيقة ضمن24ساعة، بما فيها تقييد استرداد lease متروك؛ counts للتنبيه دون أجوبة/هويات/علامات. بعد24ساعة استرداد صريح حتى7أيام؛ بعدها حذف المؤقت بلا نتيجة مع بقاء الحجز. النتيجة المختصرة تُقرأ whitelist بأربعة حقول، والعلامة المحجوبة لا تظهر في API؛ القراءة المباشرة محظورة. التسليم الناجح يحذف digests، لذلك retry قديم لـsave/expose بعد التصحيح يُرفض ويقرأ العميل الحالة النهائية؛ replay لـsubmit معروف يبقى آمنًا بmetadata دنيا.
- [أداة rehearsal](../scripts/assess/rehearse-c.mjs) تشغل المسار كاملًا في Node24 مع PGlite، أو معاملات PostgreSQL فعلية متوازية في حاوية محلية قابلة للإتلاف. لا HTTP listener أو credentials إنتاج أو endpoint مصادقة جديد. منفذ SQL/RPC جاهز للربط لاحقًا؛ اختيار استضافة Node/transport وربط صلاحية العامل وجدولته ومراقبته ليس نشرًا منفذًا.

## 4. المشترك وحدود Scale

لا تعديلات مشتركة. السقوف التشغيلية v1:200بند/50خيارًا، publication≤2MB، أمر canonical≤64KiB، مدة مؤقتة≤7أيام، maxAttempts≤1000،20ألف أمر حفظ/تعريض لكل محاولة مع السماح بالتسليم و20ألف عملية بدء لكل حجز، batch≤100، ودقة نقاط≤6منازل. بلوغ سقف الحفظ لا يمنع submit. تخزين maps البدء محدود لكنه يبقى تكلفة على الحجز؛ قياسه وفهرسة/أرشفة metadata وقياس aggregate health مطلوبان قبل توسيع الأحمال. لا وعد بسعة Free أو QPS. لا تحميل غير محدود للطلاب بالمتصفح. vocabulary التخزين مفتوح مع رفض الأنواع غير المدعومة، دون تعميم ControlSpec للواجهة.

metadata الحجز تبقى فقط للهوية والإسناد والعدد وoperation→session؛ لا أجوبة/درجات فيها. حذف الحساب/الإسناد يحذفها عبر FK. سياسة أعمارها والنسخ والاستعادة والإفصاح ضمن O106 قبل التخزين الحقيقي؛ ليست موافقة مُنجزة.

## 5. الطب والدرجات

لا حقيقة/صورة/فحص جديد أو اعتماد طبي. review metadata تحقق بنيوي وليس دليل صحة المصدر أو الترخيص أو توقيع المراجع. O108 باقٍ قبل أي publication حقيقية. الجزء يختبر المعايير المحددة فقط، بلا بوابات الفحص الكامل؛ خلفيته لا تُفترض مثالية من initialSettings. fixtures تستعمل initialSettings باعتبارها بيانات هندسية غير منشورة، لا سؤالًا مقبولًا. marker adapter مثبت هندسيًا لا سريريًا. نتائج التدريب وبياناته وتوقعاته القديمة محفوظة.

العلامة النهائية كسر صحيح بسط/مقام نصيين؛ العرض فقط half-up بمنزلتين. SQL يستخدم div لحساب السنتات الصحيحة حتى لا يحدث تقريب وسيط إلى tie، ويختبر الكسر المحدود قبل الحفظ بضرب صحيح. expiry ستة أشهر تقويمية UTC مع clamp؛ لا180يومًا أو تمديد بالنشاط.

## 6. QA ودليل التشغيل

- `npm run build:pages`: ناجح؛ ثم بناء pilot بإعداد Supabase اصطناعي فقط لتدقيق الواجهة. فحص الحزمة الساكنة لم يجد رموز مصحح/عامل C؛ لا endpoint جديد في Pages.
- تدقيق المتصفح القائم:660تحققًا و16حالة EN/AR390/1440 axe/overflow ناجحة، مع API اصطناعي محلي. لا تغيير واجهة أو مشهد في C.
- rehearsal بعقد assess-c-rehearsal/1: PASS في Node24/PGlite، ثم PASS في PostgreSQL17 محلي بمعاملات مستقلة متوازية. الحاوية بلا نشر منافذ، وقاعدة الاختبار تُنشأ وتُحذف ولا تتصل بمزود حي.
- `docs:check --base origin/main` و`status:check --base origin/main --require-previous` و`git diff --check`: ناجحة، دون review warnings. تعارض RAD-024 الموروث يظهر كما هو ولا يمنع الفحص.
- أثناء إعادة اختبار Node بالتزامن مع البناء تجاوز الاختبار الجديد مهلة Vitest الافتراضية5ثوانٍ؛ ضُبط timeout لهذا rehearsal ذي التهيئة الفعلية إلى40ثانية ثم نجح الفحص الشامل. لم تتغير توقعات قديمة أو يُتجاوز فشل منطقي.

اختبارات C تشمل رفض هويات متعددة والوصول المباشر، مواصفات الإجابة، حقول زائدة ومفتاح/نسخة قديمة، إخفاء العلامة، استكمال/قفل التعريض، حد المحاولات بعد purge، UTC/نهاية الشهر ودقة الكسور، تعطل lease،24ساعة/7أيام وفشل الحذف الذري. سكربت PostgreSQL يختبر بدءًا وتعريضًا وتسليمًا مكررًا، عاملين، اختلاف revision، تعريضين مختلفين وسباق expiry/submit بمعاملات مستقلة؛ PGlite وحده ليس دليل توازٍ فعلي.

لا تغيير واجهة في C، لذلك لا تدقيق طبي/عائلة بصري جديد. فحص EN/AR390/1440 وaxe للواجهة الحالية يجري كحارس عند نهاية الدفعة؛ لا يثبت واجهة امتحان لم تُبنَ. لم يُفتح أو يُشارك رابط معاينة مستضاف. لا مزود حي أو فحص أداء أو موافقة Assess أو حذف نسخ احتياطية مثبتة.

## 7. القرارات التقنية والبوابات المتبقية

Node24 local proof ليس اعتماد مزود إنتاج أو توافق Deno. قبل التخزين الحقيقي: اختيار binding مصادق لـRPC/worker دون admin في المتصفح، bundling ومراقبة مُجربان، جدولة دورية موثوقة للexpiry/purge وقياس تأخرها وتنبيه خارج counts، موافقة Assess وحد احتفاظ المتروك غير المؤقت ودورة backup/restore؛ ثم O108 ومراجعة كل خلفية/معيار/marker. start غير المؤقت يرفض الآن بدل اختراع حد inactivity. launch_gate مغلقة، ولا تعليمات فتح إنتاج ضمن هذه الدفعة. لا تعديل marker النشر أو تعطيل حارسه بسبب ترحيل غير مطبق.
