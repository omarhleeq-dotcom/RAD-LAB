## 2. المنجز والمستبعد

أُوقف مسار النسخة الحالية بتوجيه المالك. الناتج ملف retention وحدها، مع baseline داخل معاملته وقفل advisory وأقفال الجداول المتأثرة؛ lock_timeout5s وstatement_timeout60s ثابتتان. قبل الإضافة يراجع نفس baseline المقروء المطابق الذي أرسله المالك: B–F والدوال32 بنهايتي LF/CRLF المحددتين، والمخطط والصلاحيات والtrigger والبوابة المغلقة وغياب إضافة الاحتفاظ. داخل حارسي الكتابة يُستثنى read_only فقط من تجميع catalogue_ready لأنهما داخل معاملة تكتب؛ لا استثناء لأي شرط مخطط أو صلاحية أو مصدر. فحصا القراءة المستقلان يحتفظان بشرط read_only.

أُدرجت بايتات الترحيل الإضافي دون تعديل، مع إزالة حدّي معاملته الخارجيين فقط لاحتوائه في معاملة الحارس. SHA256 للمصدر الكامل: `6142bbecd7dae9c2ac6d2b5ab7ebcc4b10ac29ef6388aced47c7b7b82bc8b3d6`. الاختبار يثبت تطابق الجزء المصدر حرفيًا، لا إعادة توليد لتوقع/بصمة قديمة. لم تتغير ترحيلات مطبقة أو ملفات baseline السابقة.

بعد الإضافة وقبل COMMIT يراجع catalogue كاملًا يشمل account_stops والدوال36 ومصفوفة التنفيذ وRLS وعدم منح الأعمدة، وبصمات مصادر LF/CRLF المحددة، وجميع أعمدة/قيود/فهارس Assess، وعقد trigger الموافقة وtrigger الإغلاق النهائي، والبوابة المغلقة. أي فشل يمنع COMMIT. بعد COMMIT فقط تصدر معاملة قراءة صف assess-retention-install/1 النهائي؛ الأعلام backup/recovery/provider/runtime تبقى false. فحص postinstall مستقل يعيد نفس قراءة النهاية، لمعالجة ضياع الاستجابة بعد COMMIT دون إعادة installer.

مقارنة schema الجديدة مع baseline F راجعت delta فقط: closed_at وإزالة unique القديم وإضافة الفهرسين للإسناد، PK/قيد نسخ الموافقة، فهرسا sessions، وجدول account_stops. لم يُضف endpoint أو middleware أو عامل/جدولة أو تشغيل job أو حذف بيانات أثناء التثبيت؛ لا seeds أو backfill قبول أو علامة مصطنعة. النسخ/التصدير/restore الإنتاجية ليست ميزات بُنيت في هذه الدفعة.

## 3. المهمة RAD-056

## 4. الوحدات المشتركة وScale

التغيير المشترك في local-database فقط: خيار محدود `through='f'` للترقية الاصطناعية، و`lineEndings='lf'|'crlf'`؛ الافتراضي latest/LF باقٍ لأدوات الصيانة السابقة. الخيارات غير المعروفة ترفض، ولا URL أو مشروع أو أسرار. PostgreSQL عنقود محلي قابل للإتلاف عبر Unix socket داخل مجلد0700 بلا TCP؛ port يفتح معاملات مستقلة، وقراءات fixture الإدارية تسير بالتتابع عبر اتصالها الواحد.

حدود Scale: حزمة يدوية واحدة لمخطط F المحدد؛ الإضافة الموجودة/الجزئية أو أي drift توقفها. قوائم الجداول/التواقيع/البصمات مقصودة ومحدودة بعقد الإصدار؛ رفعها يحتاج مراجعة إضافة لاحقة، لا توسيع تلقائي أو normalization. الفهارس الحالية ودفعات maintain1..100 وSKIP LOCKED والحذف الذري تبقى كما هي؛ لا قراءة طلاب غير محدودة في حارس المزود، فقط catalogue وحالة gate. أدوات QA تفحص بيانات fixture صناعية في الذاكرة ولا تطبعها؛ الناتج أكواد وأسماء checks وأعلام فقط.

## 7. المتبقي والبوابات

لم يُنفذ الملف على الأصلية من الوكيل ولم يصل صفه النهائي من المالك. لا نسخة أو restore جديدة، ولا دورة استعادة مكتملة. النسخة الشاملة اللاحقة تحتاج جرد تغطيتها: القاعدة والأدوار والبيانات وعلاقات Auth/Storage والكائنات وإعدادات التطبيق/الهوية وتبعياتها؛ dump قاعدة وحده ليس نسخة كل النظام. المفاتيح والملفات خارج Git/المحادثة، ولا تغيير إنتاجي الآن أو مدة مخترعة للمزود.

استعادة snapshot قديمة قد تعيد إسنادًا أغلق أو حسابًا عُطل أو موافقة/metadata حذفت. purge النتائج وحده لا يعيد الحالات الأحدث، وlaunch_gate=false تحجب البدء فقط. يبقى الوصول محجورًا خارج API أثناء restore حتى إعادة الآثار الأحدث والحذف وفحص ACL. دليل إعادة تطبيق مستقل ودورة backup/import/restore لم ينفذا؛ شاهد الخطر السابق لا يكفي لإعلانهما مكتملين.

O108 والمصادر والترخيص والمراجعة والخلفية والمعايير وMarker، وruntime والعامل والجدولة والمراقبة والنسخ والاستعادة والتصدير والنشر بوابات مستقلة. launch_gate مغلقة، وغير المؤقت خارج التجربة، ولا قبول تجريبي حي مكتمل.
