# RAD-085 — الإجراء المحلي للمحو والتعافي

[مصفوفة الحكم والبيانات](RAD-085_ERASURE_MATRIX_2026-10-26.md) حاكمة للنطاق. [تقرير الدفعة](RAD-085_ERASURE_REPORT_2026-10-26.md) يسجل التفويض والاختبارات. لا أمر هنا لتطبيق حي أو تشغيل عامل أو فتح خدمة؛ مخزن الدليل والمصادقة وAuth/IAM/المزوّد غير مهيأة.

## الحذف من قاعدة العمل

1. يتحقق المالك من الطلب وهوية صاحبه خارج سجلات المحتوى. يستخدم C2 deactivate القائمة، فتوقف الدخول والجلسات القابلة للتجديد وتبقي الطلب لمدة30يومًا. لا يُسجّل محتوى/بريد في إثبات العملية. الإبطال في المضيف/pool/cache وإيقاف الرد المتأخر خطوات مستقلة؛ نجاح SQL لا يثبت وصول إشعارها.
2. preview للمالك فقط، UUID هدف صريح، يمنع النفس. يعيد due وأعدادًا وفئات blockers فقط؛ ليس directory أو مستندات أو قائمة أشخاص. هذه معاينة لحظة القراءة وليست وعدًا؛ finalise يعيد الفحص تحت الأقفال. لا عمل حذف من المشرف أو العامل أو الجسر.
3. finalise القديمة تبقى نافذة30يومًا وحماية النفس/آخر مالك وحد batch≤100. ترتيب القفل: scope UPDATE قبل profiles SHARE ROW EXCLUSIVE، ثم profile الهدف وversions المرتبة. هذا يجمع النشر/الإسناد الجديدين والطرق التاريخية التي تقفل profile/version. كل فشل مهلة/تعارض يرجع الدفعة كلها؛ لا SKIP أو catch يعلن محوًا جزئيًا.
4. المسار الخاص المشترك يفحص provenance والامتحانات: أي إسناد مملوك أو مرتبط بالنسخة، مجموعة مشتركة/فترة/طلب يخص آخر، مصدر مجموعة داخل إسناد، قرار/تعيين لآخر، scope أو إيصال مؤكد أو ملكية رابط غير متطابقة ⇒55000 وROLLBACK. يبقى الحساب معطلًا؛ لا نقل ملكية أو حذف محتوى لازم أو إعادة فتح إسناد.
5. بعد الإثبات: تحذف مراجعات الكاتب غير المؤكدة (review_targets عبر CASCADE القائمة)، ثم publication_links الخاصة، ثم publications غير المسندة. يحذف Auth الأصل؛ تتبع profiles والمسودات/نسخها/packages والمرشح/presentation والمجموعة الخاصة الفارغة والبيانات الشخصية CASCADE الموجودة. لم يضف FK CASCADE أو يعطل trigger. أي FK غير محسوب أو trigger رفض ⇒rollback كامل، لا إسكات للحارس.
6. التكرار: finalise على batch خالٍ يعيد processed=0؛ إعادة primitive خاصة لهدف غائب لا تعيد بيانات. عند فقد ACK لا تعاد كتابة تلقائية؛ يقرأ المسؤول الحالة الحديثة من قناة مفوضة ثم يعيد الإجراء صراحة. batch ذات هدف محجوب ترجع كلها، بما فيها أهداف سبقت داخله؛ لا تقدم مصطنع. قبل أي بيانات تشغيلية يلزم إجراء عزل الهدف المحجوب وإعادة مراجعة الالتزامات، لا تغيير requested_at لتجاوزه.
7. maintain_v1 نفسها لمسارات نتائج Assess والتفاصيل والحجوزات والموافقة؛ لا عامل جديد أو مدة جديدة أو purge للمجموعة المنتهية. لا أسرار أو bodies أو target UUID في سجلات الأداة العامة؛ الفئات والأعداد وأسماء مراحل ثابتة فقط.

## دليل أحدث من النسخة

اعتمد المالك استثناءً محدودًا من منع tombstone داخل C2: دليل مصالحة **خارج قاعدة العمل وخارج حزمة snapshot**، لا نسخة أخرى من بيانات الفرد. حقوله whitelist: operation UUID عشوائي، نوع أثر مقيد، UUID الكائن المستهدف (حساب/مجموعة/إسناد/فترة عضوية)، وقت UTC، تسلسل، previous/MAC لإثبات السلامة. UUID يظل بيانات مرتبطة؛ لا ندعي إخفاء هويته. الوصول لمسؤول الاستعادة وحده، والمفتاح وقيمة الرأس الأحدث الموثوقة خارج النسخة. لا سجل أسماء/بريد/مستند/درجة/أجوبة أو digest لها.

حياة الدليل مرتبطة **بجرد كل النسخ القابلة للاستعادة التي تحتاجه**؛ يحذف بعد انتهاء آخر واحدة والتحقق من المزوّد. ليس تداول7أيام لنسخنا دليلًا لانتهاء نسخ مزود. هوية المسؤول وخزنة/تشفير/صلاحيات/نسخ هذا الدليل التشغيلية وديمومته عبر إعادة تشغيل العملية لم تجهز في هذه الجلسة؛ لا مخزن إنتاج أو IAM منشأ.

الترتيب المطلوب قبل الوصل: نية تقييد محمية ومثبتة خارج snapshot، ثم المعاملة، ثم مصالحة حالتها وACK. pending/فشل/نتيجة مجهولة لا يصير completed؛ عند غموض النتيجة يبقى الوصول محجورًا حتى تحقق مسؤول. المخزن الصناعي المنفصل يكتب ملفات0600 داخل مجلد0700 ويستعمل fsync للملف والدليل وrename للرأس، قبل وبعد تثبيت الأثر. prepare تكتب النية قبل المعاملة؛ complete لا يثبت الأثر دون تحقق صريح. pending أو tail غير محسوم يحجب head، ولا يقتطع آليًا. سقفه10000أثر و100نية؛ payload بصفحات≤100، وأسماء الملفات metadata محدودة بهذا السقف. المفتاح منفصل في الذاكرة ولا يدخل snapshot؛ close يصفره ويحذف المجلد. لا reopen أو ضمان سقوط جهاز أو مخزن إنتاج. عينة الاختبار تثبت اكتمال الأثر من المصدر قبل أن تستخدمه للاستعادة؛ لا ترقية قصد حذف فاشل إلى حذف نهائي مأذون. اعتماد سجل تشغيل transaction/outbox موثوق لم ينفذ بعد؛ لذلك لا يجوز تشغيل هذه الأدوات على بيانات حقيقية.

الأثر الموقّع وhead الخارجي لا يثبتان وحدهما أن كل قناة حذف/سحب سجلت الحدث. قبل التشغيل يلزم حصر جميع قنوات C2 والإدارة والمشاركة والإغلاق وexpiry/العامل، وترابط الالتزام والدليل وأحدث watermark، وحجر عند فقد القناة. الاختبار لا يدعي سد قناة إدارية غير موصلة.

## الاستعادة المحجورة

1. يعزل مسؤول الاستعادة الوجهة عن API وكل القراءات والنقل والكتابة والعامل والجدولة. launch_gate=false وحدها غير كافية. لا يعاد تشغيل snapshot على الوجهة الأصلية ولا يستعاد سر/جلسة/قدرة/cache قديمة. لا تغيير للبوابة في هذه الجلسة.
2. يأتي المفتاح والرأس **الأحدث** وجرد snapshot من مصدر مستقل موثوق؛ يغلق باب التغييرات طوال مصالحة cut ثابت. غياب الدليل، أو رأس قديم لا يمكن إثبات حداثته، أو نسخة مزود مجهولة الأفق ⇒لا ready ولا وصول. MAC لا يثبت حداثة رأس اختاره snapshot نفسه.
3. البروتوكول الصناعي يتحقق على مرور أول بصفحات1–100 (افتراضي50) من schema/تسلسل/توقيع/previous حتى الرأس؛ ثم يعيد القراءة والتحقق والتطبيق idempotent على مرور ثان. سقف10000حدث قابل للضبط؛ تجاوزه يرفض مغلقًا، لا يقتطع. head فارغ مقبول فقط إن ثبت genesis الحديث من خارج النسخة.
4. replay للحذف النهائي المثبت يستعمل primitive خاصة مشتركة مع C2، بصلاحية مسؤول restore وclaim مالك حديث موثوق. ليست EXECUTE متاحة حتى للمالك authenticated؛ لا مهلة30يومًا ثانية عند إعادة حذف نفذ فعلًا، ولا اعتماد على وجود طلب التعطيل داخل النسخة. حماية النفس/آخر مالك وblockers تبقى. الحذف المرفوض في قاعدة العمل لا يتحول إلى حذف مأذون بالاستعادة.
5. يعاد السحب والتعطيل والإغلاق والمغادرة/نهاية المجموعة عبر المسارات المأذونة؛ أي حالة لا تدعمها قناة مثبتة تبقي الخدمة مغلقة. السحب لا يعيد targets أو العلامات. إعادة منح أو استعادة حساب شرعية أحدث تحتاج مصدر الحالة الحالي ومراجعة منفصلة؛ لا تؤخذ من snapshot. البروتوكول يقبل آثار التقييد فقط ولا يمنح امتيازات.
6. تشغل maintain_v1 القائمة بحدودها وتتحقق خادميًا من غياب كل المستحق، لا نجاح batch واحدة. بسبب SKIP LOCKED قد يبقى عمل؛ لا ready حتى إثبات التفريغ ونهاية نوافذ الاسترداد والحجوزات/الموافقة المستحقة. لا اختراع تاريخ انتهاء جديد.
7. تبطل جلسات/refresh tokens وcapabilities وpool والمفاتيح والأسرار القديمة وcache؛ تحقق رفضها جميعًا، بما فيها callback قديم. يراجع مسؤول الصلاحيات ACL/RLS/الأدوار/العضويات وAuth/Storage/exports وفق الجرد الفعلي، ويتحقق من كل أثر. يفحص الرأس الحديث مرة أخيرة تحت حجر التغييرات.
8. الاختبار يصدر `synthetic-verified` فقط، ولا يحتوي فتح خدمة. بعد فشل بعد COMMIT يعاد replay المقيد من البداية والتحقق، ولا يعتمد checkpoint من snapshot. الفتح التشغيلي يحتاج اكتمال دليل كل الأثر والصلاحيات والقنوات والمزوّد وموافقة منفصلة. فشل verifier أو maintain أو إبطال أو تطبيق لا ينتج شهادة جاهزية.

## حدود الشاهد

نسخة PostgreSQL صناعية فعلية عبر CREATE DATABASE TEMPLATE قبل التعطيل/الحذف والسحب، ثم استنساخها بعد الأثر إلى قاعدة أخرى في cluster معزولة عبر Unix sockets بلا TCP. هذا إثبات لاستعادة بيانات قاعدة فقط؛ roles مشتركة في cluster وليست مستعادة من الأرشيف. لا يعيد اختبار dump/globals التاريخي أو تشفير الأرشيف أو تصديق Supabase/Auth/Storage/TLS/pooler/PITR. cache/epoch في شاهد الاستعادة بديل صناعي؛ اختبارات المضيف والمتصفح السابقة تبقى دليل قناتها المحلية المحدد.

لا توجد مخازن أو جلسات أو خدمات حقيقية تُفتح. كل cluster ونسخة وقاعدة ومفتاح عشوائي صناعي عمرها عمر الاختبار وتزال في finally؛ الإخفاق في التنظيف فشل اختبار، لا نجاح صامت. جرد أرشيفات المزوّد وRPO/RTO والتشفير/الحذف والتصدير الموثق باقية للمراجعة المستقلة.
