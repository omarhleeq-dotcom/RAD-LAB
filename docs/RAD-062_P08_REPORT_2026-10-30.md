## 4. التغييرات المشتركة وScale وسؤالا AGENTS

صفر وحدات منتج/واجهة مشتركة متغيرة. تغيّر manifest لإضافة المؤجل فقط. عُدّلت **داخل M08 الأمامية فقط** ثماني دوال قائمة: `public.owner_account_deletion_v1` و`assess.account_management_v1/transfer_management_d3_v1/erase_account_d3_v1/d3_needs_transfer_v1/d3_shared_group_v1/d3_inventory_v1/authoring_write_guard_v1`. فحص كل anchor إلزامي؛ غيابه يجهض المعاملة كلها، بلا حذف دوال v1. بقي OID وowner وACL وconfig لهذه الدوال كما هي؛ تغيّر نصها فقط للتكامل المحدد. منح وظائف v2 القائمة تتغير فقط بالـGRANT النهائي الصريح.

- **المحو:** ترتيب capacity ثم scope ثم profile/assignment/session يمنع قلب أقفال كاتبي v2. محو الطالب يزيل profile والاسم وsessions والأجوبة والتفاصيل واختيارات الحوض وحجز السعة وwork/scores/events وreceipts/results الخاصة به عبر CASCADE. يُحذف attribution الكاتب، وتصفّر هوية المراجع ونص اسمه/توقيته وهوية المصحح من الدرجات والأحداث والإيصال النهائي للطلاب الآخرين.
- **المشترك والحقوق:** draft/revision/candidate/package المحمي لا يُنسب إلى المستلم. تبقى بايتاته تحت موافقة الحقوق المرتبطة بـdigest ونقل الإدارة القائمين، مع writer/owner خاليين وإزالة هويات المنشأ. أُدرجت holds في اشتراط النقل وحماية المجموعة الحاوية وجرد المحتوى؛ يسمح حارس M03 فقط بتصفير writer عبر capability D3 الخاصة مع تطابق بقية الصف. الخاص غير المحمي يحذف مع revisions/candidates/provenance؛ لا tombstone لهوية المستخدم أو نسخة جواب أو digest جواب نهائي.
- **الاسترداد:** مالك معتمد لنطاقه أو إدارة منقولة صراحة، بعد الأقفال وقبل168h فقط. يعيد `awaiting-manual` عند نجاح الآلي، وإلا `grading`؛ لا يعيد active أو يغير started/deadline/submittedAt أو يفتح gate أو يعيد احتساب الآلي الناجح. النهائي غير قابل للاسترداد.
- **D4:** قائمة keyset بحد20 وافتراضي وحد100، تشمل grading والفشل وhold والانتظار من120h إلى أقل168h. لا نص أو درجة أو هوية؛ مرجع محاولة وعدد كتابي وموعد النهائي فقط. غياب ACK يعيد المحاولة؛ يسجل وقت الإرسال مرة واحدة فقط بعد ACK القناة المعتمدة. لا قناة أُنشئت ولا ادعاء استلام، ولا تمديد للمهلة بسبب فشل الإرسال.
- **الصيانة:** كل مرحلة دفعة≤100 مع SKIP LOCKED وفحص وقت الخادم بعد قفل الصف؛ deadline ثم void وحذف المؤقت عند168h، ومعالجة فشل24h، وpurge عند expiry. تنظيف reservations المغلقة يخص schema2 فقط ولا يحذف شاهد الإغلاق الدائم؛ v1 تبقى لمسارها. الإيصال النهائي للآخرين يبقى بهوية مصحح خالية حتى expiry النتيجة نفسها، ثم يحذف معها.
- **المنح:** authenticated لواجهات الطالب/المسودة وqueue/read/score/finalize/receipt والتعافي المقيّد بالمالك؛ bridge لـbridge-read/content-submit فقط؛ worker لـclaim/finish/fail/maintain/health وقائمة الإنذار وACK. لا جداول أو helpers أو freeze أو reviewer-provisioning أو تصحيح يدوي/تعافٍ للعامل أو دور مشرف عالمي أو LOGIN جديد. تبقى هذه المنح غير مطبقة ما دامت M08 مؤجلة.
