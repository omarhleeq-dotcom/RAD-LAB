الترتيب المختصر لدخول المالك لاحقًا: (1) مراجعة النتائج والمحتوى وإسناده وتحديد اللازم، (2) مراجعة ترحيل D3 الجديد والحقوق وO5 وتهيئة المشاركة الحية المعتمدة، ثم اتباع حزمة DB day الواحدة، (3) جرد المزوّد والبريد/الحقوق/التكلفة دون تفعيل، (4) قبول الواجهات والهاتف، (5) إكمال RAD-082 والنسخ والاستعادة المحلية في أي جلسة قبل أول امتحان حقيقي، ثم أذونات تنفيذ خارجية منفصلة عند اكتمال البوابات. لا وعد بإنهاء ذلك في ساعة أو نافذة واحدة، ولا طلب دخول/أسرار الآن.

التوصية التشغيلية: نسخة أسبوعية مشفرة إلى USB خارجي مع حفظ المفتاح منفصلًا والتحقق من الاستعادة. لا نسخة أو سجل مصالحة سحابي.

الكتابي (مرحلة لاحقة): إنذار المالك في اليوم الخامس؛ يجوز له التصحيح قبل اليوم السابع؛ void فقط إن بقي غير مصحح يوم7. تصدير درجات المجموعة النهائية مرة واحدة قبل انتهائها مخطط لاحقًا وفق D8، دون تنفيذ الآن.

**سلوك مقبول (S7، [قرار المالك](DECISIONS.md#rad085-sec-fixes-owner-2026-10-27)):** إذا ألغى مشرف طلب حذفه خلال30 يومًا يعود حسابه عبر restore، لكن تعيينه ومجموعاته المنتهية بنقل D3 لا تعود تلقائيًا. يعيد المالك تعيينه يدويًا عبر appointment_v1 إن رغب، وينشئ المشرف مجموعة جديدة؛ لا استعادة تاريخ أو رؤية سابقة.

## تذكير O5 اليومي — مسؤول التنفيذ: المالك

- **كل يوم، بما فيه تغطية غياب المالك:** افتح مسار المالك القائم للحسابات/طلبات الحذف وراجع قائمة التشغيل المحدودة `assess.account_management_v1('list', p_after=>..., p_limit=>20)` من جلسة المالك المأذونة. cursor ثابت؛ لا فحص غير محدود أو subscribe/poll. لا نقل آلي أو retry بعد ACK مجهول.
- **من بدء الطلب:** التعطيل فوري؛ حقوق الاستعادة القائمة30يومًا محفوظة. راجع الجرد والمحتوى الضروري وأقل إسناد لازم والنسخ/الصادرات. جهّز preview واختبار الحقوق والمالك البديل المعتمد؛ نقل الإدارة لا ينسب التأليف أو يقبل شروطًا للطالب ولا يمدد نتائج غيره.
- **قبل اليوم25:** أكمل المراجعة والنقل الصريح على البايتات المعاينة؛ النجاح يجب أن يكتمل قبل اليوم30. `transfer_alert` يظهر من25 لطلب يحتاج نقلًا بلا إيصال مطابق. يصعّد المالك النقص يومه ويحدد تغطية غيابه؛ قبل30 يجب حل العائق، لا تغيير requested_at. لا انتظار لبلوغ30 لبدء مراجعة حقوق المحتوى.
- **بعد اليوم30، يوميًا:** المالك يستخدم **لوحة المالك → طلبات الحذف المعلقة → Finalise expired**، وهو C2 القائم. كل ضغطة حتى100؛ كرر صراحة حتى تخلو القائمة من كل المستحق بعد فحص نتيجة كل دفعة. قبل الموعد يبقى `processed:0`. لا finalise مبكر أو تعديل نافذة الاستعادة.
- **بحلول اليوم37 كحد أقصى:** تحقق من اكتمال كل محو مستحق وإبطال الجلسات وتغطية الصادرات والنسخ التي نديرها، وسجل الأثر الأدنى في السجل المحلي المشفر. `finalise_due` يبدأ بعد30 و`overdue` يعلن خرق الموعد عند37؛ أي خطأ/غياب/ACK مجهول تصعيد فوري للمالك مع فحص قراءة فقط. لا حجب مفتوح أو تمديد نافذة؛ هذه التغطية التشغيلية شرط قبل أول مشرف حقيقي، لا ضمان من مجرد وجود SQL.

سجل الحقوق الخاص `assess.erasure_rights` لا ينسخ نصًا أو اسمًا: UUID الحساب، بصمة المحتوى المعاين، disposition=`no-personal-data` أو `minimum-required-attribution`، ومعرّف المراجع المعتمد ووقت المراجعة. يكتبه المشغّل الموثوق في نافذة SQL مأذونة **بعد مراجعة كل المحتوى المثبت**؛ لا grant مباشر لأي API role. لا تستخدم disposition لتبرير هوية غير لازمة أو ترخيص مجهول. البصمة تأتي من preview الخاص ولا تُقبل بعد تغير المحتوى؛ عائق الحقوق يصعّد قبل30. ملف initializer ليس قبول Terms/مشاركة أو تفويضًا حيًا لهذه العملية.
