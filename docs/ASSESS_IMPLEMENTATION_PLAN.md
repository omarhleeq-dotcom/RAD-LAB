# خطة Assess القابلة للاستئناف

## السلطة وحدود الخطة

مرجع المنتج الوحيد هو [قرارات المالك بتاريخ 2026-10-19](DECISIONS.md#assess-owner-2026-10-19)، مع بقاء أحكام المصدر/المراجعة والحماية التي لم تُستبدل من [الأصل](archive/decisions/DECISIONS-until-2026-10-16.md#decision-s-assess-1). هذه الخطة تنظيم تقني مقترح لتنفيذ تلك القرارات، وليست إذن برمجة أو دليل تنفيذ. حالة RAD-055 وRAD-056 في [project-status](project-status.md) فقط. مراحل هذا الملف ليست مصدر حالة ثانٍ ولا مواعيد أو وعود تكلفة.

المرفق Blueprint مادة نقاش، لا مرجع اعتماد. لا نفترض اعتماد 48 سؤالًا أو أربعة أنواع أو بنك Training جديد أو تحليلات مهارات أو لجنة محددة أو صفحة محاضر. الأنواع الأولى: single-choice وsimulator-part في مسار الأسئلة المنوعة، وfull-practical في مسار الفحوصات الكاملة المستقل. لا ندمج المسارين بقالب واحد دون قرار لاحق. لا صفحة «محاولاتي» منفصلة؛ السجل داخل Assess، والتدريب لا يتغير.

## تصميم تقني مقترح — ليس قرار مالك إضافيًا

- كيانات منفصلة: مجموعات وعضويات، إسنادات اختبار لمستخدمين، قوالب وإصدارات اختبارات، إصدارات أسئلة ومفاتيح خاصة، محاولات نشطة وإجابات مؤقتة، نتائج نهائية مختصرة. الأسماء وتوزيع الجداول تُحسم في مرحلة الأساس، وليست schema/API نهائية.
- نوع السؤال وإصداره صريحان، مع تحقق ومكوّن عرض ومصحّح لكل نوع. النوع غير المدعوم يُرفض بوضوح. الصور والأنواع المقبلة تُضاف بعقود وأدلة ترخيص ومراجعة؛ لا محرك عام افتراضي لكل نوع ممكن.
- بند المحاكي يربط case/definition version، الأدوات/عناصر المشهد المسموحة، المفاتيح القابلة للتغيير، القيم الثابتة ومعايير العلامة. يعيد الخادم تركيب الحالة ويتجاهل/يرفض تعديل غير المسموح؛ الحدود والأجزاء المترابطة تُراجع لكل بند.
- القالب والإصدار المعروض وترتيب بنوده ونقاطها تثبت للمحاولة. لا تعديل لنسخة مستعملة؛ إنشاء إصدار جديد. التحويل للسلم النهائي يحفظ الدقة حتى العرض، ونتيجة غير المحلول صفر. لا خصم سلبي جديد أو قاعدة نجاح عامة مفترضة.
- مفاتيح MCQ خاصة بالخادم. حجب العلامة عبر response/RLS أو دوال قراءة آمنة لا عبر إخفاء الواجهة؛ الطالب لا يقرأ الإجابات المؤقتة/النتائج المحجوبة بطرق بديلة. قواعد Practice المنشورة ليست سرية؛ Server scoring يمنع تزوير الدرجة لكنه لا يمنع الرجوع لمواد التدريب خارج الجلسة.
- عند الإتاحة تتوسع المجموعات لقائمة مستهدفين ثابتة مع منع التكرار؛ تغيير العضوية لاحقًا لا يغير الوصول. يظل فحص اعتماد الحساب والصلاحيات جاريًا. نقل الإدارة لمشرف لاحقًا يحتاج نطاق ملكية واختبارات عزل، لا اسم دور فقط.
- مخزن حالة لكل attempt/item، وخادم يملك الوقت وعدد المحاولات وقفل التعريض والتسليم. بدء/تعريض/تسليم بمعرّفات عمليات تمنع تكرار الأثر عند إعادة الطلب؛ المعاملات تمنع سباق نافذتين أو جهازين.
- دورة مقترحة: active → submitting → graded؛ expiry ينهي المحفوظ من الخادم حتى لو المتصفح مغلق. النتيجة النهائية وتثبيتها ذرّيان، ثم حذف الإجابات والإعدادات المؤقتة. فشل التصحيح يحتفظ بالمؤقت للاسترداد ولا يحوله لنجاح أو صفر افتراضي؛ مهلة تنظيف المحاولات المتروكة/فشل التصحيح تُحدد قبل الإطلاق.
- المحفوظ الموثوق هو ما أقرّه الخادم. لا وعد بقبول تعريض offline أو إجابات وصلت بعد المهلة بناءً على ساعة الجهاز. قبل التنفيذ ثبّت بروتوكول pending/ack/retry، رسالة الانقطاع وحدود التعديل والمهلة؛ الهدف عدم منح تعريض ثانٍ أو فقد تعريض ثبت بالخادم.
- السجل النهائي الأدنى: user/assessment/version، snapshot لاسم الاختبار ونوعه، submitted_at، earned/max والحقول التشغيلية اللازمة للإسناد وعدد المحاولات والحجب وexpires_at. لا إجابات أو قيم أو نتائج معايير دائمة أو سجلات أحداث تنسخها. لا تغير أسماء السجل القديم بسبب إعادة تسمية القالب.
- ستة أشهر من التسليم: حدد في العقد معنى الشهر التقويمي وUTC وحدود نهاية الشهر. نفّذ purge آليًا ومراقبة فشله، وسجل حذف أدنى لا يحتوي إجابات/علامات. النسخ الاحتياطية والتصدير والاستعادة تحتاج دورة موثقة وإعادة تطبيق الحذف؛ لا ندعي محوًا فوريًا للنسخ القديمة.

## مراحل التنفيذ بعد استئناف برمجي صريح

قبل كل مرحلة: اقرأ الحالة وأحدث القرارات، عرّف ميزانية ملفات فعلية ومعايير قبول، وغيّر حالة RAD-056 فقط بحسب العمل الحقيقي. لا تعتبر الميزانيات أدناه تفويضًا مفتوحًا. النطاق يستثني كود التدريب إلا إعادة استخدام/استخراج ضروري مثبت بلا تغيير سلوك؛ لا فحوص أو صور جديدة.

| المرحلة المرتبة | النطاق وميزانية الوحدات المقترحة | شرط الخروج والتحقق |
|---|---|---|

| B — المجموعات والإسناد | ترحيلات إضافية مستقلة، RLS/RPCs، إدارة مجموعات/عضويات وإسنادات من لوحة المالك. لا دور مشرف فعّال أو استيراد قوائم | اختبارات مستخدمين منفصلين، رفض الوصول المباشر غير المسند، عضوية متعددة وتكرار إسناد وتثبيت المستهدفين؛ فحص تغيّر العضوية والاعتماد. قراءات مصفحة بالخادم، لا تحميل جميع الطلاب |

## التحقق المطلوب أثناء التنفيذ

- اختبارات منطقية للأجزاء والنقاط والدقة والإصدارات، ومعايير Marker المنفصلة، واستبعاد غير المطلوب والأخطاء الحرجة الخارجة عنه.
- اختبارات DB/خدمات بهويات متعددة تشمل محاولات الوصول المباشر للمفاتيح والدرجات والطلاب/المجموعات الأخرى؛ واجهة الإخفاء ليست دليل عزل.
- اختبارات دورة المحاولة: شبكة منقطعة، انتهاء الوقت والمتصفح مغلق، طلبان متزامنان، إعادة إرسال تعريض أقرّه الخادم، فشل التصحيح والحذف والاستعادة. رفض إجابة بعد التسليم، وتثبيت إصدار قديم رغم تحديث المحتوى.
- حراس التدريب القائمون، بما فيهم [characterisation](../src/features/qa/characterisation.test.ts) واختبارات scoring/marker/store والأسر المتأثرة، دون إعادة توليد hashes أو تغيير توقعات لإخفاء فرق.
- full check/build وفحوص المتصفح المطلوبة EN/AR على390/1440 وإمكانية الوصول عند نهاية دفعة المنتج؛ لا تكرار فحص ناجح بلا تغيير/سبب. الاختبار المحلي لا يثبت مزوّدًا حيًا أو مراجعة طبية.

## Scale والقرارات التقنية المتبقية

- لا قوائم طلاب/أسئلة/اختبارات غير محدودة في المتصفح؛ paging وفهارس وقيود أحجام يثبتها عقد المرحلة A ثم قياسات B/C. لا نعد بسعة أو Free قبل القياس.
- نوعان أوليان في مسار الأسئلة اختيار نطاق، لا enum مغلق في التخزين لكل المستقبل. صلاحية owner/participant الحالية لا تعني وجود instructor؛ لا نضيف الدور حتى نطاقه وتحققه.
- اختيار runtime، جدولة expiry/purge، قابلية مراجعة المصادر، بروتوكول إجابات الشبكة غير المتزامنة، قواعد الأشهر التقويمية، cleanup للفشل والمتروك، وموافقة/نسخ/حذف O106: مخرجات مراحل A/C/F، لا قرارات محسومة بالـBlueprint.
- بعد حذف التفاصيل لا إعادة تصحيح أو مراجعة اعتراض على مستوى السؤال أو تحليل مهارة. هذا قيد منتج مقبول؛ لا يضيف نموذج لاحق الاحتفاظ التفصيلي لتسهيل التحقيق دون قرار جديد.

## نقطة الاستئناف

التوثيق الحالي أذن به المالك؛ تنفيذ المنتج لم يُستأنف بهذا الإذن. الخطوة التقنية التالية عند استئنافه صراحةً هي **A**، لا صفحة «محاولاتي» ولا بدء D مباشرة. اقرأ [AGENTS](../AGENTS.md)، [HANDOFF](HANDOFF.md)، [الحالة](project-status.md)، [القرارات](DECISIONS.md#assess-owner-2026-10-19) وهذه الخطة؛ اعرض نطاق ملفات المرحلة قبل التحرير. لا تعِد طلب اعتماد قرارات المنتج المحسومة. تقرير الدفعة [هنا](ASSESS_DOCS_REPORT_2026-10-19.md).
