# RAD-085 — دليل mini DB day B على الهاتف

هذه حزمة **للعمل اليدوي بواسطة المالك بعد المراجعة**، وليست سجل تنفيذ حي. الوكيل لم يشغّل SQL حيًا. المصدر الحي المفترض هو M1–M4 والمُهيّئ المكتملان يوم2026-10-28؛ لا تعِد تطبيقهما أو إصلاح DB day السابق. الفرع مبني على main بعد #150. [قاعدة الهاتف](DECISIONS.md#rad085-mobile-sql-owner-2026-10-28) و[قرار A/B](DECISIONS.md#rad085-p1-usability-owner-2026-10-28) مستمران.

التغيير الوحيد هو ترحيل [B](../supabase/migrations/20261028000100_p1_short_codes_names.sql): CREATE OR REPLACE لثلاث دوال قائمة. لا جداول/أعمدة/منح أو قبول موافقة أو backfill أسماء. [التقرير](RAD-085_P1_USABILITY_B_2026-10-28.md) يحفظ التحقيق وQA وحدوده.

## التحضير وقاعدة اللصق

افتح [حزمة الهاتف المولّدة](RAD-085_P1_B_PHONE_PACKET.md). لكل عملية مستقلة امسح المحرر واجمع **كل أجزاء العملية في استعلام واحد قبل التنفيذ**. في التطبيق والتراجع اجمع الخطوات الخمس بالترتيب من begin إلى commit ثم شغّل مرة واحدة؛ لا تنفّذ جزءًا ولا commit مبكرًا. الخطوات الثلاث الوسطى كل منها سطر DO واحد بلا newline، وداخلها base64 لتعريف PostgreSQL النظيف. لا تستخدم SQL الترحيل متعدد الأسطر مباشرة على الهاتف. لا تفك الترميز أو تنسخ التفاف العرض كسطر جديد. فشل/انقطاع/نتيجة غامضة يعني توقفًا وفحص تقدم/جاهزية، ولا إعادة عمياء.

كل جزء أقل من15000 حرف **شامل الغلاف**؛ المولّد يرفض السطر/الدالة الأكبر ولا يقسمها عشوائيًا. أي صعوبة في تجميع المعاملة أو تجاوز السقف تتوقف إلى مسار RAD-082 على اللابتوب/CLI؛ لا حل بإزالة حارس. الدوال تشترط launch_gate مغلقًا، ووجود التوقيع، وبصمة M4 أو B المعروفة فقط، ثم تطابق OID وowner وACL وconfig والبصمة الجديدة. لذلك لا يصلح التراجع لإصلاح انجراف مجهول. لا تُعدّل pins لقبول انجراف حي.

## تسلسل التطبيق

1. أوقف استعمال P1 مؤقتًا بالتنسيق مع حسابَي الاختبار؛ لا SQL لتغيير متغيرات أو فتح launch_gate. شغّل الفحص المسبق: البوابة مغلقة، M1/M4 والمُهيّئ مطابقون، ولا جلسة active/grading/grading-failed. سجّل إصدار PostgreSQL (الحي المبلّغ17.11، الإثبات المحلي18.4). أي false أو null أو خطأ يوقف العملية للتشخيص المنقح.
2. شغّل جاهزية **قبل B** كما هي: يجب13 صفًا كلها true. القيمة الافتراضية initialized؛ لا تغيّر phase ولا تعِد المُهيّئ. احفظ الناتج الخاص.
3. احفظ أعداد كل جداول public/assess وauth.users، والنسخة الخفيفة للصفوف المتأثرة وتعريفات الدوال وowner/ACL/config. `export_complete_under_5000` يجب true؛ خلاف ذلك لا توجد نسخة مكتملة ولا تبدأ التطبيق. النسخة تضم أسماء وUUIDs وdigests وسجل الطلبات، ولا Auth/email/أجوبة أو رموز خام. تبقى نسخة خاصة مشفرة لدى المالك ولا تُرفع إلى Git أو المحادثة. سقف5000 صف/5ثوانٍ حد هاتف قابل للرفع عبر RAD-082 مع backup/restore مُراجع.
4. شغّل التقدم: البوابة true وكل دالة `m1_m4_exact=true` و`b_exact=false`. اجمع خطوات **تطبيق B** الخمس ثم نفّذ المعاملة مرة واحدة. لا DDL إضافي غير مشفّر مطلوب لهذه الدفعة.
5. شغّل التقدم ثانية: الثلاث `b_exact=true`. شغّل جاهزية **بعد B**:13/13 true. قارِن الأعداد والنسخة قبل أي استعمال جديد؛ التطبيق لا يغير أي صف بيانات. شغّل دخان الكتالوج؛ الحقول المنطقية كلها true. `codes_to_rotate_in_phone_test` معلومة، وليست نجاحًا سلوكيًا.
6. عند اكتمال هذه الأدلة فقط يضبط **المالك** `PILOT_SCHEMA_VERIFIED` إلى العلامة الكاملة أدناه. لا يغيّر الوكيل Variables أو ينشر يدويًا. CI/Pages المعتادان مطلوبان دون skip ci؛ لا تفتح/تشارك رابط معاينة مستضاف في التقرير. فشل Pages بالعلامة الحية القديمة متوقع قبل DB day، ولا يعني إذن تجاوز البوابة.
7. بعد قرار المالك بشأن الدمج/المسار المعتاد، نفّذ دخان الهاتف أدناه. لا تضع العلامة قبل DB day. يبقى PR Draft حتى قرار لاحق صريح؛ الحزمة ليست إذن ready/merge للوكيل.

```text

```

العلامة الحية السابقة للرجوع إلى واجهة A/M4 فقط:


## دخان الهاتف بحسابَي اختبار

المشرف المعيّن ينشئ مجموعة أو **يدوّر رمز المجموعة القائمة**: يظهر8 رموز من `0123456789ABCDEFGHJKMNPQRSTVWXYZ`، يُنسخ/يُشارك ثم «تم». الرمز القديم ذو64 hex **لن يُقبل بعد B**؛ لا يمكن تحويله من digest، ولذلك التدوير لازم للمجموعات القائمة. لا تُنهِ مجموعة لمجرد تحديث الرمز. يرسل الطالب الرمز بحروف صغيرة مع مسافة وشرطة؛ يظهر اسم المجموعة في «طلباتي»، ويظهر اسمه الثلاثي للمشرف في الطلب المعلّق. الموافقة ثم محاولة Practice جديدة بعد الانضمام تُظهر اسمه في الأعضاء والتدريب. افحص صفحة ثانية إن توفرت بياناتها؛ الاسم لا يعتمد على صفحة الأعضاء. الحساب القديم بلا اسم يظهر «الاسم غير متاح» فقط، ويمكنه تعديل اسمه من الحساب؛ لا UUID أو بريد بديل.

اختبر السحب/المغادرة وإخفاء التدريب، تدوير الرمز ورفض السابق، رفض حساب/مجموعة خارج النطاق. لا تُرهق حساب الاستخدام بتجارب التخمين: حد10 محاولات/ساعة يشمل الإدخال الخاطئ. إعادة الاختبار بعد انتظار النافذة فقط؛ لا SQL لتصفير throttle. لا تسجّل أسماء حقيقية أو رموز/توكنات أو صورها في Git. تُرسل نتائج PASS/FAIL المنقحة فقط.

## التراجع الآمن

قرار التراجع للمالك؛ الحزمة لا تشغله تلقائيًا. احتفظ بنافذة الصيانة والبوابة المغلقة. شغّل التقدم وجاهزية B أولًا؛ إن كانت البصمات مجهولة فلا تُجبر التنفيذ. اجمع خطوات **التراجع** الخمس في استعلام واحد ثم شغّل مرة واحدة. تنقل تعريفات PostgreSQL النظيفة لـM1–M4 بـbase64 مع الحراس نفسها. لا drop ولا حذف صفوف أو إعادة isolation أو تعديل للمُهيّئ؛ التراجع الأصلي لـDB day السابق لم يتغير.

بعده: التقدم الثلاث `m1_m4_exact=true`، جاهزية M4 الأصلية13/13، الأعداد/الصفوف المحفوظة ثابتة، وlaunch_gate مغلق. أعد الواجهة والعلامة المتوافقتين A/M4 بقرار المالك عبر المسار المعتاد فقط؛ واجهة B تحتاج حقولًا ورموزًا لا يوفرها M4. الرموز ذات8 أحرف التي وُلّدت أثناء B لا يقبلها M4؛ دوّرها من واجهة A بعد استعادتها للحصول على64 hex. لا تُستعاد البيانات القديمة فوق تغييرات المستخدمين ولا يُستبدل digest من نسخة قديمة دون مراجعة منفصلة.
