## 2. المنجز والمستبعد

أضيفت مجموعات متعددة العضوية، إضافة جماعية للطلاب المسجلين، وتعديل/حذف المجموعة. الإسناد يختار إصدارًا متاحًا ويثبت union للطلاب والأعضاء مع dedup ذري. تغيير/حذف المجموعة لاحقًا لا يغير المستهدفين؛ الإضافة والسحب الصريحان يتطلبان revision مطابقًا مع قفل الصف. إسناد واحد لكل نسخة/مالك يمنع إعادة استدعاء assign من إنشاء مسار آخر يتجاوز سياسة المحاولات المستقبلية؛ تكرار الإسناد يوجه لإدارة المستهدفين. قراءة metadata للطالب تتحقق من الاعتماد والإسناد الجاري، دون محتوى أو علامة.

واجهة المالك عربية/إنجليزية، بحث بالاسم/البريد وصفحات خادمية واختيار محدود عبر الصفحات. القسم مغلق افتراضيًا ولا يطلب Assess حتى فتحه؛ لا يظهر للطالب. نقص schema/RPC يعرض عدم توفر الخدمة محليًا دون نصوص أخطاء خاصة، ولا يستبدل صفحة إدارة الحسابات أو التدريب. المفاتيح الرسمية لا تدخل المتصفح؛ نسخة metadata لا تحمل مفاتيح أو أسئلة أصلًا.

لا دور instructor أو استيراد أو انضمام ذاتي؛ لا إنشاء محتوى أو محاولات/تعريض/تصحيح/نتائج أو مهام حذف. versions metadata فقط، بلا بيانات seed أو endpoint يجعل محتوى طبيًا متاحًا. العينات كلها اصطناعية ومحلية؛ إدارة المحتوى وبوابة نشره لاحقتان. لم تطبق الدفعة البرمجية الأصلية ترحيلًا أو exposed schema على الإنتاج. متابعة المالك اليدوية المأذونة بتاريخ2026-10-20 موثقة أدناه؛ لا بيانات اختبار أو طلاب زرعتها الأداة.

## 4. التغييرات المشتركة وScale

التغييرات المشتركة محصورة في تركيب المكون بعد قائمة المالك وإضافة namespace ترجمة. لا تعديل محرك/scoring/store/marker أو التدريب والكاتب والقراءة أو ملفات/منح/سياسات public. اختبار SQL يقارن بيانات التدريب وتعريفات الدوال وACL والأعمدة والسياسات والمنح حرفيًا قبل/بعد B. حراس السلسلة القديمة ظلت تعمل على كل الترحيلات دون تغيير توقعاتها.

schema assess: خمسة جداول RLS default-deny بلا منح مباشرة، وست دوال SECURITY DEFINER ببحث فارغ ومنح تنفيذ authenticated فقط، مع فحص الاعتماد/دور المالك والملكية لكل عملية. مالكان لا يديران مجموعات/إسنادات بعضهما؛ لا يستطيع الطالب قراءة الأعضاء أو الطلاب أو النسخ غير المسندة عبر RPC أو قراءة الجداول مباشرة. [إعداد المزوّد](PILOT_SUPABASE_SETUP.md#assess-b-setup) يشرح ضرورة exposed schema مستقبلًا وحارس التوافق؛ لم نُعط تجاوزًا لحارس النشر أو منح table/anon.

Scale: keyset UUID ثابت، صفحة خدمة≤100 وواجهة20، طلب كتابة/اختيار≤100طالب/مجموعة، مجموعة/إسناد≤10000؛ التوسعة خادمية وإدراج≤10001لرفض التجاوز ذريًا بدل truncation ناجح. فهارس الربط والملكية موجودة. ليست صفحات القراءة snapshot؛ search والتوسعة والعدّ ضمن الحدود تحتاج قياسًا قبل زيادة السقف، ولا وعد Free أو أداء حي. نوع النسخة مفتوح في التخزين مع رفض unsupported في RPC، والإصدارات مستعملة بوصفها immutable عبر الخدمات المستقبلية؛ لا UPDATE أو إدخال metadata من المتصفح.

## 7. المتبقي

الخطوة الفورية: تشغيل [أداة خدمة Assess](../scripts/pilot/assess-service-check.js) من حساب المالك وطالب معتمد والتحقق من زوج PASS، قبل تحديث إثبات النشر وإعادة workflow. أتم المالك تطبيق SQL وفحص catalogue وأفاد بحفظ إتاحة schema؛ Data API بحسابين ما زال غير متحقق. موافقة/احتفاظ O106 قبل بيانات اختبار حقيقية باقيان. PGlite ليس إثبات استضافة أو race بين اتصالات مستقلة. نافذة قفل المجموعة تسلسل تغييرات العضوية مع expansion؛ تحقق معاملات/انقطاع دورة المحاولة في C. النسخ/الحذف O106، مصادر ومراجعة المحتوى O108، الـruntime والجدولة وadapter الماركر من A لم تُعتبر محلولة بالنشر أو بهذه الواجهة.

يتطلب C خدمة نشر محتوى تتحقق من immutable refs وrubrics/private keys، ثم المصادقة والتوقيت وattempt limits ومنع تكرار التعريض والتسليم؛ لا يجوز تشغيل محاولات حقيقية باستدعاء metadata الموجود في B. سحب إسناد أثناء محاولة نشطة يحتاج تطبيق بروتوكولها قبل C. لا هاتف أو أداء مزود حي متحقق هنا؛ تطبيق المالك للترحيل ليس إثباتًا لجميع مسارات الإنتاج.
