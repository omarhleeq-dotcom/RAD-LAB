## 4. المشترك وScale

صيغة1.2 وقالب المهمة الإنجليزي والسقوف وفهرس القواعد حاضرة. HANDOFF ملخص بخمسة بنود، والمالك القديم في بند الانتظار، وقسم الإغلاق مؤشر أمر واحد. AGENTS يعرّف filler مرة ويُلزم sync قبل الفحوص. الزيادة في DECISIONS فهرس وإضافات فقط؛ لا نقل/حذف/إعادة تسمية anchor أو إعادة صياغة entry.

التعليمات القديمة التي أضيفت إليها Superseded by محدودة: blueprint الموضوع/الصعوبة ← random-question-pool؛ قيود apply واختيار Supavisor التصميمي فقط ← rad086-followup؛ قائمة HANDOFF لكل مهمة فقط ← workflow-hardening. النصوص الأصلية محفوظة؛ [دليل كل نطاق](RAD-090_DETAILS.json) يحدد العبارة اللاحقة الصريحة. لا تعميم للاستبدال على بقية entry.

L1 قراءة gh فقط لحالة كل طلب مرتبط وفحوص رأسه؛ unverified وexit0 عند التعذر. L2 يصلح الميكانيكي فقط: الروابط/source_ref كمؤشرات، فهرس reports، المؤشر، أرشفة M2 وrevision/time الناقصين أمام --base. يحفظ زيادات revision المسجلة، فلا يرفعها في كل تشغيل. لا تعديل completion_evidence أو قيم الحالات أو نص القرارات؛ لا كتابة bot أو Action إلى main.

حد Scale: تعرف rename من Git وتحليل lexical للروابط لا تحليل JavaScript عام؛ المراجع المقفلة تبقى مثبتة، والعنوان الطويل في الاختصار الآلي يوقف المزامنة بدل اختراع نتيجة. فحوص gh تخص الرأس والفحوص المعروضة؛ غيابها أو skipped/neutral لا يصبح نجاحًا. تغيير سقف يحتاج قرارًا جديدًا، والتحقق البنيوي من سجل القرار لا يثبت سلطته آليًا. المحفز: مراجعة بشرية عند rename غير معروف أو شرط غامض، دون رفع سقف أو توسيع أتمتة صامت.
