مراجعة داخلية جديدة للتنفيذ والتوافق، **ليست مراجعة أمنية مستقلة أو اعتمادًا سريريًا**. الهدف تدقيق الثلاثة والجسر، إصلاح المثبت، وتجهيز [حزمة التطبيق](RAD-085_APPLICATION_PACKET_2026-10-26.md) دون مزوّد حي. لا تعادل نتيجة محلية أو CI إغلاق بوابات المراجعات الخارجية أو قبول المالك/الهاتف.

بدأ checkout `work` نظيفًا عند `31e9cbfba6574a9e87b59d47a687f99864c74b21`، وشُغّل docs:context وstatus:summary وفُحصت الشجرة والفروق قبل تحديثها. أكد GitHub مباشرة #137 open/Draft/unmerged، ورأسه `99bc07c72544ffb3a40c12b98c23a415b7d26246` مطابق للرأس المذكور. جُلب الفرع وتقدم checkout نفسه fast-forward؛ جُلب main أيضًا. لا reset/clean/stash أو worktree/subagents. تعديلات جلسة الهاتف الغائبة لم تُستعد أو يُدّعَ وجودها، ولم تعطل المراجعة.

أُعلنت المخاطر قبل الإصلاح: مهلات ما بعد الأقفال، حذف الحسابات/الاحتفاظ، صلاحيات الجسر، والفشل بين معاملات مستقلة. الميزانية8ملفات، ثم9 بإضافة الفرق المقترح، ثم **12ملفًا** بعد موافقة المالك على الاستثناء الجديد **RAD085-SQL-AUDIT-EXPIRY-DELETE-20261026**. وافق نصًا «أوافق على الاستثناء المحدد» بعد تجهيز الفرق وتجربة الخللين وتصحيحهما صناعيًا، وقبل تحرير المصادر المحمية.

الملفات الاثنا عشر: هذا التقرير وحزمة التطبيق وملف الفرق والعقود وproject-status وHANDOFF؛ scripts/assess/rad085-security-rehearsal.mjs واختباره وrad085-application-inventory.sql؛ الترحيلان الأول والثالث وscripts/pages/frontend-schema.json. الوحدات المشتركة: عقود SQL والحالة والتسليم، وقناة content_submit_v1 بالحد المسمى فقط. الترحيل الثاني ومصادر الترحيلات التاريخية والاختبارات القديمة وrequiredMigrations/checks والشهادات وworkflows وpackage/lock لم تتغير.

## 3. حسب المهمة

RAD-085 تبقى review/waiting_on owner، بلا completion_evidence أو قبول مالك/هاتف أو إطلاق. تحققت دورة ترقية ونسخ/استعادة صناعية محددة؛ لا نسخ مزوّد فعلية أو O106/RAD-063 منجزة، ولا إغلاق لمراجعات التفويض/الأداء/المحتوى. RAD-060 وباقي المهام وحالاتها محفوظة.

## 4. العقود المشتركة والتدقيق وScale

### الأدوار وحدود الثقة

| الهوية | ما ثبت محليًا | ما لا يثبته |
|---|---|---|
| postgres/مشغّل fixture | مالك الدوال والجداول، superuser، ينشئ المخطط الصناعي وحزم SYNTHETIC فقط | دعم صلاحيات Supabase أو فصل إدارة حقيقي |
| authenticated | مستخدم التطبيق؛ auth.uid يحدد صاحب الجلسة؛ owner من profiles/is_owner فقط، والمشرف participant بتعيين منفصل | لا LOGIN خاص بالمشرف، ولا actor من جسم publish |
| anon | لا وصول مباشر للجداول/الجسر أو content_submit | مصادقة HTTP/JWT حية |
| assess_worker | NOLOGIN/NOINHERIT في المصدر التاريخي؛ منح وظائفه السابقة لم تتوسع، ولا عضوية للجسر | ليس tick-only؛ المثبتات/الصيانة/claim/recover السابقة تظل قدراته وفق عقودها |
| assess_authoring_bridge | NOLOGIN/NOINHERIT/NOSUPERUSER/NOBYPASSRLS/NOCREATEDB/NOCREATEROLE/NOREPLICATION؛ صفر حواف عضوية محلية؛ usage assess وEXECUTE على content_submit وأربع wrappers فقط | NOLOGIN وحدها لا تمنع عضوًا آخر من SET ROLE؛ أي LOGIN منتج وتفويضه وإبطاله يحتاج مراجعة مستقلة |

اختُبر SET ROLE من **session authorization** محدود لـanon/authenticated/worker، لا من جلسة postgres التي تستطيع تبديل كل الأدوار. رُفضت قراءة draft/package/link المباشرة للأدوار الأربعة، وإضافة الجديد لم توسع صلاحيات worker على الدوال التاريخية أو الجديدة. بقية مصفوفة API/RLS الداخلية ورفض إدارة الحسابات/surveys للمشرف يغطيها rad085-db واختبارات الجسر القائمة، وأُعيدت في فحوص المشروع.

قراءة المصادر شملت ثلاثية RAD-085، تعريفات B–F/retention والحذف C2، مصادر جسر TS/PG والمثبتات وvalidators، وتقارير SQL/P1/P2 والجسر والعقود، وخريطة القراءة والاحتفاظ والتشغيل والتحضير والعزل وهوية العامل. SECURITY DEFINER الجديدة search_path فارغ وأسماء جداول/دوال التطبيق مؤهلة؛ كائنات pg_catalog المضمنة تُحل عبر البحث الضمني. منح PUBLIC/anon/worker للأجزاء الداخلية مسحوبة؛ المالك الإداري يستطيع تجاوز RLS/تعديل الدوال، فيبقى ضمن حدود الثقة ولا يوصف مستخدمًا مقيدًا.

postgresAuthoringBridge يأخذ connect/identity/group من المضيف الموثوق؛ publish يأخذ draft/revision فقط. ضبط request.jwt.claim.sub داخلي وليس تحقق JWT بحد ذاته. لا actor/digest/حزمة مراجعة مخولة من المتصفح. من يستطيع استعمال LOGIN بامتياز SET ROLE للجسر يستطيع اختيار claim داخل القناة الموثوقة؛ حماية ذلك LOGIN والمضيف شرط وليست ضمانًا تصنعه NOINHERIT.

### التوافق والمطابقة والذرية

قورنت content_submit_v1 التاريخية الفعالة في E بما بعد الثالثة. بقيت خطوات فرع المالك العادي نفسها: profile FOR UPDATE وowner-only، حجم/metadata، advisory لكل assessment، منع takeover وحدpending20 وإنشاء immutable candidate. الاستثناء الوحيد في المقطع المشترك شرط ختامي للـgid غير الفارغ، وهو معين لفرع الجسر فقط. نُفذ المساران mixed/full-practical للمستخدم المأذون قبل/بعد، ورفض participant/anon/worker والتكرار/metadata غير المدعومة/المالك المعلّق. لا ادعاء أن أي participant مأذون بالنشر المباشر؛ القناة القديمة أصلًا owner-only.

المسودات القديمة/المجموعات/العضوية وPractice بقيت دون backfill أو قبول مستنتج. validate_draft تحقق بنيوي يسمح بالمسودة الناقصة ولا يصنع اعتمادًا. المراجعة المستقلة الخاصة تربط revision/digest؛ TS يطابق المفاتيح والمحتوى والمراجع والإصدارات ويعيد validators القائمة، ثم candidate/install/bind بمعاملة READ COMMITTED واحدة. لا تغيير في خوارزمية تقييم أو مثبت موازٍ. المنح الداخلية تعتمد ثقة المضيف والـvalidators؛ ليست SQL sandbox تعيد التحقق من كل specs/geometry يرسلها مضيف مخترق.

ترتيب الأقفال: scope ثم profile ثم draft ثم references/package ثم candidate/version/assessment؛ القنوات الجديدة تتشارك scope العالمي. مسارات الإدارة والتاريخية لا تتقيد كلها بـscope، لذلك تظل profile/version/FK locks وشروط المزوّد والمراجعة الإدارية ضرورية. أُضيفت إعادة وقت/تفويض بعد الانتظار دون تغيير مستوى العزل. rollback بين التثبيت والربط، والتنافس والتكرار وACK المفقود والمصالحة بالقراءة والإسناد الذري موثقة باختبارات server-authoring-bridge-db وrad085-db القائمة؛ لا إعادة mutation آلية أو zero grade بعد فقد ACK.

### القياس المحلي

PostgreSQL18.4 المضمنة المقفولة، Unix sockets في أدلة0700 وlisten_addresses فارغ؛ بيانات صناعية بأربعة حسابات ومجموعة قديمة ومجموعة مدارة وPractice قديم ومسودة/مرجع وحزمة هندسية. حتى ثلاثة اتصالات فعالة في شاهد القفل، وcluster ثانية للاستعادة، دون TCP/TLS أو JWT/PostgREST أو مصادقة مزوّد. تعطيل trigger نافذة المجموعة في fixture فقط ضبط موعد اختبار، لا مسار منتج.

في تشغيل القياس: انتظار reference نحو1055ms حتى تجاوز الموعد؛ القفل العالمي منع RPC مستقلًا للموافقة ثم اكتمل بعد تحريره، نحو15ms إجمالي شاهد الانتظار، **ليس latency/throughput مضمونًا**. حجم القاعدة الصناعية نحو11.24MB، وأرشيف custom نحو316KB. الأرقام من قاعدة قليلة الصفوف وبلا صور/بيانات تشغيل؛ لا استنتاج120مستخدمًا أو FREE أو RPO/RTO.

السقوف باقية: صفحات20/max100،1000عضو،5مسودات×100revision×128KiB نص مستند، وحزمة مراجعة≤128KiB لكل revision؛ نحو64MiB نص revisions ومثلها packages لكل كاتب عند السقف قبل JSONB/refs والفهارس والنسخ والمنشورات. انتهاء مجموعة لا يحرر تلقائيًا حصة المسودات؛ هذا قرار احتفاظ/محو، لا عامل تنظيف أُضيف هنا. رفع الحمل يحتاج قياس قفل عالمي وحجم/تكلفة وعلاجًا مراجعًا عند بلوغ السقف.

## 6. التحقق والتعافي وحدود الأدلة

حاضنة [security-rehearsal](../../scripts/assess/rad085-security-rehearsal.mjs) واختبارها مستقلان عن جرد/شهادات التاريخ، ولا يقبلان URL أو مدخل اتصال/credential. اختبار المصدر المصحح واختبار الرأس المثبت كلاهما ناجحان؛ يشملان فشلًا محقونًا قبل COMMIT لكل ترحيل، مع ROLLBACK صريح ثم التحقق من حالة الكتالوج في نفس الجلسة بعد الخروج من المعاملة الفاشلة:

| فشل الملف | ما يبقى مثبتًا |
|---|---|
| الأول | لا شيء من الثلاثة |
| الثاني | الأول فقط |
| الثالث | الأول والثاني فقط |

ثم أُكملت الترقية بالترتيب واختُبر التوافق. هذه تجربة فشل داخل المعاملة، لا محاكاة crash/فقد ACK عند COMMIT للمزوّد. حزمة التطبيق تفرض فحصًا من اتصال جديد عند عدم اليقين ولا تفترض إلغاء الأولى والثانية بفشل الثالثة.

النسخ بأدوات PostgreSQL18.0 (`pg_dump -Fc` وpg_dumpall roles-only/no-role-passwords وpg_restore exit-on-error) إلى cluster18.4 أخرى؛ مقارنة كاملة للبيانات الصناعية، حالة التسلسلات، الأدوار/العضويات، RLS/policies، ACL والدوال وsearch_path والقيود والمشغلات والفهارس والمنح الافتراضية والمخططات. قورنت ACL الافتراضية عبر acldefault وdeparser القيود بوضع pretty لأن النص الخام قد يختلف مع بقاء الدلالة. لم يُستبعد قيد أو منحة لتجاوز الاختلاف. الأرشيف الصناعي غير مشفر داخل tmp0700 ثم حُذف؛ لا إثبات تشفير نسخ تشغيلية أو RPO/RTO أو نسخ مزوّد. إنشاء قاعدة الوجهة وACL/settings الخاصة بها منفصل عن dump بلا --create.

فشل أول تجهيز لأدوات pg_dump لغيابها من الحزمة المضمنة؛ بُنيت أدوات العملاء من مصدر PostgreSQL REL_18_0 في/tmp مع أدوات flex/m4 محلية مؤقتة، بلا تعديل نظام أو حزم المشروع. فشل أول استيراد globals لأن pg_dumpall18 ينتج أوامر psql restrict؛ حُذفت توجيهات restrict/unrestrict فقط وCREATE ROLE postgres القائمة من **ملف الأدوار الصناعي المؤقت** قبل إرساله عبر pg. هذا ليس إجراء استعادة globals للمزوّد. مقارنة ACL/constraint النصية الأولى أظهرت فرق تمثيل، فعولجت مقارنة المعنى كما سبق. لا فشل استعادة مخفي أو تغيير توقع قديم.

إعادة الشاهد تتطلب Linux x64، إعداد `node scripts/assess/setup-rad085-postgres.mjs`، وعميلات PostgreSQL18 مبنية/موثوقة في مسار `toolsDir` المعلن داخل الحاضنة (مصدر هذا التشغيل `/tmp/rad085-pgtools/postgres-REL_18_0/src/bin/pg_dump/`، الأدوات الثلاث pg_dump/pg_dumpall/pg_restore). اختيار binaries محلي وليس إعداد اتصال. ثم:


لا QA واجهات معاد لأن الواجهات لم تتغير. لا هاتف أو اختبار إطلاق أو crash storage أو استعادة مزوّد. أغلقت الحاضنة كل clusters والاتصالات وحذفت الأرشيفات الصناعية في finally؛ لا خادم مراجعة أو عامل شُغل. دليل CI وتخطي Deploy على الرأس المدفوع نفسه يُحفظ في وصف PR بعد التحقق المباشر، دون commit توثيق لاحق يغير الرأس؛ لا نجاح مستنتج قبل اكتماله.

## 7. الباقي وشروط التطبيق

المتبقي ذو الأولوية: احتفاظ/محو الروابط والمراجعات والحسابات المرتبطة، مراجعة ACL/التزامن مستقلة ودعم المزوّد/مالكي الدوال، مخزن مراجعات ومسؤول إدخال وأدلة محتوى حقيقية، سياسة مشاركة وقبول الذات، هوية نقل وإبطال حي، نسخ مزوّد واستعادة وحمل/تكلفة، ومراجعة المالك P1/P2 والهاتف. حزمة التطبيق تعطي شروط المتابعة/التوقف وإعدادات تظل مغلقة؛ لا وثيقة «نجاح محلي» تفتح launch_gate أو تمنح LOGIN.

## 8. قائمة المالك والخطوة التالية

الاستثناء المسمى أُجيب ونُفذ محليًا؛ لا يعاد طلبه. القرارات الضرورية اللاحقة وتوصية كل منها في حزمة التطبيق: مسؤول إدخال مستقل مسمى، إجراء احتفاظ/محو مراجع، نص مشاركة ومضيف نقل موثوق وإبطال LOGIN/pooler/cache. لا حاجة للابتوب لإكمال هذه الحزمة المحلية، لكن التنفيذ الحي وتجربة المالك والهاتف خطوات منفصلة.

الاستئناف: اقرأ AGENTS وHANDOFF والتقرير والحزمة والعقود؛ تحقق مباشرة من #137 open/Draft/unmerged والرأس. جهّز تصميم هوية الجسر المحدودة وإبطالها باختبارات محلية منفصلة عن العامل، ثم مطابقة worker/case/evaluator وIAM/STOP والتكلفة والنسخ قبل أي إذن تشغيل. لا SQL حي أو عامل أو جدولة أو preview/tunnel أو variables/shares/قبول مشاركة أو ready/merge/auto-merge.
