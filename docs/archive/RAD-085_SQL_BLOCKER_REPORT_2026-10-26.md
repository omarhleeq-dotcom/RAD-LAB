# RAD-085 — توقف SQL عند توقع حارس الشهادة

## 1. الانحرافات والميزانية

هدف الجلسة الأصلي SQL محلي مجمع للمشرف وP1/P2 وعقود الربط. توقف قبل التنفيذ وفق أمر المالك: «أي استثناء لتوقع قائم يجب أن يكون مسمى ومأذونًا؛ إن لم يكن، توقف عنده وبلّغني». الميزانية المعلنة بعد اكتشاف العائق أربعة ملفات فقط: هذا التقرير و[الخطة](../RAD-085_PLAN_2026-10-25.md) و[الحالة](../project-status.md) و[HANDOFF](../HANDOFF.md). لا ملفات SQL أو اختبارات أو وحدات مشتركة معدلة. لم تُستكمل دفعة SQL المطلوبة.

استُخدم checkout نفسه دون worktree أو subagents. جُلب main ورأس PR #137 صراحة؛ تحقق GitHub من open/Draft/unmerged. الرأس الفعلي `042126de4f883889ccfa716d36aaad0af365b161`، وmain `31e9cbfba6574a9e87b59d47a687f99864c74b21`. بدأ checkout من main، فظهرت unknown task لـRAD-085 قبل الانتقال؛ بعد الانتقال ظهرت المهمة. محاولة switch مع tracking لم تنجح بسبب إعداد remote المحدود؛ استُخدم --no-track في checkout نفسه وأصبحت الشجرة نظيفة قبل تحرير الوثائق. لا استنتاج نشر أو تشغيل من Git.

## 2. المنجز والمستبعد والجرد الأولي

سُجل قرار المالك الجديد بتاريخ2026-10-26 بتوقيت Asia/Amman: تأجيل مراجعة P1/P2 والهاتف إلى ما بعد SQL والربط الفعلي وتجهيز نسخة متصفح قابلة للمراجعة. لم تحصل مراجعة أو موافقة. استُبدل شرط المراجعة قبل SQL في نقاط الاستئناف الحالية، وحُفظت التقارير التاريخية دون تعديل.

| الموجود | المطلوب لاحقًا ضمن الإذن |
|---|---|
| assess.groups وmemberships وversions وassignments وtargets في ترحيل B | امتداد التفويض والفترات والنوافذ والرموز والطلبات دون إعادة إنشاء الجداول |
| profiles بدوري participant/owner، وis_owner/is_approved | تعيين وسحب مشرف منفصل دون تغيير معنى owner أو صلاحيات إدارة الحسابات |
| close_assignment_v1 وclosed_at في retention | تفويض محدود وإسقاط حالة الإغلاق وعقد ربط RAD-060، دون إعادة بناء الإغلاق |
| Practice started_at/finished_at قابلان للإرسال من العميل | وقت تسجيل خادمي موثوق؛ لا backfill يوحي بوثوق التاريخ القديم |
| عقود ومهايئات P1/P2 اصطناعية في الذاكرة | مسودات مستقلة ذات ملكية وrevision ومراجع، snapshot ذري للمستهدفين والنسخ والصلاحية وإعادة تحقق عند التأكيد |
| consents وconsent_v2 وحارس جلسة قائم | موافقة المشاركة المطلوبة والتحقق الخادمي عند الربط، دون قبول نيابة عن الطالب أو تغيير CONSENT_VERSION |
| قارئ PostgreSQL محلي Unix socket في local-database.mjs | اختبارات سباقات متعددة الاتصالات ببيئة معزولة؛ حزمة PostgreSQL الخارجية الافتراضية غير موجودة بهذه البيئة عند الفحص |

قُرئت البداية وخريطة القراءة والخطة وتقارير الواجهات والعقود والـadapters، ورُوجع ترحيل B ووقت Practice والموافقة وسطح retention وحراس الترحيلات والشهادة. هذا جرد أولي توقف عند الحارس؛ لا ادعاء اكتمال تدقيق كل دالة أو مرجع. يجب استكمال القراءة التفصيلية قبل SQL. لا قائمة ترحيلات جديدة أو ترتيب تطبيق: لم يُنشأ أي ترحيل. التاريخ المطبق لم يُعدّل، ولا دالة أو constraint أو trigger قائم تغيّر.

## 3. حسب المهمة

RAD-085 تبقى review / waiting_on owner دون completion_evidence؛ انتظار الاستثناء المسمى أدناه، ثم استكمال SQL والربط والمراجعات والقبول. RAD-060 لم تتغير: لا SQL أو عقد ربط أو زر جديد منفذ بهذه الجلسة. بقية المهام محفوظة؛ لا إغلاق للصلاحيات أو التشغيل أو النسخ أو الربط.

## 4. المشترك وScale والعائق المحدد

لا تغيير وحدات مشتركة أو حراس أو ceilings. صفحة20 و200بند و128KiB ومسودة fixture الحالية في الذاكرة أدلة نطاق محلي فقط؛ لا ضمان سعة إنتاج. حدود FREE وreceipts وPractice والنسخ والقياس في الخطة باقية.

[frontend-schema.json](../../scripts/pages/frontend-schema.json) يصف متطلبات الواجهة الحالية، وdeferredMigrations فيه فارغ. [pilot-schema-gate.mjs](../../scripts/pages/pilot-schema-gate.mjs) يرفض كل migration جديد خارج requiredMigrations ما لم يسجل hash وreason وserverModules ضمن deferredMigrations؛ نص الخطأ Unreviewed deferred migration. هذا تصنيف مصدر، وليس شهادة تطبيق حي.

[assess-f-schema.test.ts](../../src/features/deployment/assess-f-schema.test.ts) يفرض حرفيًا `expect(m.deferredMigrations).toEqual({})`. لذلك تصنيف SQL الجديد مؤجلًا عن الواجهة الحالية يصطدم بهذا التوقع. ترقيته إلى requiredMigrations يغير عقد SQL المطلوب للواجهة وعلامة التوافق، رغم أن الربط الحالي ما زال اصطناعيًا. لم يُستخدم هذا بديلًا لتجاوز التعارض.

**الاستثناء المحدد المقترح للموافقة:** السماح بتعديل توقع deferredMigrations الفارغ في اختبار assess-f-schema فقط، ليختبر قائمة ترحيلات RAD-085 المؤجلة المحددة وبصمات مصدرها وحدودها الخادمية وعدم وصول الواجهة إليها، مع إبقاء requiredMigrations/checks والشهادة الحالية وحراس التقييم ثابتة. أسماء الملفات والبصمات لا تُخترع قبل تنفيذها؛ تعلن ميزانيتها قبل التحرير. هذا مقترح غير منفذ، وليس إذنًا لتغيير توقعات أخرى أو توليد شهادة. لا حاجة لتخفيف بوابة المصدر؛ آلية التصنيف المؤجل قائمة بالفعل.

كذلك يفرض [migration-chain.test.ts](../../src/features/pilot-db/migration-chain.test.ts) حفظ بيانات وأعمدة وقيود public إلا استثناءاته المسماة؛ إضافة recorded_at مباشرة إلى attempts تستلزم مراجعة هذا الحارس. لم يُعتمد هذا التصميم أو يُطلب استثناؤه هنا؛ يمكن بحث سجل خادمي خاص في assess لتجنب تغيير الأعمدة المحمية. لا إخفاق اختبار فعلي مدعى؛ التعارض الحالي مثبت بقراءة المصدر قبل التحرير.

## 6. التحقق وحدوده

شُغل docs:context لـPR #137 وstatus:summary لـRAD-085 وRAD-060 ومهام Assess، وجُلبت المراجع وتحققت حالة PR عبر الموصل. دليل العائق قراءة مباشرة للتوقع والبوابة والmanifest؛ لم تُنشأ migration تجريبية في المستودع ولم يُعدّل التوقع لإظهار نجاح مصطنع.

فحوص الدفعة الفعلية: docs:check --base origin/main وstatus:check --base origin/main --require-previous وgit diff --check؛ نجحت جميعها في الفحص النهائي، وdocs:check بلا أخطاء أو تنبيهات مراجعة. كشف التشغيل الأول حذف مرساة المتابعة المطلوبة من HANDOFF؛ أُعيدت في الملف نفسه دون تعديل التقارير التاريخية أو الحارس، ثم أُعيد الفحص بنجاح. لا QA واجهات أو check/build أو docs:test لأن التغيير توثيق فقط. لا اختبارات SQL أو أدوار أو RLS أو تزامن أو PostgreSQL منفذة؛ هذه فحوص ضرورية للدفعة الأصلية وغير مكتملة، وبالتالي لا ادعاء نجاح SQL محلي. لا قاعدة حية أو Supabase أو شهادة أو تشغيل أو هاتف أو قبول أو CI مفترض.

## 7. المفتوح ومتطلبات التطبيق اللاحق

بعد الاستثناء المسمى: استكمال جرد الترحيلات والاختبارات والحراس، إعلان هدف وميزانية SQL دقيقة، ثم تنفيذ التفويض وRLS/ACL والعمليات المحدودة وفترات العضوية والرؤية الخادمية والمسودات والإسناد الذري واختبارها محليًا. اختبر المالك ومشرفين والطلاب المتداخلين وغير المسندين وanon والمعلق والمسحوب، والرفض المباشر وعدم التسرب قبل العد والتصفح، وسباقات القراءة/القبول/المغادرة/الإنهاء/السحب وإعادة الانضمام، وتعارض revisions والمراجع والصلاحية وثبات targets وتكرار الطلبات. PGlite المتسلسل لا يثبت التزامن.

عند وجود migrations جديدة، وثق أسماءها وترتيبها واعتمادياتها وفحص drift وخطة النسخ/restore والمراجعات قبل أي تطبيق لاحق مأذون. لا تطبيق أو DB day حي بهذه الجلسة. الربط الفعلي وعقوده والتعامل مع الأخطاء والتكرار وcache والموافقة والعامل المتطابق والنسخ والمراجعات والقبول والهاتف متبقية؛ لا تغيّر variables أو PILOT_SCHEMA_VERIFIED أو launch_gate أو CONSENT_VERSION.
