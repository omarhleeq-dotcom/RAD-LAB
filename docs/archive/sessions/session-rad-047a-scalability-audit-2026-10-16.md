## 5. Architecture, migration and privacy conclusions

**How growth reaches pilot storage.** New compatible exam/case: registry + composed RadCase → observing logger → buildAttemptRow → same attempts row; no exam CHECK/table. New modality/data type: same storage only if a real adapter emits an approved versioned shape within caps. No modality column is needed to save it, but historical exam→modality joins need immutable catalogue/releases; changing an id is not a translation. New language currently hits DB CHECK and writer coercion; proposed configured locales remove this storage ceiling, not translation work. New mode currently lacks provenance; stamp Practice before adding another writer. Instructor/org access is a distinct authorisation design, never granted by display-role text. Assess requires server-owned scoring and frozen rubric with answers withheld; saving client results is never sufficient.

**Owner reads/export.** Use Supabase SQL RPCs; static Pages needs no new runtime server. Owner guard once at RPC entry, fixed search_path and least privilege; participant requests reject even if they guess another user's id. Use bounded participant cards, lazy attempts/notes, server counts/filtering. Keep export endpoint contract separate from visible-page data and ordinary UI count. Projection excludes device/email/auth ids; SQL joins participant_code, note→attempt for number instead of joining truncated browser arrays. Preserve CSV quoting/BOM/formula guard and version the export manifest. Unknown JSON versions and API errors must be visible, never silently interpreted as complete.
