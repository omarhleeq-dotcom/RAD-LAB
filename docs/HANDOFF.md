# التسليم الحالي — تطبيق SQL E على الأصلية باختيار المالك

## نقطة البداية
اقرأ [AGENTS](../AGENTS.md)، ثم شغّل `npm run docs:context -- --pr 93` وتحقق من CI والنشر، و`npm run status:summary -- --id RAD-056`. الحالة في [project-status](project-status.md) وحده؛ لا تعتبر ملفات التحضير إثبات تطبيق حي.

## الهدف والمنجز
E البرمجية في مسودة #93؛ CI للرأس البرمجي نجح، وDeploy توقف عند Require verified pilot schema كما تحقق GitHub. بعد ذلك أذن المالك بتطبيق SQL E، وأكد عدم وجود نسخة حديثة وطلب المتابعة على الأصلية vlacestfruxooznrcjqc. هذا اختيار جديد لهذه العملية فقط؛ لا يُستنتج من استثناء C/D السابق ولا يغلق جاهزية الاسترداد. [تقرير E](ASSESS_E_REPORT_2026-10-20.md#متابعة-تطبيق-sql-e-على-الأصلية) يسجل الاختبارات والحدود والدليل.

## الخطوة التالية
من SQL Editor للمشروع الأصلي: شغّل [فحص E قبل التطبيق](../supabase/checks/assess-e-preinstall.sql) كاملًا. إذا ready_for_e_install=true، شغّل [حزمة E اليدوية](../supabase/manual/assess-original-e-install.sql) كاملة مرة واحدة دون تعديلها؛ تتضمن فحص الحالة مجددًا، E وحدها ومعاملة وتحققًا قبل COMMIT. عند false أو أي خطأ توقف وأرسل الناتج المنقح؛ لا DROP أو إعادة B/C/D أو استخدام الحزمة القديمة. بعد نجاح مبلغ عنه تُراجع نتائج [catalogue](../supabase/checks/assess-staging-ready.sql) و[فحص E المغلق](../supabase/checks/assess-practical-ready.sql) ثم مسار خدمة E ضمن النطاق المأذون، قبل أي إثبات نشر جديد. لا تعدل PILOT_SCHEMA_VERIFIED لتمرير الفشل.

## العوائق والحدود
لا اتصال إداري مجهز للوكيل؛ تطبيق SQL من المالك لم يُبلغ عنه بعد. الحزمة المحلية لا تثبت هدف القاعدة من داخل SQL؛ يجب مطابقة محدد المشروع. النسخة الحديثة والاستعادة غير متحققتين باختيار المالك لهذه العملية؛ المعاملة تحمي فقط من أخطاء قبل COMMIT. launch_gate تبقى مغلقة، ولا تشغيل محاولات/محتوى إنتاجي أو runtime/worker/scheduler أو F أو ready/merge. بوابات الموافقة/الاحتفاظ/المراقبة/النسخ والاستعادة وO106/O108 مستقلة. أدلة C/D المغلقة السابقة محفوظة ولا تعاد دون تغير ذي صلة، ولا تثبت تشغيل المحاولات حيًا. لا فتح أو مشاركة معاينة مستضافة من الوكيل.
