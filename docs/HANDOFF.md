# التسليم الحالي — تجهيز C/D على مشروع RAD-LAB الأصلي

## نقطة البداية
اقرأ [AGENTS](../AGENTS.md)، ثم شغّل `npm run docs:context` وتحقق من PR المعني وCI والنشر عبر GitHub، و`npm run status:summary -- --query assess`. الحالة في [project-status](project-status.md) وحده؛ مراجع Git المحلية ليست دليل نشر.

## الهدف والمنجز
D في المسودة بعد دمج C؛ [تقرير D](ASSESS_D_REPORT_2026-10-20.md) يحفظ واجهتها وفحوصها. بعد خطة staging اختار المالك صراحةً الاستكمال على المشروع الأصلي vlacestfruxooznrcjqc. [الخطة](ASSESS_STAGING_PLAN.md#المسار-الجاري-بعد-اختيار-المالك-للأصلية) توثق تغيير الوجهة وحزمة C/D المحلية المراجعة واختبار المعاملة وحدودها؛ اقتراح staging السابق لم يعد الخطوة الفورية. لا حذف للمشروع الجديد، ولا طلب إعادة اعتماد قرارات Assess أو Blueprint أو E/F.

## الخطوة التالية
أرسل المالك نتيجة [فحص البداية للقراءة فقط](../supabase/checks/assess-cd-preinstall.sql) مطابقة لحالة B-only؛ التفاصيل في الخطة. أكد عدم وجود نسخة حديثة. الخطوة التالية تجهيز نسخة منطقية مشفرة وتجربة restore وفق §8 في [دليل الإعداد](PILOT_SUPABASE_SETUP.md)، وتحديد جهاز المالك وإتاحة Backups لاختيار المسار. نسخة أكتوبر القديمة لا تغطي التغييرات اللاحقة. بعد شروط الاسترداد ومراجعة التعاريف والصلاحيات وسجل التطبيق ونافذة القفل، تُطبّق C ثم D وحدهما بمعاملة محروسة؛ لا إعادة ترحيلات قديمة أو DROP. لا تعتبر ready_for_cd_review فحص bodies/ACL شاملًا أو إذن تشغيل. لم ينفذ الوكيل SQL بعيدًا.

## العوائق والحدود
فحص البداية منقول من المالك وناجح؛ النسخة الحديثة وتجربة استعادتها غير متوفرتين بعد؛ C/D غير مثبتتين على المزود والبوابة لم تُفتح. لا تغيير PILOT_SCHEMA_VERIFIED أو pins أو workflow لمجرد تمرير Deploy؛ بعد SQL يلزم catalogue والبوابة المغلقة وفحص الخدمة بالحسابات قبل مراجعة الإثبات. اختيار الأصلية لا يأذن بنشر Node/عامل/جدولة أو فتح إطلاق أو دمج PR. O106 للموافقة والاحتفاظ/النسخ والاستعادة وغير المؤقت، وO108 قبل محتوى حقيقي وخلفيته ومعاييره وMarker؛ التدريب والتصفير مستقلان. لا فتح/مشاركة معاينة مستضافة من الوكيل، ولا انتقال تلقائي إلى E.
