# التسليم الحالي — تجهيز C/D على مشروع RAD-LAB الأصلي

## نقطة البداية
اقرأ [AGENTS](../AGENTS.md)، ثم شغّل `npm run docs:context` وتحقق من PR المعني وCI والنشر عبر GitHub، و`npm run status:summary -- --query assess`. الحالة في [project-status](project-status.md) وحده؛ مراجع Git المحلية ليست دليل نشر.

## الهدف والمنجز
D في المسودة بعد دمج C؛ [تقرير D](ASSESS_D_REPORT_2026-10-20.md) يحفظ واجهتها وفحوصها. بعد خطة staging اختار المالك صراحةً الاستكمال على المشروع الأصلي vlacestfruxooznrcjqc. [الخطة](ASSESS_STAGING_PLAN.md#المسار-الجاري-بعد-اختيار-المالك-للأصلية) توثق تغيير الوجهة وحزمة C/D المحلية المراجعة واختبار المعاملة وحدودها؛ اقتراح staging السابق لم يعد الخطوة الفورية. لا حذف للمشروع الجديد، ولا طلب إعادة اعتماد قرارات Assess أو Blueprint أو E/F.

## الخطوة التالية
المالك جاهز على SQL Editor للأصلية؛ شغّل [فحص بداية C/D للقراءة فقط](../supabase/checks/assess-cd-preinstall.sql)، ثم راجع النتيجة وسجل التطبيق والنسخة الاحتياطية المشفرة وتجربة restore ونافذة القفل وفق دليل الإعداد قبل الكتابة. لا تعتبر ready_for_cd_review فحص bodies/ACL شاملًا أو إذن تشغيل. عند قبول الأساس وشروط الاسترداد تُطبّق C ثم D وحدهما بمعاملة واحدة وحارس B-only؛ لا إعادة ترحيلات قديمة ولا DROP لحل فرق أو تطبيق جزئي. الحزمة المحلية وبصماتها ودليلها في الخطة. لم ينفذ الوكيل SQL بعيدًا.

## العوائق والحدود
فحص البداية الحي وشروط الاسترداد غير مثبتين بعد؛ C/D غير مثبتتين على المزود والبوابة لم تُفتح. لا تغيير PILOT_SCHEMA_VERIFIED أو pins أو workflow لمجرد تمرير Deploy؛ بعد SQL يلزم catalogue والبوابة المغلقة وفحص الخدمة بالحسابات قبل مراجعة الإثبات. اختيار الأصلية لا يأذن بنشر Node/عامل/جدولة أو فتح إطلاق أو دمج PR. O106 للموافقة والاحتفاظ/النسخ والاستعادة وغير المؤقت، وO108 قبل محتوى حقيقي وخلفيته ومعاييره وMarker؛ التدريب والتصفير مستقلان. لا فتح/مشاركة معاينة مستضافة من الوكيل، ولا انتقال تلقائي إلى E.
