# خطة إشعار Brevo عند تسجيل طالب جديد — تصميم فقط (RAD-104)

**اقتراح بلا حكم:** لا تنفيذ ولا SQL ولا مفتاح ولا اتصال في هذه الدفعة. القرار للمالك ([مقترح في DECISIONS](DECISIONS.md#brevo-signup-notify-proposal-2026-11-04)). كل حقيقة خارجية موسومة **Verified** (مقروءة في المستودع أو من المالك) أو **Not verified** (من المعرفة العامة ولم تُقرأ في هذه الدفعة).

## 1. الهدف والقيود

- **الهدف:** يصل المالك بريد عند تسجيل طالب جديد.
- **المحتوى:** لا بيانات شخصية: لا اسم ولا بريد ولا UUID. نص ثابت «تسجيل جديد» + **العدد الإجمالي الجاري** فقط.
- **المعدل:** بريد واحد على الأكثر كل 10 دقائق؛ التسجيلات داخل النافذة تُدمج في بريد واحد برقم إجمالي واحد.
- **عدم الإعاقة:** الإشعار لا يمنع التسجيل ولا يبطئه أبدًا. أي فشل يُسجَّل برمز وزمن **دون تفاصيل** (لا نص خطأ ولا عنوان ولا مفتاح).
- **مفتاح الإيقاف:** لكل خيار طريقة تعطيل بلا نشر كود (§3).

## 2. القيود القائمة

- Brevo مستخدم أصلًا لبريد المصادقة عبر SMTP (**Verified**، [S-PILOT-6 في الإعداد §3](PILOT_SUPABASE_SETUP.md#3-بريد-التأكيد-smtp--نُفِّذ-بـ-brevo-2026-10-15-المالك)): باقة مجانية، **300 رسالة يوميًا بحسب لوحتهم** (رقم المالك، لا تحقق مستقل)، مرسل `radlab.pilot@gmail.com`. مفتاح **SMTP** ينتهي بعد 90 يومًا بلا استخدام (**Verified** من السجل نفسه).
- **مفتاح API غير مفتاح SMTP:** المفتاح الحالي لا يصلح لواجهة API (**Not verified**)؛ يلزم مفتاح API منفصل من لوحة Brevo، وتأثير ذلك على الحصة المجانية **Not verified**.
- الخصوصية والاحتفاظ: [TERMS_OWNER_DRAFT](TERMS_OWNER_DRAFT_2026-10-16.md) — لقطة المالك: سجلات Brevo شهر واحد وعدم تخزين المعاينات (**Verified** كإعداد ظاهر، لا كمحو مثبت). الرسالة هنا بلا بيانات شخصية فلا تضيف تصنيفًا جديدًا، لكن **عنوان المستلم** (بريد المالك) يمرّ عبر Brevo؛ يُخزَّن خارج Git (§4).
- المشروع على باقة Supabase **FREE** ([D1](DECISIONS.md#launch-records-owner-2026-11-03)). توفر `pg_net` و`pg_cron` وVault وEdge Functions وحدودها في هذه الباقة **Not verified** هنا؛ تُتحقق من لوحة المشروع قبل التنفيذ.
- جدول الطلاب `public.profiles` (**Verified** في الترحيلات). أي مشغّل يوضع على جدول التطبيق لا على `auth.users` ما لم يُثبت أن ذلك ممكن ومناسب (**Not verified**).

## 3. الخيارات (Decision-needed — لم يُختر شيء)

| | A: مشغّل قاعدة + `pg_net` ومفتاح Brevo في Vault | B: Database Webhook ← Edge Function | C: ملخص مجدول |
|---|---|---|---|
| **أين المفتاح** | Supabase Vault؛ تقرؤه دالة `SECURITY DEFINER` فقط | سر Edge Function (Secrets) | Vault (إن أُرسل من القاعدة) أو سر Edge Function |
| **تحديد المعدل** | جدول حالة صغير (آخر إرسال، عدّاد معلّق)؛ المشغّل يزيد العدّاد ويرسل إن مرّت 10 دقائق | نفس جدول الحالة تفحصه الدالة بدور الخدمة؛ أو تجاهل الاستدعاء الزائد | كل 10 دقائق بطبيعته: يعدّ التسجيلات الجديدة ويرسل إن وُجدت |
| **ذيل الدمج** | تسجيلات داخل النافذة بلا تسجيل لاحق تبقى معلّقة حتى تسجيل تال؛ علاج: مهمة `pg_cron` خفيفة (**Not verified**) | نفسه | لا ذيل: كل دورة تُفرغ العدّاد |
| **أثر على التسجيل** | المشغّل داخل معاملة التسجيل: يلزم `EXCEPTION WHEN OTHERS` يبتلع كل خطأ، و`pg_net` غير متزامن بحسب توثيقه (**Not verified**) | أقل ارتباطًا: Webhook غير متزامن (**Not verified**)؛ فشل الدالة لا يرجع إلى المشغّل | لا ارتباط إطلاقًا بالتسجيل؛ تأخير حتى 10 دقائق |
| **وضع الفشل** | يُسجَّل رمز في جدول الحالة (`ok`/`fail` وزمن)؛ لا رسالة خطأ | سجلات الدالة قد تحتوي تفاصيل: يجب إلغاء طباعة الاستجابة | دورة فاشلة تُعاد في التالية؛ رمز فقط |
| **مفتاح الإيقاف** | صف `enabled=false` في جدول الحالة يقرؤه المشغّل أو حذف المشغّل بأمر واحد | حذف الـWebhook أو إزالة السر | `cron.unschedule` أو صف `enabled=false` |
| **حدود الباقة المجانية** | حصة Brevo اليومية فقط (≤144 بريدًا/يوم بحد 10 دقائق، بعيد عن 300) | + حدود استدعاءات Edge Functions في Supabase (**Not verified**) | ≤144/يوم أيضًا؛ + `pg_cron` (**Not verified**) |
| **يدوي عند المالك** | وضع مفتاح API في Vault؛ توثيق المرسل في Brevo؛ حفظ بريد المستلم خارج Git (جدول إعداد أو سر) | وضع المفتاح كسر؛ توثيق المرسل؛ ضبط الـWebhook من اللوحة؛ المستلم كسر | كالأول أو الثاني + تفعيل `pg_cron` من اللوحة |
| **ما يحتاج كودًا** | ترحيل (جدول حالة، دالة، مشغّل) | ترحيل جدول الحالة + كود Edge Function (وحدة جديدة) | ترحيل + دالة/مهمة |

**ملاحظة محايدة:** C أبعد عن مسار التسجيل لكنه الأبطأ في الوصول (حتى 10 دقائق)؛ A أقل أجزاء متحركة لكنه الأقرب إلى المعاملة؛ B يضيف سطح Edge Function جديدًا. لا توصية مسجّلة.

## 4. ما يفعله المالك يدويًا (أيًّا كان الخيار)

1. مفتاح API في Brevo (منفصل عن SMTP)، ثم وضعه في Vault أو Secrets؛ لا يُكتب في Git أو المحادثة.
2. توثيق عنوان المرسل في Brevo (قائم لـSMTP؛ يلزم التأكد أنه مسموح لواجهة API — **Not verified**).
3. عنوان المستلم يُخزَّن خارج Git ولا يظهر في سجل أو رسالة خطأ.
4. بعد التنفيذ: تسجيل تجريبي وحيد بحساب اختبار والتحقق أن الرسالة بلا بيانات شخصية وأن التسجيل لم يتأثر (يُقاس زمنه قبل/بعد).

## 5. Scale (S-STD-3) وقائمة المالك

- **السقوف:** حد 10 دقائق (≤144 بريدًا/يوم)؛ تسجيل واحد لكل رسالة غير معروض. محفّز الرفع: ضرورة تمييز التسجيلات (عندها قرار خصوصية جديد). **لا مسار بحث أو ترقيم جديد**؛ العدد الإجمالي `count(*)` على `profiles` — صغير الآن، ويُعاد النظر عند نمو كبير (يُخزَّن العدّاد بدل العدّ).
