## 4. المشترك وScale

P1_AVAILABLE مشتق حصريًا من requiredMigrations وdeferredMigrations للثلاثة معًا. لا env flag أو probe RPC أو promotion لدور owner. الملف والجسر ومستهلك الاستيراد المشروط مثبتة في guardedFeatures؛ يفحص حارس المخطط بايتاتها، ويتبع import داخل if(P1_AVAILABLE) فقط عند required. الاستيراد غير المحروس وRPC المؤجل والـboundary غير المراجع تبقى مرفوضة. لا يسمح الحارس باستدعاء API داخل الفرع المؤجل؛ الناقل مستقل ومثبت. required في نسخة اختبار فقط يغيّر العلامة ويُرفض معه المؤشر القديم، بينما إنتاج deferred يحافظ على العلامة الحالية.

الحارس الوحيد يحجب route/menu/Account/owner section ومصدر الناقل حتى required. تطبيق publishable client نفسه يختار assess schema وأسماء معاملات RPC؛ لا service key أو actorId للـRPC أو retry آلي. لا اشتراك شبكة أو polling أو قناة SSE أضيفت؛ لا عامل. تتغير هوية الجلسة/الدور/الاعتماد والموافقة العامة فتفك الواجهة والطلب القديم. عند إخفاء الصفحة يُفك عرض البيانات؛ العودة تقرأ النطاق من جديد. deadline الخادم يمحو العرض دون click. السحب في عميل آخر يُنفذ على كل قراءة/تغيير في SQL؛ الصفحة تعرض snapshot حتى refresh أو تغيير الظهور أو deadline، وليست خدمة push لإزالة بكسلات سابقة عن بعد.

قواعد نافذة §4 تبقى في RPCs القائمة: max(joined_at,starts_at,appointed_at,accepted_at)، recorded_at خادمي، لا pending أو تاريخ عضوية سابقة أو بيانات مشرف آخر، والعد قبل paging. قائمة النتائج في P1 تدريب فقط؛ نتائج الاختبارات وtargets ودرجاتها لا تتغير. إصلاح P1 UI يحفظ groupsCursor عند اختيار مجموعة من الصفحة التالية ويصفر مؤشرات الأعضاء/النتائج عند تغيير المجموعة؛ لا قراءة كل المجموعات.

Scale: صفحة20، حد SQL100، عضوية≤1000 وthrottle10طلبات/ساعة قائمة دون رفع؛ الدور المشرف قدرة مستقلة والـIDs بيانات لا قائمة أشخاص ثابتة. الجديد قائمة عائلات RPC v1 محدودة لهذا النطاق؛ تمديدها يحتاج عقدًا ومراجعة schema. فحص catalogue strict على مصدر PostgreSQL16 مع ACL/owner/body؛ اختلاف المزوّد/الإصدار/CRLF يوقف ولا يحل بتحديث hash عمياني. قياس الحمل/التخزين/قفل النطاق والنسخ/الاستعادة قبل إطلاق حقيقي ما زال مطلوبًا.
