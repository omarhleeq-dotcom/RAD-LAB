# RAD-085 — المشرف أولًا، ثم أول امتحان حقيقي، ثم الكتابي، ثم الصور

الحاكم الحالي: [قرارات المالك D1–D8](DECISIONS.md#rad085-owner-tidy-2026-10-27) و[التقرير الموحد](RAD-085_REPORT_2026-10-27.md). المقاطع التاريخية أدلة لنطاقها فقط.

**شروط قبل أول امتحان حقيقي:** RAD-082: النسخ اليومية الآلية المحلية عبر Docker على لابتوب المالك شرط مكتمل قبل أول امتحان حقيقي، في أي جلسة تسبقه. لا نسخ سحابية. سجل المصالحة ملف محلي مشفر بجانب نسخ Docker، بلا تخزين سحابي؛ تجهيز التشفير والحداثة والإبطال والاستعادة ما زال مطلوبًا. RAD-059 شرط صارم: اختبار إيقاف طارئ يوقف الإنفاق فعليًا، لا تنبيه ميزانية فقط. حجب محو الكاتب/المشرف مؤقت؛ تنقل الإدارة للمالك ويكتمل المحو ضمن نافذة Terms ذات30يومًا دون احتفاظ مفتوح. النقل الآمن غير منفذ بعد، ولا SQL لهذا التصحيح التوثيقي.

التاريخ الأصلي: 2026-10-25؛ القرار الحالي: 2026-10-27 بتوقيت Asia/Amman. مصدر الحالة الوحيد [project-status](project-status.md). أدلة الواجهات السابقة في [تقرير الجاهزية](archive/RAD-085_UI_READINESS_REPORT_2026-10-25.md) وتقارير P1/P2 وfull-practical والمشهد؛ لم تُعد كتابتها لتوحي بمراجعة حصلت.

**قرار SQL السابق المحفوظ:** تنفيذ دفعة SQL المجمعة واختباراتها المحلية لنطاق المشرف وP1/P2 الحالي، وتجهيز عقود الربط اللاحق على PR #137 نفسه Draft وفي checkout نفسه دون worktree أو subagents. أُجلت مراجعة المالك للواجهات والهاتف إلى ما بعد SQL والربط الفعلي وتجهيز نسخة متصفح قابلة للمراجعة؛ لم تحصل المراجعة أو الموافقة. يستبدل هذا شرط المراجعة قبل SQL، ولا يمنح إذن الربط الحي أو العامل أو الدمج أو النشر أو الكتابي أو الصور. أسماء DTO والـfixtures ليست schema/RPC نهائية.

**الحالة المحلية للمسودة:** P1/P2 وربط PostgreSQL والجسر والإسناد والإغلاق والعامل والمحو وسياسة المشاركة v2 مجهزة محليًا بحاضنات اصطناعية، دون route/menu منتج أو SQL حي أو نشر عامل. [التقرير الموحد](RAD-085_REPORT_2026-10-27.md) يميز التنفيذ الحالي عن أدلة الدفعات التاريخية. تبقى مراجعة المالك والهاتف والأمن/المحتوى/المزوّد والتشغيل؛ RAD-085 review لا done. أعيد استعمال المجموعات والعضويات والإسناد والإغلاق، مع أعمدة/قيود وtriggers جديدة؛ ليست التغييرات إضافية محضة. الاستثناءان D6 وD7 محددان ولا يجيزان توقعات أو بصمات أخرى. لا PILOT_SCHEMA_VERIFIED أو launch_gate أو CONSENT_VERSION أو شهادة جديدة.

**المعاينة الحالية:** PracticalScene وPracticalControls القائمان بقيم مؤقتة فقط. فُصلت إطارات الرسم ونطاقات إزاحته عن ملفات الفحوص/الحالات، دون نقل targetPx أو rubric أو مصادر/ترخيص/مراجعة إلى بيانات الطالب ودون تعديل حارس الاستيراد. بقيت هندسة السجل وسلوك الرسم والتصحيح ثابتة بالمقارنة البايتية؛ [تقرير المشهد](archive/RAD-085_SCENE_PREVIEW_REPORT_2026-10-25.md) يحفظ الإثبات وحدود القبول. لا محاولة أو تعريض أو حفظ إجابات أو تصحيح عبر الخدمة.

**أصل القرار المحفوظ:** أمر RAD-085 الأول أجاز التخطيط؛ اختار المالك Cloud Run، وامتحانات مجموعات المشرف فقط، وحد7أيام للكتابي. [سجل التخطيط الأصلي](#planning-report) دليل نطاق تلك الدفعة التاريخي؛ الإذن الحالي يضيف ربط P2 المحلي إلى ربط P1 والدفعات السابقة ولا يفتح Assess حيًا.

**الهدف:** أول امتحان جامعي حقيقي لـ3 شعب و≤120طالبًا، بأسئلة MCQ وأجزاء المحاكي دون صور جديدة. مسار الفحص الكامل مستقل كما في S-ASSESS-7؛ بناء امتحان Assess لا يجيز إضافة فحص تشريحي جديد أو رفع تجميد Shoulder Y/forearm. المحتوى English، والواجهة EN/AR. لا التزام باستيراد Excel/paste.

**خط الأساس:** تمت قراءة AGENTS وHANDOFF، وتشغيل docs:context وstatus:summary للمهام RAD-056/059/060/062/063، وقراءة القرارات والأساس والخطة والتشغيل المستمر والتجربة وAssess/DB day في دليل الإعداد وSQL ووحدات الخادم. بدأ الفحص من checkout أقدم ثم حُدث fast-forward إلى main دون تغيير عمل الآخرين. عند الفحص كان main هو `31e9cbfba6574a9e87b59d47a687f99864c74b21`، ورقم الحالة الحر RAD-085. تحققت قراءة GitHub من دمج #96 و#131؛ لا نشر أو فحص هاتف أو حالة DB حالية مستنتجة من الدمج.

### ما يتضمنه RAD-059 في الخيار A

- صورة تشغيل عامة منفصلة عن صورة trial المقيدة؛ لا رفع allowlist/controller التجربة لتصبح تشغيلًا عامًا. تثبيت digest وإصدارات المحتوى والمصحح من base معتمد واحد.
- ربط النشر بالـform: candidate خاص→قراءة محدودة من worker→validateMixedContent/validatePracticalContent→install ذري؛ لا نشر مباشرة من المتصفح أو اكتمال حقول review وحده.
- tick محدودة، pool=1 وplatform retries=0، وإيقاف عند غموض ACK. Job الحالية تصحح حد1 فعلًا؛ الرفع المقترح إلى25 بعد قياس، والحد العام100. لا افتراض throughput من trial.
- منع تداخل ticks بقفل advisory على اتصال PostgreSQL مثبت طوال الدورة؛ lock وRPCs على الاتصال نفسه، ولا reconnect صامت بعد فقده. تعديل الربط المحدد واختباره جزء المرحلة؛ parallelism1 وحدها لا تمنع executions متداخلة.
- دقيقة أثناء نوافذ الامتحان، وصيانة يومية خارجها؛ تُحدد النوافذ بالإعداد، ولا cron دقيقة طوال الفصل دون حاجة. يحسب عددالتشغيلات الفعلي ومدة الحد الأدنى للفوترة وأسعار الخدمات التابعة قبل الاعتماد.
- تنبيه عند غياب تقرير/فشل execution خلال5دقائق داخل النافذة، backlog متزايد، تجاوز leases، قرب7أيام، وpurge متأخر. خارج النوافذ تُراقب صيانة اليوم ولا تنشأ إنذارات غياب tick امتحان غير متوقع.
- قناة فعلية يختارها المالك وبديل مسؤول، واستلام إنذار تجريبي موثق؛ هذه الجلسة لا ترسل رسائل أو تنشئ قناة.
- سجل منقح بأعداد ورمز ارتباط فقط، بلا claims أو أجوبة أو keys أو JWT أو أسماء/علامات؛ مراقبة الميزانية ليست cap.
- STOP مجرّب: منع starts الجديدة، إيقاف الجدولة/التشغيلات، سحب الوصول للسر، NOLOGIN/expiry، إنهاء الاتصالات المستهدفة ورفض اتصال جديد بالاعتماد القديم من المسار نفسه. NOLOGIN لا يقتل جلسة قائمة؛ غموض Supavisor cache يبقى فشل قبول.

### التفويض والنافذة

1. RLS default-deny على كل جدول Assess جديد، بلا direct grants حتى للمالك أو worker. RPCs SECURITY DEFINER وsearch_path=''، وrevoke/grant صريحان؛ auth.uid() مصدر الهوية، لا user_id يرسله العميل كهوية ذاتية.
2. المشرف يحتاج حساب approved وتعيينًا ساريًا ومجموعة مسندة إليه. لا اعتماد/تعليق/حذف حسابات، ولا owner/all training أو surveys أو directory عام؛ يختبر الرفض باستدعاءات مباشرة لا UI فقط.
3. الرمز يتيح طلبًا فقط؛ pending لا يعطي عضوية أو قراءة. القبول يثبت joined_at بساعة الخادم. المالك والمشرف لا يسجلان موافقة Terms نيابة عن الطالب.
4. memberships والفترة تتغيران ذرّيًا؛ المغادرة تحذف العضوية الحالية وتغلق الفترة، وإعادة القبول تنشئ فترة جديدة. الفترات هي دليل التاريخ، والجدول القائم هو إسقاط العضوية النشطة.
5. الرؤية تتطلب وقت الطلب مجموعة غير منتهية وعضوية نشطة وتعيينًا ساريًا. بداية البيانات هي max(joined_at, supervised_from, starts_at). لا يشاهد المشرف بيانات قديمة عند تسلمه مجموعة.
6. بعد المغادرة أو نهاية المجموعة تختفي كل بيانات الطالب عن ذلك المشرف، بما فيها القديمة. إعادة الانضمام لا تعيد تاريخ فترة سابقة. سحب التعيين يسحب الوصول فورًا؛ يبقى المالك وفق سياسة الاحتفاظ.
7. Practice يُقرأ منذ recorded_at الخادمي داخل النافذة؛ الأوقات الحالية finished_at/started_at يقبلها العميل فلا تصلح حدًا أمنيًا. وقت التسجيل لا يثبت زمن إنجاز النشاط أو نزاهة Practice. الصفوف السابقة للإضافة لا تعرض للمشرف دون دليل موثوق مستقل.
8. امتحانات المشرف هي إسنادات مجموعاته فقط كما اختار المالك؛ محاولة بدأت داخل النافذة ونتيجة غير منتهية. لا نتائج امتحان مشرف آخر أو مفاتيحه/أسئلته. فحص النطاق قبل count/aggregate/paging، لا ترشيح owner/all في الواجهة.
9. تغيّر العضوية لا يغير targets المنشورة أو وصول الطالب صامتًا؛ السحب بتعديل إسناد صريح. الرؤية الإشرافية تُسحب فورًا، والساعة والتسليم القائمان لا يتغيران. المحتوى والنسخ القديمة لا تُعدّل.
10. RPCs القديمة members_write_v1/group_write_v1 لا يجوز أن تتجاوز الفترات أو تمحو تاريخ مجموعة حديثة؛ تغلف بالحراس أو ترفض العملية غير المتوافقة. انتهاء المجموعة هو archive/end؛ لا حذف تاريخها لتسهيل التنظيف.
11. تعديلات مصدر RPC القائمة في migration جديدة تُذكر كغير إضافية محضة؛ لا تعديل ملفات migrations المطبقة، ولا منح owner للمشرف كاختصار.

**مصادر التأليف:** form يجمع السؤال والخيارات والمفتاح/حالة المحاكي والنقاط والمصادر والترخيص؛ يستخدم registries وvalidators القائمة. MCQ من تأليف الرافع يُسجل authorship بلا اختلاق reviewedBy طبي. قبل التنفيذ يُراجع عقد ContentReview لتمييز authorship عن independent review بإصدار صريح؛ مراجعة المحاكي وخلفيات الأجزاء وMarker تبقى مطلوبة، وإكمال حقول المصدر لا يثبت ترخيصًا أو مراجعة. المعاينة للكاتب فقط ولا تكتب محاولة طالب أو تسرب المفتاح إلى runner.

### عقد الكتابي المقترح بعد اختيار حد7أيام

- awaiting-manual حالة مستقلة عن grading-failed؛ لا يصحح المكتوب آليًا ولا يحوله لصفر افتراضيًا. نسخة المحتوى الجديدة تدعم المكتوب وتبقي القديمة دون تغيير.
- العامل يصحح البنود الآلية فقط ويثبت subtotal خاصًا وحالة الانتظار؛ finish القديم لا يجوز أن ينهي امتحانًا يحمل كتابة غير مصححة. maintenance والـclaim يميزان الانتظار عن فشل العامل24ساعة.
- المهلة سبعة أيام من submitted_at؛ ينبه المالك في اليوم الخامس، ويجوز له التصحيح قبل اليوم السابع. لا void إلا إذا بقيت الإجابات غير مصححة في اليوم السابع؛ لا تمديد صامت بسبب غياب المشرف.
- المشرف يحدد علامة ضمن maximum البند بعقد revision؛ طلبان متزامنان أو retry لا يعتمدان درجتين. الاعتماد النهائي يحسب الكسور الدقيقة ويثبت النتيجة ويحذف التفاصيل ذرّيًا.
- عند النهاية غير المصححة: void بلا علامة مختلقة وحذف التفاصيل وإنذار المالك؛ إعادة الامتحان بإسناد جديد عند قراره. فقد صلاحية المشرف/انتهاء المجموعة يحيل التسوية للمالك دون استمرار وصول المشرف.
- النتيجة تبقى ستة أشهر تقويمية من التسليم، لا من تاريخ التصحيح؛ لا إعادة تصحيح بعد حذف الأجوبة أو احتفاظ بدفتر درجات مفصل خارج السياسة.
