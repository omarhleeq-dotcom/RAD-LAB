الهدف الواحد: إنشاء مسودات mixed وfull-practical وقائمتها وفتحها وحفظ تعديلاتها واسترجاعها عبر RPCs القائمة وPostgreSQL معزول، مع عزل النطاق واستعادة revision/ACK دون كتابة صامتة فوق تعديل أحدث. الميزانية15ملفًا، استُخدمت كاملة: contracts وSession وAuthoringView وcopy داخل authoring-review؛ sql-adapter وsql-adapter-db.test وsession-recovery.test؛ scripts/qa/rad-085-p2-sql-audit.mjs؛ الخطة والعقود والحالة وHANDOFF وهذا التقرير؛ لقطتا rad085-p2-sql-en/ar.jpg. لا تعديل وحدات P1 أو SQL/Assess أو workflows أو package/lock، ولا تجاوز ميزانية أو تغيير توقعات/بصمات محمية.

بدأ checkout علىwork برأسmain لا يحتويRAD-085؛ فشل status:summary أولًا بـunknown task. تحقق docs:context مباشرة أن#137 مفتوح وDraft وغير مدموج، ورأسه424c9e5527bc0fc51f5382a029776b162f51cb48 وmain31e9cbf. جُلب مرجع فرع الطلب صراحة لأن fetch الافتراضي جلبmain فقط؛ انتقل checkout نفسه إلى رأسPR دون worktree أوsubagents أوPR بديل. شُغّل docs:context وstatus:summary بعد الانتقال. استُخدمت مهارة cloud-environment-runtime لقراءة البيئة وسياسة الشبكة دون تعديلهما أو طباعة أسرار.

لا خلل SQL استلزم تعديلًا في هذه الدفعة؛ لم تُطبّق الترحيلات الثلاثة حيًا. لا publication bridge أو تثبيت محتوى أو تجهيز/تأكيد إسناد أو زر إغلاق أو worker أو جدولة أو اتصال Supabase حي أو variables/PILOT_SCHEMA_VERIFIED/launch_gate/CONSENT_VERSION أو شهادة جديدة. حاجز Draft قائم؛ لا إزالة أو فتح أو مشاركة المعاينة السابقة، وإزالتها خارج النطاق.

أُعيد استخدام AuthoringView ومحرري المسارين وStudentPreview ومشهد PracticalScene وضوابطه والإسقاط القائم دون تعديلها أو إنشاء محرر/مخزن موازٍ. دعم المحرر التاريخي الاصطناعي باقٍ لاختباراته، وإفصاحSQL منفصل يوضح التخزين الحقيقي المحلي. الاستعادة ليست تخزينًا دائمًا آخر: النسخة غير المحفوظة تضيع عند إغلاق/إعادة تحميل الجلسة، وتمحى عمدًا عند فقد النطاق؛ الواجهة تفصح عن حدها. إلغاء حفظ معلّق يحتفظ بالنسخة ويعامل النتيجة غير مؤكدة بدل افتراض rollback.

المراجع والسياسة والبيانات هندسية اصطناعية داخل إعداد الاختبار فقط. لا إدخال لسجل المراجع عبرHTTP أو تعبئة سجل تشغيل من المتصفح. --unconfigured يبقي السجل فارغًا ويرفض البنود ذات المراجع؛ لا يخترع مصدرًا طبيًا أو licence أو reviewedBy أو publication قابلة للتثبيت. لم تُعد هذه الدفعة سياسة المشاركة أو قبولها، ولم توسع صلاحيات المشرف إلى owner أو حسابات أو surveys.

## 3. حسب المهمة

RAD-085 تبقىreview/waiting_on owner دون completion_evidence أو ادعاء اكتمال Assess أو الإطلاق. حُدّث عنوانها والمتبقي ومصدرها معrevision/time، وبقيت بقية المهام محفوظة. مراجعة المالك P1/P2 والهاتف لاحقة لنسخة المتصفح القابلة للمراجعة وليست شرط بدء هذه الدفعة، ولم تحصل أو تُفترض. RAD-060 وإغلاق الإسناد لم يتغيرا.

## 4. المشترك وScale

التعديل المشترك محصور بعقد AuthoringAdapter وجلسة P2 القائمة: service=sql، اشتراك إبطال اختياري، وقائمة/فتح اختياريان؛ الاختبارات التاريخية تستعمل المسار السابق. ScopeTransport نفسه منP1 أُعيد استخدامه دون تعديل. كل هوية مثبتة لدى النقل، وactorId فحص محلي لا وسيطRPC. خادم القبول binds إلى127.0.0.1 فقط مع Host/Origin وCSP وno-store وقائمةRPC محددة وحجم طلب محدود؛ PostgreSQL عبر Unix socket دون TCP أوURL موروث.

قبل/بعد كل قراءة مسودة أو حفظ تُقرأ صفحة المجموعة المحددة مجددًا ويُقارن جيلها؛ لا لقطة ذرية مزعومة بينRPCs. كلRPC معاملة قصيرة مستقلة. ساعة الخادم تخصم زمن النقل والانتظار محافظًا، وتخفي النتيجة عند انتهاء النافذة. مؤشر المجموعة محفوظ لصفحة≤20فقط، فلا مسح لكل المجموعات أو الأعضاء. قائمة المسودات20وحدSQL100؛ التحقق منACK يحتاج صفحة واحدة لأن السقف الحالي5مسودات/كاتب. رفع سقف المسودات إلى أكثر من الصفحة يستلزم ترقية بحث الاستعادة إلىkeyset قبل ذلك؛ لا افتراض دائم لعدد غير محدود. الكتالوج المشتق من السجل الحالي صغير ويحتاج بحثًا/paging عند نموه.

سقوف SQL باقية:5مسودات/كاتب،100revision/مسودة،200بند،128KiBبتحويلJSONB،50خيارًا. اختبار الصفحةSQL يستعمل limit=2لإثبات UUID keyset دون رفع سقف التخزين. لا تنظيف أو حذف جديد أو قياس سعةFREE/120متزامنًا؛ القفل العالمي والاحتفاظ بنسخ المستند يحتاجان قياسًا وسياسة وrestore قبل التشغيل. البصمة خادمية، لا مقارنة JSON.stringify ببصمة PostgreSQL.

إبطال SSE محلي بلا بيانات مستخدم لتغييرات النطاق فقط؛ حفظ تبويب آخر لا يمحو تعديل المستخدم بل يكشفه revision. فقد القناة يمسح العرض بلا إعادة تحميل آلية. التغييرات الإدارية خارج القناة المحلية وPostgREST/auth/Realtime الحية لم تُثبت؛ نفس حدودP1 الموثقة في [العقود](RAD-085_SQL_CONTRACTS_2026-10-26.md). حاضنتاP1/P2 قاعدتا اختبار مستقلتان، وليستا هوية/خدمة إنتاج مشتركة أو تشغيلًا حيًا.

## 5. الطب والتصحيح وفصل الطالب

لا تغيير لبيانات فحص/حالة أو مصحح أو درجات أو أوزان أو بوابات حرجة أو إصدارات تقييم أو بصمات مشهد محمية، ولا كتابي أو صور أو بيانات حقيقية أو فحوص جديدة. مصادر وملاحظات QA موسومة هندسية اصطناعية وغير معتمدة؛ لا ترخيص أو اعتماد طبي مستنتج. لم تُغيّر StudentPreview أو عقد الطالب؛ الإسقاط whitelist القائم يعرض الحقول العامة فقط. اختبارات SQL-loaded documents تثبت غياب correctOptionId وauthoring والملاحظات الخاصة وreviewedBy وrubric وmaximum وevaluatorVersion من DTO الطالب، وقائمة المسودات لا تحمل مفاتيح أو مستندات. تدقيق المتصفح يفحص المعاينتين معaxe والتخطيط؛ ليس مراجعة طبية.

## 7. المفتوح

سياسة مشاركة معتمدة وقبول الذات وسجل مراجع تشغيلي مثبت مستقل غير مهيأة. publication bridge والمراجعات المطلوبة والتثبيت والإسناد والإغلاق والعامل والجدولة خارج الدفعة. النقل الحي والمصادقة والإبطال الإداري خارج القناة المحلية والنسخ/restore والأداء والسعة والتكلفة والمراجعة الأمنية/المحتوى والمالك والهاتف والقبول قبل التشغيل متبقية. الترحيلات الثلاثة لم تُطبق علىSupabaseحي. نجاح المحلي وCI لا يثبت اكتمال نشر أو إسناد ولا يأذن بالتطبيق الحي.
