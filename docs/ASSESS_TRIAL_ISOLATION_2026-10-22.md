## 2. المنجز والمستبعد

الحزمة **اختُبرت على قواعد محلية جديدة فقط**. SQL تحت scripts، وليست migration أو وصفة تنفيذ على الأصلية. تنشئ جدول تحكم خاصًا وtriggers ودوال جديدة؛ تبدأ بلا صف نطاق ودون فتح gate. جرد المالك السابق خالٍ من المحاولات والمحتوى والإسنادات والمستحقات، مع موافقتين غير مستحقتين للحذف؛ لا يعاد ولا يُنظّف. الحزمة لا تستنتج هويات أصحاب الموافقتين أو v2 من عدّهما.

النطاق يحدد UUID عملية تحكم ومالكًا وطالبًا مسندًا وآخر غير مسند ومعرف assessment واسمَي نسختين immutable. الحد نسختان mixed/schema1، وإسنادان فرديان، ومحاولة ordinal1 لكل إسناد للطالب المسند، ودون مجموعات. UUIDs الفعلية للنسخ/الإسنادات تتحقق عبر روابطها بمعرف assessment والمالك وأسماء النسخ، وتصبح مفاتيحها immutable تحت الحماية؛ ليس مجرد مقارنة أعداد أو اسم واجهة. لا تستورد هويات حقيقية أو JWT في Git أو اختبارات أو stdout.

تفعيل صف التحكم مستقبلًا يحتاج المشغّل الإداري القائم، بوابة مغلقة، وتحققًا من وجود الهويات المعتمدة بأدوارها وفحص كل البيانات تحت القفل. يرفض بيانات غير التجربة ويثبت حدود الحجم؛ لا يمنح أدوار المستخدمين أو العامل قراءة الجدول أو تعديله، ولا ينشئ حسابات أو موافقة نيابة عن أحد. تغييرات إعداد النطاق ممنوعة بعد إنشاء صفه عدا active. لا تفعيل تلقائي مع installer أو بدء طالب أو tick.

عند active، تعترض triggers الكتابة الفعلية في جداول Assess الأربعة عشر المعنية، بما فيها RPC العادية والكتابة SQL المباشرة: تفحص طرفي UPDATE، وترفض الإسناد/المحاولة/المحتوى خارج النطاق، ونقل المفاتيح، وتوسعة targets للطالب غير المسند، والمجموعات. السماح بالبدء من خلال sessions/reservations يظل فوق شروط auth.uid/الاعتماد/الإسناد/الموافقة القائمة، ولا يحل محلها. القراءات العامة وسياسة إظهار العلامة لا تتغير.

تظل كل الموافقات القائمة محفوظة: UPDATE/DELETE للموافقات وTRUNCATE للبيانات مرفوضة أثناء الحماية، ولا توجد نسخة أخرى من صفوفها في جدول التحكم. INSERT للموافقة من هويات التجربة مسموحة عبر موافقتها الأصلية فقط. إذا أصبحت موافقة مستحقة لتنظيف metadata، تتوقف الدورة قبل الصيانة، أو تتراجع معاملة الصيانة كاملة إذا صار الاستحقاق نتيجة حذف جلسة داخلها؛ لا تعديل لعمر الاحتفاظ أو إعلان نجاح حذف جزئي. تعطيل Assess يظل دائمًا بعقده القائم، لكنه قد يجعل التجربة تتوقف لحاجة تسوية منفصلة؛ لا حذف account_stop أو consent للتحايل على ذلك.

الإغلاق يستعمل أداة المالك القائمة، لا SQL impersonation. لا يمكن تعطيل النطاق مع gate مفتوحة أو محاولة active/grading/grading-failed. بعد تسوية المحاولات وغلق gate يمكن جعله inactive ثم حذف **صف التحكم وحده** إداريًا؛ لا حذف محتوى/إسنادات/موافقات/نتائج للتجربة لتفريغ الجرد. لا FK من صف التحكم إلى profiles تعطل حذف حسابات المنصة، ولا نسخ metadata دائمة إضافية. TRUNCATE لجدول التحكم ممنوعة، وحذف الصف وهو active مرفوض. قواعد الإسناد المغلق والحذف التقويمي الأصلية تبقى حاكمة لبيانات المجال.

## 3. RAD-056 والحالة الفعلية

RAD-056 تبقى review/waiting_on owner للقبول والتشغيل مستقلين؛ لا done أو قبول حي. أُنجز نموذج الحماية المحلي واختبار التنافس، وأدوات تثبيت mixed واحد والإغلاق المفوض محفوظة من الدفعة السابقة. لا يوجد شاهد تركيب الحماية على الأصلية أو هوية/Auth حية للدورة أو إصدار UI/SQL مطابق جديد. نجاح Cloud Run probe السابق ثابت ولا يعاد، والعامل الأصلي باقٍ بحارسه المغلق وفق آخر شاهد.

## 4. المشترك وScale والتزامن

كل واحدة من trial_maintain/claim/finish/fail/health تستدعي حارسًا داخل **معاملة RPC نفسها**: أقفال `EXCLUSIVE NOWAIT` على جداول Assess الخمسة عشر المؤثرة، ثم قفل صف التحكم والتحقق من active وUUID، ثم جرد metadata bounded وفحص الروابط، ثم الدالة الأصلية. تبقى الأقفال حتى COMMIT في النقل القائم. لا فاصل بين فحص النطاق وأثر تلك RPC. القفل من PostgreSQL نفسه، لا بروتوكول advisory اختياري؛ يمنع الكتابة والقراءات التي تقفل الصفوف، مع بقاء SELECT العادية ممكنة. لا قفل لجدول Practice أو profiles.

NOWAIT تتوقف عند كاتب/قارئ ذي قفل قائم قبل فحص النطاق أو تنفيذ المرحلة، بدل الانتظار مع احتجاز أقفال جزئية. SQL تُرجع خطأ وتُرجع معاملة النقل، دون retry أو counters صفرية. طلب جديد قد ينتظر أقفال العملية الجارية؛ يبقى statement60s/lock5s في النقل وlease/COMMIT مرجع عدم اليقين. هذا إجراء تجريبي خشن القفل، ليس تصميم throughput أو نظام تشغيل دائمًا. لا ضمان نجاح كل tick عند تداخل حفظ الطالب أو أمر إدارة؛ الفشل يوقف التنفيذ للمراجعة.

فحص البيانات يقرأ metadata scalar فقط بسقف100 وسنتينل101 لكل مصدر، ويرفض ما خارج النطاق حتى لو لم يستحق المعالجة بعد. لا SELECT لأجوبة/علامات في فحص النطاق، ولا أخطاء تحوي هوية أو وثيقة. claim الأصلية وحدها تقرأ snapshot الخاص داخل العامل بعد الحماية. لا تقيد الحماية أحجام Practice أو Auth، ولا تدعي أن مشروع Supabase كله فارغ.

لا تكفي أقفال الجداول مع snapshot قديمة: لذلك يجب READ COMMITTED لفحوص الحماية **ولكتابات Assess المحروسة حتى عندما يكون النطاق غير مفعّل**. هذا قيد توافق مقصود في الحزمة يمنع معاملة REPEATABLE READ قديمة من عدم رؤية صف تفعيل جديد؛ لا ادعاء أن التثبيت الخامل لا يغير أي سلوك. المسار الافتراضي للنقل وPostgREST الحالي READ COMMITTED، لكن ذلك لا يثبت إعداد المزود الحي أو كل عملائه؛ يجب فحصه قبل تركيب لاحق. بعد inactive لا تُحتجز أقفال صف التحكم لكتابات Assess العادية، مع بقاء شرط READ COMMITTED.

الأقفال تتحرر بين RPCs، وتبقى triggers النطاق نشطة بين مراحل الدورة كي لا ينشأ إسناد/طالب/محاولة خارجها. تركيب أو تبديل النطاق نفسه تحت الأقفال؛ كاتب بدأ قبل التفعيل يمنع التفعيل، وتُرفض بياناته الأجنبية الملتزمة عند الفحص التالي. لا تصدر الحزمة دوال trigger/assert/enter للمستخدمين أو العامل؛ العامل ينال خمس RPC مغلفة فقط **بإضافة** إلى قدراته السابقة. لم تُسحب قدراته العامة القديمة ولم تتحول إلى tick-only؛ الأداة المقيدة لا تستعملها، ولا يُؤذن تشغيل صورة العامل العامة خلال التجربة. DDL إداري أو تعطيل triggers أو تغيير أجسام الدوال خارج نموذج الحماية ويحتاج حجر الإدارة والتحقق من البصمات/ACL قبل نافذة حية.

server-runtime أضافت خمس أسماء RPC ثابتة casts، بلا أسماء SQL واردة من المستخدم أو تغييرات TLS/هوية/connection limits. scopedTrialWorker يربط كل call بـp_trial ولا يقبل overrides أو recover/install ضمن الدورة. executeTrialJob يعيد استخدام executeAssessJob وrunAssessJobs والحد1 والمصحح والإيقاف والتنقيح وclose؛ غياب SQL أو النطاق يتوقف بلا رجوع إلى الدوال العامة. مخرجات الدورة العقد المعتاد بأعداد فقط؛ لا UUID أو وثيقة/claim/درجة في logs. الاستيراد لا يقرأ إعدادًا ولا يتصل، ولا يوجد entrypoint أو تحميل ملف/ENV جديد أو artifact حي من هذه الدفعة.

الحدود متعمدة لتجربة النسختين، وليست registry عامة: controller واحد، ثلاث هويات، assessment واحد، اسما نسختين، إسنادان ومحاولتان، حد100، وأقفال واسعة قصيرة لكل RPC. لا تشغيل متوازٍ أو scheduler أو retry. السماح بتجارب أكثر أو إسنادات جماعية/محتوى سابق أو حجم أكبر يحتاج عقدًا واختبارات مختلفة؛ لا رفع سقف أو reuse يخلط بيانات جولة جديدة بقديمة. singleton والـUUID صريحان؛ حذف التحكم غير المفعّل لا يحذف البيانات القديمة ولا يجعلها مؤهلة لجولة أخرى تلقائيًا.

## 5. الطب والتقييم والاحتفاظ

الاختبار الاصطناعي سؤالان حروف غير طبيين، خمس نقاط لكل سؤال، ونسختا visible/hidden؛ الحفظ/التسليم والانقضاء يعطيان5/10 ضمن الحالة المعروفة وحجب النتيجة من RPC في hidden. لا طبي أو عملي كامل أو simulator في fixture. الحارس ليس ترخيص محتوى أو O108، ولا يثبت منع نسخ محتوى طبي مرفوض من مشغّل موثوق؛ التحقق والمراجعة يظلان شرطًا مستقلًا قبل نشر أي وثيقة. لم تتغير Practice أو المصحح أو المعايير أو hashes أو توقعات اختبار قائمة. مدة ستة أشهر تقويمية من submitted_at والقواعد24ساعة/سبعة أيام واستخدام الحجز والإغلاق دوال أصلية غير معاد تنفيذها.

## 7. المفتوح والتوقف

لم تُركب هذه SQL على الأصلية أو تُفعّل الحماية/LOGIN/gate، ولم يُشغّل عامل أو scheduler أو content install/close حي أو IAM/Variables. قبل أي تطبيق لاحق يلزم حزمة تركيب مغلقة مستقلة تتحقق من أجسام/ACL/ترتيب triggers الحالية ومن dormant postcondition وفحص عدم الانتحال والصلاحيات على المزود، وتطابق UI/SQL، وجلسة مالك آمنة، وتعبئة عملية مقيدة مستقلة ونافذة محددة وإيقافها. لا نسخ secret أو رفع إصدار أو إعادة probe. هذه بوابات تنفيذ فعلية، لا موافقة تصميم أو سياسة احتفاظ جديدة.

حارس SQL لا يحمي من إداري يغير DDL/trigger عمدًا أو صورة تستعمل قدرات مختلفة. تثبيت مصدر الحزمة والصورة والصلاحيات وحجر تعديل الإدارة خلال النافذة جزء من قبول حي لاحق. عند55P03/40P01/STOP أو غموض COMMIT تتوقف الأعمال الجديدة ولا تعاد تلقائيًا؛ الإغلاق/lease/الاسترداد الحالي يحتاج مصالحة مستقلة. لا حذف metadata أو result أو إعادة reservation لإخفاء الفشل. المراقبة/cache والتكلفة والنسخ/restore/O108 والقبول الوظيفي والطبي مستقلة، ولا تشغيل مستمر مستنتج من هذا الشاهد.
