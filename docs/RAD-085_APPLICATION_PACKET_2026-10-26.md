4. جرد سابق كامل ومراجع، ومقارنة مصدر/مطبق/إصدارات وdrift. مصدر المخطط السابق الصناعي ليس وصفًا مؤكدًا للمزوّد. اختلاف اسم/نوع/قيد/دالة/مالك/منحة، أو نقص صلاحية، أو تجاوز حد، أو timeout = **توقف**؛ لا IF NOT EXISTS أو إسقاط قيود أو توسيع صلاحيات لتجاوز الاختلاف.

## جرد قراءة فقط — لاحقًا بيد المالك

الملف [rad085-application-inventory.sql](../scripts/assess/rad085-application-inventory.sql) مستقل عن أدوات الجرد التاريخية. يعمل في معاملة READ ONLY مع statement_timeout=5s وlock_timeout=1s؛ يعيد metadata فقط، دون صفوف مشاركين أو كلمات مرور أو JWT أو أجسام دوال. اختُبر محليًا قبل الثلاثة وبعدها؛ لا يمنح علامة نجاح أو شهادة.

تُحفظ النتائج في قناة مراجعة خاصة، لا تعليق PR عام. لا تقبل مخرجات ناقصة: الحدود الأساسية 256 دورًا،512عضوية،256جدولًا،1024عمودًا،512دالة،256سياسة،512قيدًا/فهرسًا،128مشغلًا/منحة افتراضية،64امتدادًا. صف الحد+1 هو إنذار توقف ومراجعة جرد أوسع منفصل. لا تحدّث الأدوات التاريخية كي تقبل الجديد.

يفحص المراجع: أعلام LOGIN/INHERIT/BYPASSRLS والإدارة، جميع حواف ADMIN/SET/INHERIT والعضويات العابرة، منح PUBLIC وعمود/جدول/دالة، CREATE/TEMP/CONNECT، المالك الفعلي وsearch_path، وRLS والفهارس والمشغلات والقيود validated. `NOLOGIN` لا يمنع SET ROLE عبر عضو آخر. SUPERUSER والإدارة والقدرة على تعديل دالة/منحة حدود ثقة إدارية، وليست عزلاً ضد DBA.

إن ظهر سجل `supabase_migrations.schema_migrations`، يفحص المشغّل تعريفه أولًا ثم يقرأ **version فقط** بحد257، دون حقل statements أو بيانات تنفيذ؛ مثال بعد تأكيد العمود:

```sql
begin read only;

rollback;
```

غياب السجل أو اختلافه يحتاج إثبات تاريخ التطبيق بطريقة المالك المعتمدة؛ لا إنشاء سجل أو اعتبار marker واحد إثبات اكتمال. بصمات تعريف الدوال تقارن بكتالوج متوقع مُعدّ لكل مرحلة ومراجع، مع فصل المالك والمنح عن الجسم. لا تستخدم كتالوج الاختبار الصناعي شهادة للمزوّد. افحص كذلك الاستعمال/الأقفال بمعرفات إدارية محدودة دون query text؛ عند جلسات غير محكومة تؤجل النافذة، ولا تُقتل تلقائيًا.

## خطوات التطبيق وشروط المتابعة

المنفذ اللاحق يراجع دعم CREATE ROLE ومالكية الكائنات وdefault privileges في المزوّد. حساب CREATEROLE غير superuser قد ينتج عضوية ADMIN-only لمنشئ الدور في PG16+؛ لا تفترض غيابها لأن fixture superuser لم تنتجها. لا تسمح بأي مسار SET/INHERIT من API أو عامل إلى الجسر؛ العضوية الإدارية نفسها تراجع صراحة.

كل ملف يحتوي BEGIN/COMMIT مستقلين. يستعمل المشغّل لاحقًا قناة توقف عند أول خطأ، مثل psql مع `ON_ERROR_STOP=1` ضمن خطة معتمدة؛ **لا تلف الثلاثة بمعاملة خارجية وتتوقع ذرية جماعية**. لا إعادة لكل migrations التاريخية: إعادة التاريخ في الاختبار كانت لبناء قاعدة صناعية فارغة فقط.

| الخطوة | شرط المتابعة | عند الفشل أو ACK مفقود |
|---|---|---|
| قبل 1 | نسخة/حجر/جرد معتمدة، لا كائنات RAD-085 جزئية، بصمات مطابقة | توقف قبل الكتابة |
| تطبيق 1 | COMMIT معلوم؛ تحقق schema/ACL/قيود/مشغلات المرحلة الأولى؛ المجموعة والعضوية القديمتان دون تحويل، لا إيصالات Practice قديمة ولا قبول مشاركة مستنتج | افحص من جلسة جديدة هل المعاملة ثبتت. لا تطبيق2 قبل حسم النتيجة |
| تطبيق 2 | الأول متحقق؛ كتالوج المرحلة الثانية مطابق؛ لا مراجع تشغيلية مخترعة أو منح جداول | عند rollback تبقى1؛ لا إسقاط1 أو إعادة1 تلقائيًا |
| تطبيق 3 | الثاني متحقق؛ الدور غير موجود سابقًا؛ مالك الدوال ومنحها معتمدة | عند rollback تبقى1+2. افحص من جلسة جديدة الدور والدوال والجداول معًا؛ لا تعاود CREATE ROLE عميانيًا |
| بعد 3 | جرد نهائي ومراجعة الفرق المتوقع ومصفوفة رفض/توافق في staging؛ جميع الإعدادات المغلقة كما كانت | الحجر مستمر؛ لا عامل أو واجهة متصلة أو شهادة جديدة |

لا تشغّل عمليات حذف/كتابة «اختبار» على بيانات المشاركين للتحقق. اختبارات مالك مأذون/participant/anon/worker وSET ROLE والأقفال والنشر والإسناد تُعاد على staging معزول مطابق بصلاحيات مزوّد مراجعة، لا بانتحال هوية مستخدم حي. تأكيد عدم تغير قنوات الحسابات/surveys والمصحح مستقل عن وجود الملفات.

بعد1، في قاعدة بلا بيانات RAD-085 سابقة، يتوقع policy.required_version/text_digest=null وsharing_consents فارغة، ولا backfill لفترات العضوية أو Practice. بعد2 السجل الخاص فارغ إلى تعبئة معتمدة؛ بعد3 reviewed_packages فارغ والدور NOLOGIN وNOINHERIT/NOBYPASSRLS وبلا وصول API/worker. لا تمنح المشرف owner أو صلاحيات حسابات/surveys.

فحوص إضافية محدودة **بعد الثالثة فقط**؛ النتائج المتوقعة كلها true، باستثناء أي شرط جرد سابق يثبت اختلافًا فيبقى توقفًا للمراجعة. لا يفحص هذا الأدوار غير المسماة أو العضويات العابرة؛ استعمل جردها الكامل أيضًا:

```sql
begin read only;
set local statement_timeout='5s';
set local lock_timeout='1s';
select not exists(select 1 from assess.launch_gate where enabled) launch_still_closed,
 not exists(select 1 from assess.sharing_policy
   where required_version is not null or text_digest is not null) sharing_unconfigured,
 not exists(select 1 from assess.authoring_reviewed_packages) review_store_empty,
 not exists(select 1 from assess.authoring_references) reference_store_empty;
select rolcanlogin=false and rolinherit=false and rolsuper=false and rolbypassrls=false
 and rolcreaterole=false and rolcreatedb=false and rolreplication=false bridge_flags_closed
from pg_roles where rolname='assess_authoring_bridge';
select not has_function_privilege('anon','assess.authoring_bridge_read_v1(uuid,uuid,integer)','EXECUTE') anon_denied,
 not has_function_privilege('authenticated','assess.authoring_bridge_read_v1(uuid,uuid,integer)','EXECUTE') api_denied,
 not has_function_privilege('assess_worker','assess.authoring_bridge_read_v1(uuid,uuid,integer)','EXECUTE') worker_denied,
 not has_table_privilege('assess_authoring_bridge','assess.authoring_reviewed_packages','SELECT,INSERT,UPDATE,DELETE') bridge_table_denied;
rollback;
```

غياب صف الدور أو صف السياسة أو singleton scope/launch المتوقع هو فشل، لا نجاح vacuous من NOT EXISTS. راجع القيود وعدد صفوف singleton ضمن الجرد؛ لا تضف صفًا مفقودًا تلقائيًا. تبقى هذه probes شروطًا محددة لا شهادة شاملة.

## النسخ والاستعادة والتعافي

الشاهد المحلي نفّذ `pg_dump -Fc` لقاعدة صناعية و`pg_dumpall --roles-only --no-role-passwords` ثم استعادة إلى cluster ثانية عبر `pg_restore --exit-on-error`. قوائم الأدوات والحدود والقياسات في التقرير. المطابقة شملت البيانات والتسلسلات والأدوار والعضويات وACL/RLS والدوال والقيود والفهارس والمشغلات وdefault privileges. لا يُنقل أرشيف الاختبار إلى الإنتاج، وقد حُذف بعد التحقق.

قاعدة البيانات المنطقية تتضمن مخططها وبياناتها وكائناتها ومنح تلك الكائنات؛ globals ملف منفصل للأدوار وعضوياتها، **دون كلمات المرور**. لم يُستخدم --create؛ إنشاء قاعدة الوجهة ومالكها وACL/settings للقاعدة وتكوين cluster معالجة منفصلة. هذه ليست لقطة ذرية واحدة عبر كل القواعد/الأدوار. لم تختبر tablespaces أو large objects أو اشتراكات/replication أو Extensions خاصة بالمزوّد. ملف globals قد يمنح SUPERUSER؛ لا يستعاد خامًا فوق Supabase أو cluster مشتركة. تعالج تعارضات الأدوار ومالكية objects يدويًا ضمن خريطة معتمدة؛ لا `--no-owner/--no-acl` لإخفاء الاختلاف.

المطلوب من المالك لاحقًا: نطاق نسخ Supabase الفعلي وسياسة احتفاظه وإمكان restore/PITR وتكلفته؛ Auth المدار/Storage blobs والأسرار وإعدادات API/pooler وTLS وIAM والصور ونسخ العامل والجدولة خارج ضمان هذه النسخة. dump لصفوف auth لا يثبت إمكان إعادة خدمة المصادقة المدارَة. credentials/secrets تعاد من قناة منفصلة مع تدوير مدروس، ولا نصدّرها للتقرير.

سياسة [الاحتفاظ](ASSESS_RETENTION_POLICY.md) باقية: نسخ نديرها مشفرة يوميًا وتداول7أيام ونسخة قبل التغيير، واختبار restore، دون وعد بشأن نسخ المزود. بعد restore يبقى API والنقل محجورين حتى إعادة تطبيق الحذف والسحب وتعطيل الحسابات وإغلاق الإسنادات والموافقات الأحدث من اللقطة والتحقق من الأدوار. `launch_gate=false` تمنع start فقط؛ لا تحجر كل القراءات أو maintain/claim.

عند الفشل: أوقف الدفعة والعامل والنقل، احفظ حالة المعاملة والمرحلة والبصمات دون بيانات حساسة، وافحص من اتصال جديد. لا DROP CASCADE أو down migration على بيانات حقيقية. يختار المسؤول بعد المراجعة إصلاحًا أماميًا أو استعادة إلى وجهة معزولة والتحقق ثم تحويلًا مخططًا؛ لا overwrite تلقائيًا. إذا دخلت كتابات بعد النسخة، يوقف التحويل حتى تحديد مصالحتها وفقدها المقبول؛ لا RPO/RTO مثبتين من تجربة صغيرة.

## ما يبقى مغلقًا والقرارات الضرورية

تبقى variables وPILOT_SCHEMA_VERIFIED وlaunch_gate وCONSENT_VERSION وشهادات التطبيق كما هي، والعامل/الجدولة/هوية الجسر LOGIN والنقل الحي غير مفعلة. reviewed_packages وauthoring_references بلا تعبئة تشغيلية، ومعنى نص المشاركة معتمد الآن [بقرار المالك](DECISIONS.md#rad085-owner-final-local-2026-10-26)، دون تهيئة تشغيلية أو قبول مستخدم حقيقي. PR Draft؛ الدمج إلىmain ينشر تلقائيًا وخارج الإذن.

| القرار قبل المرحلة المعنية | التوصية المحددة |
|---|---|
| من يدخل حزم المراجعة التشغيلية؟ | مشغّل بشري مسمى منفصل عن المؤلف، عبر قناة إدارة مؤقتة مراجعة؛ لا المتصفح ولا supervisor ولا worker ولا دور الجسر. لا منح جديدة في هذه الحزمة |

أُنجز تصميم واختبار هوية اتصال الجسر وإبطالها **محليًا فقط** في [تقرير الاتصال](RAD-085_CONNECTION_IDENTITY_2026-10-26.md)، مع LOGIN خدمة صناعي وموثّق جلسة محقون وpool معزول وإبطال النطاق/cache ومصالحة ACK. لا إعداد اتصال حي جاهز أو هوية تشغيلية. الخطوة التالية إثبات مخزن دليل المحو والسحب وقنواته التشغيلية وحالة الكاتب المحجوبة والمزوّد، ثم قناة المصادقة والإبطال ومراجعاتها قبل أي وصل مستقل مأذون؛ [تقرير المحو المحلي](RAD-085_ERASURE_REPORT_2026-10-26.md) يفصل المنجز والحدود. تراجع صورة العامل الحالية وworker/case/evaluator وIAM/STOP/المراقبة والتكلفة والنسخ قبل أي تشغيل مستقل مأذون. لا نعيد تهيئة هوية عامل تاريخية أو نستخدم كلمتها لهذه القناة.


### أثر الهوية والإبطال على التطبيق والاستعادة

لا SQL أو بصمة جديدة لهذه الدفعة. هوية الخدمة منفصلة عن المستخدم ومجموعته وعن الدور الداخلي؛ لا تسمح هوية الخدمة وحدها باختيار actor/group من الطلب. التشغيل المستقبلي يحتاج جرد منح الخدمة وSET/INHERIT/ADMIN والتأكد من عدم وجود امتيازات أو عضويات إضافية، وإثبات verifier وقناة إبطال وفشلها وTLS/pooler الفعليين. لا يستعمل secret العامل لهذه القناة.

عند سحب هوية الخدمة مستقبلًا: حجر النقل، إبطال المضيف وإغلاق pool، منع LOGIN/تدوير الهوية وإنهاء الجلسات القديمة تحت مسؤول مأذون، ثم إثبات رفض الجديد والمفتوح والمعاد استخدامه؛ NOLOGIN وتغيير السر وحدهما لا يكفيان. عند فقد قناة الإبطال يغلق المضيف محليًا؛ الاستعادة تحتاج مضيفًا وجلسات موثقة جديدين، ولا إعادة كتابة تلقائية بعد فقد ACK. بعد COMMIT يمكن حجب الرد دون إلغاء الأثر، ثم مصالحة قراءة صريحة عند عودة التفويض.

محو الروابط والمراجعات لا يُستعاض عنه بمسح cache. قبل إعادة فتح النقل بعد restore يجب منع إحياء عضويات/موافقات/حسابات سُحبت بعد اللقطة ومراجعة منح LOGIN، وعدم استعادة capabilities أو caches أو credentials القديمة. الإجراء التشغيلي وسجل replay الموثوق ما زالا مطلوبين؛ لم تختبرهما هذه الدفعة على مزوّد. شواهد الأقفال والحذف دخلتCI؛ اختبار dump/restore الكامل السابق لا يزال مستقلًا ولم يُعد في جلسة الاتصال.


## ملحق المحو المحلي — ليس ضمن حزمة التطبيق الحي

اعتمد المالك RAD085-SQL-ERASURE-LOCAL-20261026 بعد عرض الفرق والشاهد. [`supabase/manual/rad085-account-erasure-local.sql`](../supabase/manual/rad085-account-erasure-local.sql) ببصمة `383b1400532c4f8a4bf93d21daeb71242993279c4c2e90750e6620761e1de8b2` يطبق في fixture صناعية **بعد** الثلاثة الحالية فقط؛ لا تغيرت بصماتها أو الترحيلات التاريخية أو جرد/حارس المخطط أو الشهادات. ليس ملف رابعًا مأذونًا للمزوّد، ولا يكفي إلحاقه تلقائيًا بترتيب التطبيق أعلاه. يلزم إجراء ترقية وفحص ومراجعة definer/ACL وشهادة مستقلة بإذن لاحق قبل أي تشغيل.

[الفرق المأذون](RAD-085_ERASURE_SQL_PROPOSAL_2026-10-26.patch) مطابق بايتًا؛ معاينة owner-only، primitive خاصة بلا منح API، وC2 finalise تستخدمها بعد شرطها الأصلي30يومًا. الطالب تمحى بياناته؛ الكاتب الخاص غير المسند تفك مراجعاته/روابطه/publication قبل CASCADE، والمشترك/المسند يحجب ذريًا دون نقل ملكية أو تغيير FK. لا حذف تلقائي عند انتهاء المجموعة. فشل الملحق داخل begin/commit يرجع تعريفاته جميعًا؛ لا يزيل الثلاثة السابقة أو يجعل نشرًا ممكنًا. فقد ACK يحتاج فحصًا من اتصال جديد لا تطبيقًا أعمى.

شاهد restore الجديد قاعدة PostgreSQL TEMPLATE صناعية قبل التعطيل/الحذف/السحب، والدليل مستقل على قرص مؤقت؛ replay للحذف النهائي لا يعتمد على طلب C2 داخل snapshot القديمة. النية غير المحسومة أو الدليل الناقص/المزور/غير الحديث أو فشل التطبيق/الإبطال يبقي الوصول محجورًا. لا فتح خدمة في البروتوكول. [الإجراء](RAD-085_ERASURE_RECOVERY_2026-10-26.md) يحدد أقل بيانات الدليل وحياته ومسؤوله؛ المخزن التشغيلي ومصدر head الحديث وفصل السر وقنوات كل التغييرات والصادرات والمزوّد لم تجهز. اختبارنا ليس Supabase/Auth/PITR أو إتلاف أرشيف مزوّد. عائق التشغيل باقٍ.
