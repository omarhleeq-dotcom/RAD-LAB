## 4. المشترك وScale check والأثر على سير العمل

الأدوات Node built-ins، بلا اعتماد جديد أو parser طبي/شبكة/DB. `status:summary` يعرض JSON الأصلي ولا يكتب نسخة ثانية؛ IDs وعقد الحالة لم يتغيرا. فحص القرارات يجمع السجل الحالي والتاريخي، فيسمح بأرشفة إضافية دون فقد التتبع، ويقارن fork point الصحيح على PR. الملفات الجديدة غير المتجاهلة تدخل فحص Markdown قبل staging أيضًا.

الجلسات القادمة تبدأ بنقطة واحدة وتختار القراءة، بدل نسخ التعليمات وإعادة فتح التاريخ. التعديل الروتيني للدكس يستخدم أوامر المشروع نفسها محليًا وفي CI؛ نقل ملفات/حذف عنوان/إضاعة معرّف/كسر توافق يفشل قبل الدمج. المراجع البشري يصل إلى أصل الحكم بنقرة، والوكيل يعرض مهمة واحدة ودليلها بدل قراءة JSON كامل. هذا يقلل تكلفة القراءة ولا يلغي مراجعة المعنى والأدلة. القياسات الفعلية قبل/بعد في§6، وليست وعدًا بانخفاض tokens بنسبة ثابتة لكل مهمة.
