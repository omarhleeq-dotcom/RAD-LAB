## Architecture and optional mechanisms

- **Exams/cases are data:** `ExamDefinition` in `src/data/exams/*` holds controls, rules, tolerances, weights/critical findings, protocol and scene/render bindings; `CaseDefinition` in `src/data/cases/*` holds patient/order, baseline, cooperation, attenuation and initial state. `composeCase()` yields the `RadCase` compatibility view. Validate with `validateExam` / `validateCase`; no case-specific UI logic.
- **Separation:** `domain/` ← pure `features/evaluation|scoring` (no React) ← stores ← UI. Simulation/scoring never lives in React or pixels. Technique selectable controls, target, tolerance and evidence class are distinct data. Prefer reusable components; avoid unnecessary dependencies/global state.
- Scene registry (`scenes.tsx`), `SceneLayout` / `DetectorFigure` and projection registry (`src/data/projections.ts`) supply art, second view, optional cues, texts and wording. `SceneId`, `BodyPartId`, `ProjectionId`, `WordingNs`, effect/critical/variant ids are extensible and validated against their registries; no projection flags in shared positioning components. New anatomy/effects must fit existing mechanisms or have a separate reference-led generalisation.
- Optional fields mean **unused when omitted**: no hidden controls, fallback scoring or feedback (S-STD-1). Chest cues, breathing, inspiration response, lung landmarks and AEC are optional; manual-only exams omit AEC. Existing documented data fallbacks are not permission to introduce new ones. Available mechanisms and precise touch-points: [recipe §2](docs/exam-recipe.md#2-s11-generic-mechanisms-what-an-exam-may-use).
- Learner chooses the instruction, never the defect; inspiration/motion are deterministic `patientCooperation` data, independent of each other and technique. Keep-still is weight0 until an educator defines its rubric. No grid control or patient-build mechanism is implied by contextual text (S11-3/4).

## Medical evidence, scoring and rendering

- **Never invent medical facts or diagnostic radiographs.** Clinical values remain `provisional: true` + TODO pending educator/physicist review O5. Every medical rule has one of the five `EVIDENCE_CLASSES`; classify each value SOURCE-BACKED / TEACHING CHOICE / OWNER DECISION. Teaching choices are labelled in feedback and [REVIEW_PACKAGE](docs/REVIEW_PACKAGE.md); unvalidated imagery remains a labelled placeholder.
- **Reference first (S10-2):** before generalisation or implementation, the exam/modality reference must be merged to main with complete Needs (same/differs/new/unknown; each unknown names the missing source). References run ahead of code; generalise only for concrete merged needs, never placeholders. Use [reference template](docs/templates/EXAM_REFERENCE_TEMPLATE.md) and [exam recipe](docs/exam-recipe.md); no new exams while the freeze holds.
- **BONTRAGER-9 governs X-ray positioning/technique** (printed pages, S10b-25). Other sources support; on conflict Bontrager wins; where silent use the next applicable official source (EC16260, ACR-CHEST/ACR-PORTABLE, WHO-TECH, WHO-CHEST), then owner decision. This does not clinically validate provisional values. Read [source notes/register](docs/sources/REGISTER.md), not uncommitted PDFs; advisor-read claims are not independently re-verified by an agent. Abstracts alone cannot establish a rule/value/convention; PMC full text only via official NCBI E-utilities; no captcha bypass, unofficial mirrors or caches.
- Facts are paraphrased/cited, short quotes only; no textbook text/figures or third-party student notes. **Commercial compatibility (S10-3):** own work, PD/CC0, CC BY or purchased licence; NC/ND excluded, SA only with explicit owner approval. Radiopaedia never used. Every external asset is registered in [provenance](docs/ASSET_PROVENANCE_AND_LICENSES.md) in the same commit; PDFs/secrets are never committed. Image sourcing/approval and documented exceptions are in recipe §5 and the asset register; never turn owner verification into independent verification or reopen an explicitly settled licence audit automatically.
- Scoring/category/check weights are exam configuration, categories sum to100. Collimation belongs to `positioning`. **Marker is per exam:** `markerRule`, placement and critical list are distinct from numeric weight; Chest PA `side-marker` stays weight0 while missing/wrong markers are critical gates (S11b-1). Other exams may have weighted checks. `fixed-side` judges the letter without a viewer-half rule; its side is exam data, not a duplicate case field (O29). `markerKeepOut` is optional, with the documented whole-required-anatomy exclusion when absent. Never impose one universal marker/scoring policy.
- Renderer consumes `EvaluationResult.resultState`: `RadiographResultState` → `buildRenderPlan` → pure `renderRadiograph`; canvas only draws. No pixel read-back into state/scoring, no unseeded randomness. Magnitudes live in `features/radiograph/tuning.ts` and are educational approximations. `ImageVariantId` comes from failed/partial checks; `ResultImage` swaps validated imagery. Low exposure means noise/detail loss, never brightness; excess exposure never darkens; digital brightness is not an exposure indicator. No invented EI/EIT, universal DI threshold or clinical numeric mAs target (a labelled model anchor is different).
- Rotation sign is defined by the **result image**, per exam (S11c-1/S13-6); the old universal physical-turn wording does not hold for AP. Preserve the open plan-view mismatch O19; new projections need a recorded sign and renderer test. Magnitude-only feedback where sources give no direction. Anatomy/markers and SVG/canvas stay LTR and never mirror in RTL.

## Scene design and bilingual UI

- Reuse `scene-style.ts` tokens (`SCENE`, `STROKE`, `UNDER`, `LABEL_SIZE`), `SceneParts.tsx` and existing figures. Never invent hex/stroke values. Dark muted anatomy, thin bone/edge lines; ONE amber accent over dark understroke; guides at most green target + sky reference/fault, also distinct by shape/text. Accents ≥3:1 against every fill (`scene-style.test.ts`); labels ≥7:1 on measured dark pills, no stroke halos on Arabic joins.
- Draw scored faults visibly by shape, with outlines/labels only when guides ON. If an honest cue cannot be drawn, label/record that limit and apply the honesty gate before implementation. Clip to detector/viewBox, no dead space or unexplained shapes; each drawing has settings-derived text alternative. Keep pointer/keyboard/ARIA semantics. Use family-appropriate axis/hint labels, not universal Head/Feet. Measure overlaps at390/1440 EN/AR, guides ON/OFF and all moving axes ([recipe §4a](docs/exam-recipe.md#4a-label-collision-measurement-reusable-script-s14-0)).
- UI strings in both `messages/en.json` and `messages/ar.json`, synced keys; data text `LocalizedText`; logical CSS (`ms-`, `ps-`, `border-s-`), numbers/units `dir="ltr"`. New Arabic terms remain machine-assisted DRAFT in [ARABIC_TERMINOLOGY](docs/ARABIC_TERMINOLOGY.md) until reviewed; use «الكاشف». Keep assessment answer separation.

## Session workflow, QA and delivery

- S-STD-1/2: one focused goal, explicit file/shared-module budget before edits; no opportunistic fixes. Optional-field and effect-honesty rules apply. Stop/report missing sources, conflicting decisions, blocked commands/sites (one429 retry only), unclear licences, secrets, unexpected medical/score changes or budget overflow. Existing tests: type-only narrowing/`!` only unless a specific approved exception/list extension applies; no semantic expectation change to pass QA.
- S-STD-3 **Scale check** in PR and final section4: state any ceiling (volume, hard-coded sets/ids/locales/roles, unversioned data, unbounded/unindexed reads, hand-only changes) and avoidance; prefer configuration, versioned shapes, bounded server-side keyset paging, additive extension. No speculative features; necessary ceilings need an open decision and lifting trigger.
- **QA by session type:** DOCS = local Markdown paths/anchors/tables + text `source_ref`, state transition and `git diff --check`, no app build. REFACTOR = byte-identity proof + full suite once. EXAM = targeted tests while working; once at end `npm run check`, `npm run build`, EN/AR390/1440 browser/axe, relevant family audits + label collisions. See recipe §7; do not repeat passing QA without a relevant change/failure.
- Protect characterisation/goldens/render hashes/composed cases and existing `scene-dom`/family hashes. Never regenerate to hide a failure (`qa:characterise` only for deliberate reviewed behaviour change). New family guards cover only their projections; existing hashes stay unchanged. Scene/result and scoring are independently protected.
- Report in Arabic, S-STD-1 order: **1 deviations/budget;2 done/dropped;3 per-task;4 shared changes + Scale;5 medical/scoring table;6 QA/regression evidence;7 open items;8 owner phone checklist**. Update HANDOFF at boundaries (branch/base, done/unfinished, QA run/not run, blockers/next action), roadmap if phase status changes, and a session report; finish with a ready-to-copy next-session prompt. Do not append session history to this guide.
- Ready changes → **Draft PR only**. Never mark ready, merge or enable auto-merge without an explicit later owner instruction. Never open/share hosted preview URLs; owner checks phone. No subscribe/poll. Use existing cloud checkout; no worktree unless asked. At≈90–95% usage stop new work, preserve compiling work, commit/push and leave exact handoff; never fake/skip QA.

## Project status file (RAD-STATUS)

[project-status.md](docs/project-status.md) is the single task-state authority; [status-format](docs/status-format.md) governs it. Read first, update only actual changes in the same batch; keep all IDs/notes, no deletion/reuse, raise `revision`/`updated_at`, merge others' updates. No planned work as done; done requires evidence. Format1.1: `waiting_on` required on open planned/in_progress/review/blocked tasks, forbidden on done; description≤350, evidence≤400chars; HANDOFF≤80lines. Rewrite the five-item summary, no appended history/counts derived from code; history to status/archive. Merged work lacking external verification stays review. Run `npm run status:check -- --base origin/main --require-previous`; it checks structure/continuity, not truth. Unsettled conflicts remain notices. If state cannot be updated, report why.
